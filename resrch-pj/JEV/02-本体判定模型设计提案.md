## 0. 定位：我们的本体模型核心解决什么问题

三模型分工（一句话版）：

| 模型 | 解决 | 输出形态 | 比喻 |
| --- | --- | --- | --- |
| LLM | 通用性、推理深度、内容创作 | 自然语言 | 会说，但会错 |
| Jev 类判定模型 | 已知选项中的快速决策 | typed value + 校准概率 | 选得快，但不懂语义深度 |
| **本体判定模型（本提案）** | **语义接地与逻辑保真** | **可验证的符号结构（IRI/三元组/公理槽位/验证结论）+ 校准置信度** | 对得真，可验证 |

**核心问题陈述**：让自然语言与 OB2 符号概念空间**双向可验证地对接**——
- 正向（接地）：模糊的语言 → 概念 IRI、关系三元组、公理槽位（带概率与拒答）；
- 反向（导出）：符号空间的可验证结论 → 人可读的依据说明。
- "像逻辑学家一样思考"的实现方式不是把逻辑学进神经网络，而是**神经感知 + 符号裁决**：
  模糊匹配（词→概念、候选关系、对齐候选）交给神经模型；演绎运算（层级闭包、一致性、
  约束验证）交给符号推理器。用概率做数学必错，用符号做感知必僵。

**在我们架构中的缺口**：推理分级第④类"语义判断"目前由通用 LLM 承担——贵、慢
（P95≤8s）、概率性、每次要注入本体上下文。本体判定模型 = 第④类的专用引擎，
百毫秒级、本地、可校准、输出直接是 OB2 符号结构，且给 LLM 候选当守门人（预检后
再进引擎①②③终审）。挂接点：agent loop 八扩展点中的 `reasoning.engines`。

## 1. 架构：一骨干、三头、一双塔、一内核、一校准层

```
自然语言/状态
    │
    ▼
┌─────────────────────────────────────────────┐
│ A. 共享骨干  gliner_multi-v2.1 (mdeberta-v3, 279M, fp16≈0.6GB, 已跑通) │
│   ├ 头A 概念抽取头（GLiNER span 原生）      mention + 候选类        │
│   ├ 头B 关系抽取头（GLiREL span-pair 路线） (s,p,o) 候选三元组      │
│   └ 头C 判定/路由头（GLiClass 式多分类）    意图/工具/风险级 = Jev 接口 │
└─────────────────────────────────────────────┘
    │                       ▲ 召回/重排
    ▼                       │
┌──────────────┐   ┌───────────────────┐
│ D. 校准层     │   │ C. 双塔检索器 bge-m3 │←→ Milvus（1024 维契约已定案）
│ conformal+拒答 │   │  消歧/对齐的召回层    │
└──────────────┘   └───────────────────┘
    │
    ▼
┌─────────────────────────────────────────────┐
│ E. 符号内核（非学习组件，CPU）                 │
│  owlready2+owlrl（层级闭包/一致性） pySHACL（约束门禁） 规则引擎 │
└─────────────────────────────────────────────┘
    │
    ▼
输出：OB2 符号结构 + conformal 置信区间 + abstain（无法判定时不硬猜）
```

**五能力 → 组件映射**（用户提出的五个要求）：

| 能力 | 神经组件 | 符号裁决 | 输出 |
| --- | --- | --- | --- |
| 概念消歧 | 双塔召回 + 骨干上下文重排 | 术语唯一性 lint（国标底线） | `ob2:Object` 类 IRI + 概率 |
| 关系抽取 | 头B（GLiREL 路线） | domain/range 合法性检查 | 三元组候选 |
| 层级推断 | subsumption 候选打分（头B 复用） | owlrl/HermiT 闭包，**结论由推理器出** | TBox 增量候选 |
| 约束验证 | NL→SHACL 槽位解析头（唯一"学习"点） | pySHACL 门禁，**判定 100% 符号** | pass/fail + 违规报告 |
| 本体对齐 | 双塔跨库召回 + 重排（BERTMap 思路） | 互斥/函数性冲突一票否决 | 映射对 + 概率 |

VRAM 预算：骨干 0.6G + bge-m3（568M）≈1.2G + 激活 ≈ 2~3G，RTX 4060 8GB 微调也够
（fp16 + batch 4~8）。

## 2. 训练计划（S0→S3）

- **S0 零样本基线（已完成）**：tools/jev-local/ 跑通 GPU；抽取可用，路由弱。
- **S1 监督多任务微调**：
  - 数据三源：① GB/T 附录 D Turtle 实例反向构造（文本,标注对）；② docs/ 语料人工标注
    50~200 条起步；③ LLM 离线合成大规模数据（Jev 模式：大模型造数据、小模型在线判定），
    格式沿用 tools/jev-local/train_sample.json。
  - 目标：头A/B/C 一次多任务训练；关系标签体系从国标 34 个核心对象属性起步。
- **S2 对比校准（RLCD 精神）**：
  - hard negative 生成器 = **国标第 8 章公理类型**（互斥/唯一值/日期有效性/枚举/函数性/
    版本替代/层次约束）——"表面相似但违反公理"的候选即负例。这是本项目独有的优势：
    公理越全，负例越准，校准越好。
- **S3 conformal 校准**：held-out 集上定覆盖率（如 95%），输出置信区间 + 三档动作分级：
  高置信→自动执行 / 中置信→LLM 复核 / 低置信→人工终审（对接已有 confirm_token 机制）。

## 3. 平台集成

1. **MCP 出口新增工具**（带 `_meta.x-ontology` 语义标注）：
   `ontology.ground`（消歧）、`ontology.extract`（抽取）、`ontology.align`（对齐预检）；
   `ontology.validate`/`ontology.reason` 保持走符号内核。
2. **推理分级更新**：第④类"语义判断"默认引擎 = 本体判定模型；LLM 降为兜底
   （低置信/拒答时升级）。写入 reasoning.engines 扩展点。
3. **接口规范（Jev 式）**：`{value, type, confidence_interval, decision: auto|review|human}`
   ——与 MCP `_meta.x-ontology` 的 risk_level 直接联动。
4. 锚点变更：docs/architecture/01 L5 语义层增加"本体判定模型服务"（FastAPI+GPU，
   独立进程），LiteLLM 模型网关注册为本地 provider。

## 4. 红线（对齐国标四条底线）

1. 本体判定模型输出仍是**候选非成品**，必须过引擎①②③（OWL→SHACL→规则）+ 人工终审；
2. 层级推断与约束验证的最终结论**只由符号内核出具**，神经头只有提名权；
3. bge-m3 契约不变（换嵌入模型=重建 collection）；
4. 模型换型/重训须走验收集回归（消歧 F1、抽取 F1、校准 ECE、覆盖率）。
