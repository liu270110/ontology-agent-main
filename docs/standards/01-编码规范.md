## 2. Python 后端规范（services/）

### 2.1 分层 import 规则（import-linter 契约）

依赖单向（锚点 §2）：L2→L3→{L4, L5}→L6→L7。硬规则：

| 层 | 允许 import | 禁止 |
| ---- | ---- | ---- |
| L2 gateway | L3 | L4~L7、存储客户端 |
| L3 business | L4（含 ports）、L5、L7（仅经 L4 ports） | L2、L6 内部模块、SQL/ORM |
| L4 domain | **无**（纯 Python + pydantic） | 任何层、FastAPI/SQLAlchemy/存储客户端 |
| L5 semantic | L6、L7、L4 接口 | L2、L3（不处理会话/权限） |
| L6 data | L7 | 业务规则、HTTP 细节 |
| L7 infra | 外部系统 | L1~L6（倒置例外：`CapabilityProvider` 注册，锚点 §3.4） |

契约配置入 `pyproject.toml`（CI `lint-imports` 强制，违规即构建失败）：

```toml

name = "分层单向依赖（L2→L7）"
type = "layers"

    "services.gateway",
    "services.business",
    "services.semantic",
    "services.data",
    "services.infra",
]

[[tool.importlinter.contracts]]
name = "L4 领域层零依赖"
type = "forbidden"
source_modules = ["services.domain"]
forbidden_modules = [
    "services.gateway", "services.business", "services.semantic",
    "services.data", "services.infra",
    "fastapi", "sqlalchemy", "redis", "neo4j", "pymilvus", "minio",
]

[[tool.importlinter.contracts]]
name = "L3 禁穿透 L2/L6 内部"
type = "forbidden"
source_modules = ["services.business"]
forbidden_modules = ["services.gateway", "services.data"]

[[tool.importlinter.contracts]]
name = "L2 网关禁入 semantic/data/infra（显式白名单除外）"   # 2026-09-26 评审修复G 补
```

### 2.2 命名与模块

| 对象 | 规范 | 正例 / 反例 |
| ---- | ---- | ---- |
| 包/模块 | snake_case | `kb_pipeline/` ✅ `KbPipeline/` ❌ |
| 类 | PascalCase；**聚合根不带后缀**（`Agent` 而非 `AgentEntity`） | `OntologyGate` |
| 函数/变量 | snake_case；私有 `_` 前缀 | `_normalize_iri` |
| 常量 | UPPER_SNAKE | `MAX_TOOL_LOOPS = 5` |
| DTO（L2 `schemas/`） | 后缀 `In`/`Out`，与网关路由一一对应 | `CreateOntologyIn` / `OntologyDetailOut` |
| 仓储接口/实现 | `XxxRepository`（L4 `repo/`）/ `PgXxxRepository`（L6 `repo_impl/`） | `SessionRepository` |
| 端口/策略/编排器 | `XxxPort`（L4 `ports/`）、`XxxPolicy`、`xxx_orchestrator` | `ModelPort`、`WritebackPolicy` |
| 领域事件 | 过去式 PascalCase；`event_type` = `{聚合名}.{过去式 snake_case}`（04 篇 §6） | `OntologyPublished` / `ontology.published` |

一文件一主类（聚合/编排器）；模块超 500 行即拆分并登记。L2 `routers/` 文件名与资源对应（agents/sessions/ontology/kb/memory/plugins/mcp/admin），与前端 `src/api/*.ts` 一一对照（frontend/03 篇 §4）。

### 2.3 类型注解

- 全量注解（含私有函数），Python ≥3.11 语法（`X | None`、内置泛型）；
- mypy 分级：`services/domain`、`services/semantic` **strict**；其余包 normal（`pyproject.toml` 分节配置）；
- **禁裸 `Any`**：确需 `Any` 必须注释理由并在函数边界收窄；外部无类型库用带错误码的 `type: ignore[...]`，禁裸 `# type: ignore`；
- ORM 侧用 SQLAlchemy 2.0 typed 风格（`Mapped[UUID] = mapped_column(...)`）。

```python
# ✅ 正确：显式类型 + 收窄
async def find_open_tickets(self, target: TargetType) -> list[ReviewTicket]: ...
# ❌ 错误：裸 Any 逃逸到调用方
def parse_payload(data: Any) -> Any: ...
```

### 2.4 pydantic 纪律（04 篇 §1 裁决）

```python
class Ontology(AggregateRoot):                 # 聚合根：绕过方法改属性触发校验
    model_config = ConfigDict(validate_assignment=True)

class OntologyVersionRef(BaseModel):           # 值对象：一律 frozen
    model_config = ConfigDict(frozen=True)
    version: str
    artifact_uri: str
    checksum: str

class Message(BaseModel):                      # 实体：按 id 判等（禁 pydantic 结构相等冒充标识相等）
    id: UUID
    def __eq__(self, other: object) -> bool: ...
    def __hash__(self) -> int: ...
```

- validator **只做形状校验**（类型/长度/格式）；业务不变式只写在聚合方法里，禁止藏进 `@field_validator`；
- DTO（L2 `schemas/`）与领域模型严格分离，禁止一个类两用；
- 领域事件 `frozen=True`，字段全部可 JSON 序列化（直接进 outbox payload，04 篇 §6）。

### 2.5 异步规范

- IO 一律 `async def`：走 asyncpg/httpx/Neo4j AsyncDriver 等异步客户端（06 篇 §1 clients 约定）；
- **禁同步 IO 混入请求路径**（`requests`、`psycopg2`、`time.sleep`）；确需同步库（rdflib/pySHACL）在 `asyncio.to_thread` 中执行并注明；
- **超时必设**：一切外部调用（LLM/MCP/存储/HTTP）显式 `timeout=`；总预算用 `asyncio.timeout()` 包裹（对话总预算 60s、策略可配，流式按 TTFT 3~5s 判超时——08 篇 §5；2026-09-26 评审修复G 统一口径，原 30s 作废）；
- 并发用 `asyncio.TaskGroup`；后台任务必须可取消、可观测，禁 fire-and-forget 裸 `create_task`。

```python
async def search_with_budget(self, q: str) -> RetrievalResult:
    async with asyncio.timeout(10):            # ✅ 超时必设
        return await self.retriever.search(q, mode="local")
```

### 2.6 错误处理

- 异常层级：`DomainError`（L4，带平台错误码）→ 各聚合子类；`InfraError`（L7 客户端错误）；L2 统一 exception handler 转错误体 `{code, message, trace_id}`（frontend/03 篇 §3）；
- **错误码登记表**：新增错误码必须在 [02-网关层设计 §7](../architecture/02-网关层设计.md) 登记表登记，禁止随手编数字。已登记分段示例：`4101 SESSION_CLOSED`、`4102 TASK_ALREADY_RUNNING`（03 篇 §3）、`5001 LLM_TIMEOUT`、`5004 UOW_COMMIT_FAILED`（03 篇 §3）；
- **禁裸 except**：`except Exception:` 必须记日志后 re-raise 或转义；禁止 `except: pass`；保留因果链 `raise XxxError(...) from e`；
- 可重试写操作必须携带 `idempotency_key`（PG `tasks` 与 Redis `idem:*` 双落，08 篇 §5）。

### 2.7 事务与仓储用法（03 篇 §6 / 06 篇 §1）

- 仓储实例**只从 UoW 获取**：`uow.for_tenant(tenant_id)` 构造期绑定租户作用域，方法级不传 `tenant_id`（少一个参数少一处漏过滤）；
- **禁事务外写**：`save`/`append` 必须在 UoW 上下文内；一个用例一个 UoW；跨聚合强一致组合走 03 篇 §6.1 **豁免清单**（已知：①消息落库+task 终态；②工单裁决+changeset 迁移；③业务表+outbox 同写），新增豁免必须登记并评审，禁止私扩；
- **外部调用（LLM/MCP/MinIO）一律在事务外**：先短事务落意图 → 调外部 → 再短事务落结果；
- 跨存储投影只经 `uow.enqueue_projection()`（业务行与 outbox 同事务）；SSE 长流程全程不持事务。

```python
async with uow.for_tenant(tenant_id) as tx:            # 一个用例一个 UoW
    task = await tx.tasks.get(task_id) or raise_task_missing()
    task.start()                                       # 不变式在聚合方法内断言
    tx.enqueue_projection("task.started", task.id, {...})
    # ⚠ 此处不得出现 LLM/MCP/MinIO 调用（评审清单 §7.1-4）
```

### 2.8 日志与 trace

- 结构化日志（JSON 输出），统一字段：`ts / level / trace_id / tenant_id / actor / msg`；
- trace_id 从 L2 中间件生成/透传（`contextvars`），贯穿日志与 OTel span（08 篇 §1）；后台任务从 payload 恢复上下文；
- **禁 `print`**；禁 f-string 拼接敏感参数——入参走 `params_digest` 脱敏（08 篇 §3）；
- 级别约定：ERROR=需人工介入、WARNING=降级/重试、INFO=关键状态迁移、DEBUG=局部细节。

```python
logger.warning("retrieval_degraded", trace_id=ctx.trace_id, tenant_id=ctx.tenant_id,
               mode="vector_only", reason="neo4j_unavailable")   # ✅ 结构化 kv
```

### 2.9 测试规范

- **AAA 布局**：用例内 `# Arrange / # Act / # Assert` 三段注释分块；
- 命名 `test_{单元}_{场景}_{期望}`，场景/期望用中文短语：`test_session_重复消息_抛出4102`；
- **fixture 分层**：`tests/unit/conftest.py`（内存聚合工厂）、`tests/integration/conftest.py`（testcontainers 五存储，每用例自建租户、结束自清理）；fixture 用**工厂函数**构造，禁静态 JSON（08 篇 §8.2）；
- marker：`integration`（起真实存储）、`slow`；纯单测必须秒级可跑（`pytest -m "not integration"`）；
- 不变式测试：每条不变式至少合法 + 非法各一例；状态机全部非法迁移参数化断言（04 篇 §7）；契约 schema 快照变更必须在 PR 描述显式确认（08 篇 §8.2）。

```python
def test_task_终态后再次迁移_抛出DomainError():
    # Arrange
    task = make_task(status="succeeded")
    # Act / Assert
    with pytest.raises(DomainError):
        task.transition_to("running")
```

## 3. 前端规范（frontend/）

### 3.1 组合式 API 统一

- 一律 `<script setup lang="ts">`；**禁 Options API**（新代码零容忍）；
- 类型化宏：`defineProps<{...}>()`、`defineEmits<{...}>()`；`ref` 显式泛型（`ref<AgUiEvent | null>(null)`）；
- 组合逻辑放 `composables/useXxx.ts`，组件内不写跨组件复用逻辑。

### 3.2 组件规范

- 组件文件**多词 PascalCase**（`ReviewTable.vue`）；views 以页面目录组织、入口 `index.vue`；
- **单向数据流**：props 只读不改，需要改用 `emit` 回传或 `defineModel`；
- 插槽默认内容兜底；组件超 300 行或承载 3 个以上不相关职责即拆分。

### 3.3 样式铁律（frontend/01 篇）

- 颜色/圆角/阴影/间距**只允许 `var(--onto-*)` token**，禁裸色值（hex/rgb/`--el-*` 直用）；lint 自定义规则强制；
- `styles/tokens.scss` 是 token 唯一定义处（亮/暗两态）；Element Plus 变量覆盖**只收敛在 `element-overrides.scss`**（`--el-*` → `--onto-*` 映射），组件内禁写 `--el-*`；
- 组件样式 `scoped`；全局工具类只进 `global.scss`（`.onto-card` 等）。

```scss
.card { background: var(--onto-bg-elevated); box-shadow: var(--onto-shadow-sm); }  // ✅
.card { background: #ffffff; }                                                    // ❌ 裸色值
```

### 3.4 状态与请求（frontend/03 篇 §4/§5/§6）

- **API 调用只在 `src/api/`**：单例 axios（`http.ts` 拦截器统一注入 JWT / `X-Tenant-Id` / `X-Client`）；组件与 store 禁直接 `axios/fetch`；方法命名 `listX/getX/createX/updateX/deleteX`，注释写死路径；
- **SSE 一律经 `useEventStream`**（重连、`Last-Event-ID`、心跳看门狗内建），组件禁直接 `new EventSource`；ChatStream 只订阅 store 渲染态，不解析协议；
- Pinia **setup store** 写法，按域划分（auth/ui/session/ontology/kb/memory/plugin）；服务端长列表原始行留页面局部状态，不冗余进 store；持久化仅 `ui.theme` 与 auth。

```ts
/** POST /api/v1/sessions/{id}/messages */
export function createMessage(id: string, body: SendMessageIn) {
  return http.post<never>(`/sessions/${id}/messages`, body);
}
```

### 3.5 路由与权限（frontend/03 篇 §7）

- 路由表 `routes.ts` 与 frontend/02 篇 §2 逐条对应，每条带 `meta: { title, roles[], icon, hidden }`；
- 守卫统一在 `router.beforeEach`（白名单 → 登录检查 → roles 求交 → 403），**禁页面级散写守卫**；
- 按钮/操作级权限用 `v-permission` 指令，角色 id 与 08 篇 §2.2 权威码一致（admin/ontologist/curator/member/guest），禁在代码里硬编码角色判断矩阵（矩阵落 `roles.scopes` 种子，08 篇 §2.2）。

## 4. SQL 与迁移规范

- **禁裸 SQL in 业务层**：L2~L5 不得出现 SQL 字符串/ORM 查询；SQL 只存在于 L6 `repo_impl/`（SQLAlchemy 2.0 typed 风格）与 `migrations/`；Cypher 只经 `clients/neo4j.py` 构建器（强制租户过滤）；
- **迁移只增不改**：已合入 develop 的迁移不可变；结构迁移与数据迁移分文件；`downgrade()` 必须可执行（06 篇 §7 四条纪律全文重申）；
- 改表三步流程（顺序不可反）：06 篇契约 → [docs/database/01](../database/01-数据库详细设计.md) DDL → Alembic 迁移；
- **长事务禁令**：事务内禁 LLM/MCP/MinIO 调用；SSE 流全程不持事务；批量任务分批提交（抽取流水线每步独立 checkpoint 事务，03 篇 §4）；
- 每个仓储方法查询必须携带租户过滤（`for_tenant` 构造期绑定保证）；新增表唯一索引必须含 `tenant_id`（docs/database/01 §1.2）。

```python
# ✅ L6 repo_impl：typed 风格 + 租户过滤（构造期绑定）
stmt = select(TaskORM).where(TaskORM.tenant_id == self._tenant_id, TaskORM.status == "pending")
# ❌ L3 编排器内拼接 SQL —— 评审直接打回
rows = await conn.execute(text("SELECT * FROM tasks WHERE ..."))
```

## 5. 提示词治理（LLM 资产）（2026-09-26 旧稿合入）

> **2026-09-26 旧稿合入**：本节摘录自旧稿[架构设计/18-提示词与抽取策略设计](../架构设计/18-提示词与抽取策略设计.md)的栈无关增量（提示词版本化治理、候选统一信封、Token 预算引用）；四类抽取模板细节以 [docs/OntRAG 知识库设计 §2.3](../OntRAG/知识库GraphRAG设计.md) 为准引用不重复。宪法两条贯穿：**第 2 条推理分级**——LLM 输出一律过确定性校验（JSON Schema / SHACL）才可采纳；**第 3 条候选非成品**——LLM 产出只进候选区，经门禁或人工终审才升级。

### 5.1 提示词是版本化资产：模板入库、变更评审、运行时引用版本号

- **模板入库**：`PromptTemplate` 入库为版本化资产，字段 `id / name / kind / version / body / schema_ref / few_shot_refs / model_hint / evalset_ref / status / created_by`；kind 与用位一一对应（`extract.text / extract.data / extract.flow / extract.multimodal` 及判定类用位）；
- **变更评审**：与本体 changeset 同款流程 `draft → reviewing（审批中心）→ active → deprecated`；active 后不可变，修错发新版本；正文 / schema / few-shot 任一变更即构成变更集，评审材料必附评测回归报告；
- **版本钉死（version pin）**：运行期只调 active 版本，任务定义显式记录 `模板 id@version`，同一 job 全程同版本——回归可复现、成本可归因（template_ref 进 llm_calls）；
- **模板引擎约定**：Jinja2 严格子集（仅 `{{var}}` 插值与槽位，禁循环 / 分支 / 过滤器），模板可静态校验（变量完备性、注入位存在性进 CI）；
- **few-shot 样例**：独立版本化资产（更新走同款评审），每集必含正例 + 拒绝例（教模型何时不抽、何时输出 uncertain）；
- **评测回归门禁**：每类模板配评测样例集（抽取类 = 字段级 F1 + schema 通过率 + 出处 span 命中率；判定类 = verdict 一致率），任何变更 CI 强制跑回归——字段 F1 降 > 2pp 或一致率降 > 3pp（初值）即评审打回；与 §1.2「触及提示词的 PR 追加评估回归阶段」同一落点。

### 5.2 四类抽取模板（要点引用，不重复）

文本 / 数据表格 / 时序流程 / 图片多模态四类模板的提示词要点与分型策略以 [docs/OntRAG §2.3](../OntRAG/知识库GraphRAG设计.md) 表 1 为准，本节不重复；此处只钉**公共硬要求**：

1. 每个候选必带 `source_ref` 四元组（document_id + doc_version + chunk_id + span，doc_version 参与哈希——引用出处永远能定位到「哪个版本的哪一段原文」）；
2. 候选之间**不得互为证据**（佐证计数只认终审事实）；
3. 只输出符合 `{{output_schema}}` 的 JSON，依据不足输出空集或 null，**禁止先验补全**。

各类输出 JSON Schema 骨架（完整可校验定义）见旧稿 [18 篇 §2](../架构设计/18-提示词与抽取策略设计.md)，模板正文实施期填充。

### 5.3 候选统一信封（宪法第 3 条的落库形态）

所有 LLM 产出一律封装为**统一信封**后落库，只进候选区（review 队列），经门禁或人工终审才升级。核心结构 `{payload, confidence, source_pointers}`：

| 信封字段 | 说明 |
| ---- | ---- |
| `payload` | 类特定结构，按模板 schema 校验（宪法第 2 条落点） |
| `confidence` | 门禁与排序参数，**非真值**；未校准不得直接作裁决依据 |
| `source_pointers`（provenance） | 最少一条出处证据：source_ref 四元组或会话/工具调用/人工来源 |

完整信封字段（envelope_version / candidate_type / template_ref / trace_id / payload / provenance / review）与 JSON Schema 见旧稿 [18 篇 §3](../架构设计/18-提示词与抽取策略设计.md)。不变式：`candidate_id` 与 `review.state` 由系统回填流转，LLM 只产 payload 与 confidence；候选不得互为证据。

### 5.4 Token 预算（引用，不重复）

绝对 token 预算与上下文注入占比以 [Agent/Agent服务设计 §4.1](../Agent/Agent服务设计.md) 已合入口径为准（「绝对 token + 窗口占比」双约束，起步值 M3 实测后冻结），本篇不重复；按模板 kind 的成本量级预估表（对齐 llm_calls 归因口径）见旧稿 [18 篇 §9](../架构设计/18-提示词与抽取策略设计.md)，初值待评测集 + 灰度流量标定。

## 6. Git 规范

### 6.1 分支与合并（根 README「分支策略」）

`master`（可发布）/ `develop`（日常）/ `feature/{域}-{简述}`（如 `feature/ontology-changeset`）；feature → develop 用 **squash**；develop → master 打 tag 发布。

### 6.2 Conventional Commits（中文描述）

格式：`{type}({scope}): {中文描述}`

| type | 用途 | 示例 |
| ---- | ---- | ---- |
| feat | 新功能 | `feat(kb): 文档切片支持按章节分片` |
| fix | 缺陷修复 | `fix(ontology): 修复变更单回滚未失效缓存` |
| docs | 文档 | `docs(db): 补 writeback_ledger 分期矩阵` |
| refactor | 重构 | `refactor(domain): 会话聚合拆出 Run 实体` |
| test | 测试 | `test(business): 补检索降级三条路径单测` |
| chore | 构建/工具 | `chore(deploy): Milvus collection 初始化脚本` |

| scope | 范围 | scope | 范围 |
| ---- | ---- | ---- | ---- |
| gateway / business / domain / semantic / data / infra | 后端七层 | frontend | 前端 |
| cli | CLI | db | 迁移/表结构 |
| kb / ontology / memory / mcp / plugin / review / writeback | 业务域 | deploy / docs / ci | 工程支撑 |

### 6.3 commit / PR 检查清单

- [ ] PR 描述含：动机、改动面、测试证据；触及接口/表/事件的列出需同步的文档清单（§8）；
- [ ] 前端 PR 附对应页面截图（亮/暗两态）；触及模型/本体/检索参数/提示词的 PR 附评估回归结果（08 篇 §7.2）；
