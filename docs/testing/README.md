## 1. 定位

本目录是 ontology-agent 平台**测试体系的唯一入口**。平台零代码起步，测试先于代码设计：**用例是开发的验收合同**——任何模块动工前，其对应域的用例必须先行评审通过。测试金字塔、覆盖率门槛、环境与缺陷流程见策略篇；逐条可追溯的用例见用例集篇。

## 3. 用例维护规则

- **新不变式**（04 篇 §2 不变式总表增行）→ 必须同步新增 TC-DOM 用例（合法 + 非法各一，04§7）；
- **新端点**（02 篇 §4 路由清单增行）→ 必须同步新增 TC-API 用例（含 scope 标注断言）；
- **新事件**（04 篇 §6.1 事件-消费者映射表增行）→ 必须同步新增事件消费/幂等/失败语义用例；
- **新错误码**（02 篇 §7 登记分段）→ TC-API-005 语义抽样集同步补充；
- **用例 ID 只增不改**：语义变化时废弃旧 ID（行内标注 deprecated 并保留）+ 新增新 ID，禁止复用、禁止重排；
- 用例修订走 PR：评审人核对追溯列仍指向有效上游条目，上游条目本身变更时先改上游再同步用例。

## 4. 与 CI 的关系

- 用例「自动化层级」列即 CI 归属：单测 → unit 阶段；集成（lite 子集）→ integration-lite；golden/契约 → contract 与常驻基准；E2E/性能/full 集成 → nightly（阶段表见策略篇 §4）；
- **里程碑矩阵（02 篇 §12）= 各期发布门禁依据**：出口评审逐行打勾，未绿不放行；
- 评估回归（08 篇 §7.2）作为独立 CI 阶段按变更触发，主指标退化超阈值即阻断合并；
- `@pytest.mark.full`（Neo4j/Milvus）仅在 nightly full 档执行；本地 lite 档承担日常主干（锚点 §3.2 部署分档）。
