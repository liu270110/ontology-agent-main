### 1.2 从 llmwiki 借鉴什么

| llmwiki 机制 | 本平台对应物 | 差异说明 |
| ---- | ---- | ---- |
| 原始文件只读，wiki/ 是编译产物，`.llmwiki/` 索引可删可重建 | **三层资产模型**（§2）：Raw 不可变 / Compiled 可再编译 / Derived 可丢弃 | 平台的编译产物不止 Markdown 页，而是候选实例 → 终审事实 → 图谱/向量索引 |
| 增量编译：routine 只处理上次运行以来的新增，把新材料"折入"既有页面 | **维护例程**（§5.2）：只重编译受影响事实的社区摘要，不全量重建 | 平台有 ARQ 任务队列与 Outbox 事件，例程由事件驱动 + 定时兜底 |
| **Supersession callout：变更要显式声明取代，不许静默覆盖** | **supersedes 链**：文档级与事实级都显式记录取代关系，检索结果默认携带"已被 X 取代"提示（§4、§6） | 平台用图边 + 双时间戳承载，比 Markdown 标注更结构化 |
| 外部系统声明必须带指针 + 核对日期，lint 按最老优先重验 | **易变知识不入库，只存指针**（§5.4）；知识条目带 `checked_at`，v1.5 起陈旧重验 | 直接采纳，这是社区 1000+ 评论里最痛的教训 |
| lint 巡检：悬挂链接、孤儿页、陈旧页 | **知识 lint**（§5.2）：悬空出处、孤儿实体、陈旧声明、失效未封口 | 检查对象从 Markdown 换成图谱与索引；v1 只做廉价三项 |
| Promotion gate：agent 起草、人工晋升，未晋升草稿不得作为证据被引用 | **候选非成品**（设计宪法第 3 条，已有）+ **候选不得互为证据**（§3.2） | 已有，本文补"候选不得互为证据"细则 |
| "Scope, don't filter"：按领域切分语料，不把一切塞进上下文 | 知识库按 kb_id（业务域）划分集合/分区，检索路由先定域再查 | 已有 kb_id 设计，重申为检索前置步骤 |

### 1.3 七条设计公理（本文档范围内强制）

1. **原始层不可变**：原始文档与切片永不修改、永不物理删除；一切下游资产都是它的投影。
2. **事实带时间线**：每条断言有双时间（业务有效时间 t_valid / 入库事务时间 t_txn）；失效用边和封口表达，不删除。
3. **取代必须显式，且分边承载**：版本承接走 `SUPERSEDES`，裁决淘汰走 `OUTRANKED_BY`，无替代撤回走 `INVALIDATED_BY`（§4.3），禁止静默覆盖。
4. **默认最新，旧知可寻**：检索默认只返回当前代有效知识；时间点查询（as-of）与显式包含被取代知识是一等公民参数。
5. **消歧在入库时完成大半**：术语对齐是入库门禁，不留到检索时猜。
6. **冲突是治理信号，不是错误**：冲突自动分诊，裁决不了的进人工工单；**v1 不做机器终审**——所有 T2/T3 冲突人工裁决（宪法第 3 条"硬门禁不可跳过"），自动化按 §11 分期逐步放开。
7. **主事实在 PG**（承接 02 篇 §7）：事实权威存储是 PG `kb_facts` 表；Neo4j / Milvus 是投影。bi-temporal 判定、承接比对、as-of 查询都在 PG 索引上执行。

## 2. 三层资产模型（知识库的地基）

```
┌────────────────────────────────────────────────────────────────┐
│ Raw 原始层（不可变）                                              │
│   原始文档（MinIO raw-documents，永久）                            │
│   切片 doc_chunks（PG，带 hash 与 span，版本戳）                    │
└──────────────┬─────────────────────────────────────────────────┘
               │ 七步流水线（抽取/对齐/校验/终审）
┌──────────────▼─────────────────────────────────────────────────┐
│ Compiled 编译层（可再编译，有门禁）——权威在 PG                      │
│   候选实例 candidates（PG，审核队列）                               │
│   终审事实 kb_facts（PG 权威注册表，bi-temporal + generation）      │
│   投影：Neo4j ABox 图（含 supersedes 链）、社区摘要                  │
│   术语表 terms / 别名表（PG）                                      │
└──────────────┬─────────────────────────────────────────────────┘
               │ 投影（Outbox 中继，幂等，按 event 单调推进）
┌──────────────▼─────────────────────────────────────────────────┐
│ Derived 派生层（可丢弃、可重建）                                    │
│   Milvus 向量索引、PG 全文索引、Redis 缓存、图谱统计物化              │
└────────────────────────────────────────────────────────────────┘
```

| 层 | 变更策略 | 回答什么问题 |
| ---- | ---- | ---- |
| Raw | **append-only**：只增不改不删（同源更新 = 新版本文档追加，旧版本转 superseded 状态而非删除） | "旧知识也需要在"的第一保证——任何历史内容永远取得到 |
| Compiled | 门禁内变更：事实被取代时封口 + 连边，不删；社区摘要可随时由 Raw + 事实重算 | 知识的当前语义与历史演变 |
| Derived | 任意重建：Milvus 可全量重灌（源在 PG），索引损坏零风险 | 检索速度 |

这一分层是 llmwiki "filesystem is the source of truth; the index just makes it fast to search" 的结构化落地：**只要 Raw 在，任何知识在任何时刻的状态都可重放重建**。02 篇的容量与备份策略（Milvus 可重建、MinIO 永久）与本模型一致。

## 3. 文档解析入库（七步流水线的落地细化）

既有七步框架不变：`文档预处理 → 环境配置 → 批量抽取 → 术语对齐 → 一致性校验 → 约束校验 → 人工归档`。本节给每一步补上本文关心的强化点。

### 3.1 文档预处理：准入 + 同源检测（v1 两级，SimHash v1.5）

上传后先做同源检测，再进常规预处理（格式转换/OCR/表格标准化，矩阵见研究 03 篇）：

| 级别 | 手段 | 命中含义 | 路由 | 分期 |
| ---- | ---- | ---- | ---- | ---- |
| ① 精确重复 | 内容 SHA-256 | 完全相同的文件 | 拒收（幂等返回既有文档） | **v1** |
| ② 身份命中 | **文档身份键**：规范化编号/标题（如 `GB/T 31486`），解析出 `identity_key + doc_version` | 同一文档的新版本（如 2015 版 vs 2024 版） | 走**版本更新路径**（§3.4） | **v1**（T1 承接判定的前提，必须先做） |
| ③ 近似同源 | n-gram SimHash（阈值待真实语料校准） | 大面积改写/拆分合并的疑似同源 | 人工确认：新文档 or 新版本 or 独立文档 | v1.5（`documents.simhash` 列 v1 预留；漏检场景由 T2 冲突工单兜底） |

- 身份键解析：标准/法规类文档优先解析编号（`GB/T xxx`、`ISO xxx`）+ 年号版本；无编号文档用规范化标题 + 发布日期。
- **命中身份即建链**：新版本文档的 `supersedes_id` 指向旧版本，形成文档版本链（`v2015 → v2024`），链上每个版本都是独立的 Raw 资产，永不删除。

### 3.2 环境配置 / 批量抽取：出处指针加密

- 抽取提示词模板（研究 03 篇四类）不变；硬要求：**每个候选事实必须带 `source_ref = (document_id, doc_version, chunk_id, span)`**，且 `doc_version` 参与哈希——引用出处时永远能定位到"哪个版本的哪一段原文"。
- **候选不得互为证据**（promotion gate 细则）：候选 A 的置信度不能因为引用了候选 B 而提升，防止"坏知识互证成环"；佐证计数（T4）只统计经终审的事实。
- **谓词白名单前置**：候选谓词必须映射到 TBox 属性；映射失败的谓词单独进"候选属性"工单，不得静默跳过——否则后续承接比对与冲突检测的比对键直接失效。

### 3.3 术语对齐：消歧的入库时刻（详见 §8）

候选实体/概念在此与术语表对齐（绑定既有 IRI / 新建候选 / 歧义工单三态）。术语唯一性国标底线在此门禁。

### 3.4 一致性校验：冲突分诊 + 事实级承接判定（详见 §4）

新增冲突检测器。**核心原则：文档被替代 ≠ 其派生事实全部作废**——新版文档通常只改写部分内容，必须逐条判定，不能整链推翻。承接判定在 PG `kb_facts` 上执行（权威表，按 `source_doc_id` 索引反查，subject 分组后哈希连接，单文档数千事实为毫秒~秒级）：

```
新版文档 v2024 终审通过
  → 取旧版本 v2015 派生的全部当前事实（kb_facts 按 source_doc_id 索引，按 subject+predicate 分组）
  → 与 v2024 的新事实逐条比对：
      a) 新版有同主谓新事实        → 旧事实标 superseded，valid_to = 继任事实 t_valid_from，
                                    连 SUPERSEDES；新版拆为多条时允许组级边（记 cardinality=split）
      b) 新版未重现的旧事实        → 先做【定向复查抽】：用旧事实宾语值 + 术语对新版 chunks
                                    做检索式复查（走 §7 词法路）。命中 → 判"疑似漏抽"，加急工单；
                                    未命中 → 判"确认删除"，转 needs_review
                                    （"源已更新，本条未在新版重现"，默认可见但带待复核标注）
      c) 新版明确否定（矛盾）       → 走冲突分诊（§4）
```

**顺序依赖**：若本体同期发生 MAJOR 变更，先完成 §5.3 的 IRI 迁移，再执行承接判定（对齐键依赖 IRI 稳定）。

### 3.5 约束校验 / 人工归档：代际激活切换（generation 模式）

> 修订说明：v0.1 的"状态字段翻转 + 原子切换"在 Outbox 异步投影下不成立——Neo4j/Milvus/PG 三处存储无跨库原子性，先写新后封旧会出现"双 current 窗口"（图谱路已返回新事实、向量路仍返回旧事实，RRF 去重因 IRI 不同而失效，矛盾上下文注入 LLM），先封旧后写新则出现"零 current 窗口"。修订为**代际激活**模式，把原子点收敛到 PG 单行：

**模型**：每条 `kb_facts` 行带 `generation` 代数；每个知识库（`kbs` 表）维护单行 `active_generation` 激活指针。**检索统一按 `generation = active_generation` 过滤**。

**切换流程**（新版文档终审通过后）：

1. **PG 单事务**：写入新代事实（`generation = active + 1`：新版事实 + 承接判定保留的 needs_review 事实）+ 旧代事实封口（valid_to、superseded 状态、取代关系）+ 写 Outbox 事件（同事务，02 篇约定）；
2. **Outbox 中继投影**：新/旧事实（均带 generation 标记）幂等投影到 Neo4j（图结构与 supersedes 边）与 Milvus（向量标量）；投影按事件序单调推进，失败重试、超限死信（02 篇既有纪律）；
3. **激活**：投影追平后，`UPDATE kbs SET active_generation = active + 1`（**全流程唯一原子点，PG 单行**）；
4. **善后**：受影响社区标脏，投递 `kb.community.dirty` 事件；旧文档 `lifecycle → superseded`（Raw 层文件原封不动）。

**窗口期语义（明示）**：激活前用户看到旧代知识（数据一致，只是未更新）；激活后立即全量切到新代。**不存在新旧混杂窗口**——新旧代在所有存储中都共存但互不可见，检索过滤条件单一。代价是切换期间的新事实有激活延迟（SLO：< 5 分钟，投影滞后告警沿用 02 篇）。幂等键：`(tenant_id, kb_id, old_doc_id, new_doc_id, step)`，各步可安全重放。

## 4. 新旧知识冲突治理

### 4.1 冲突分诊：四型四处置 + 判定顺序

冲突检测器触发时机：新事实终审前（PG `kb_facts` 内按 `subject IRI + predicate IRI` 比对当前代事实）+ 维护例程补扫。**分诊按固定顺序执行**（先廉价确定性判定，后语义判定）：

```
T1 版本链命中？ → 是：T1。否 ↓
主谓宾全同？   → 是：T4。否 ↓
双方 scope 均有源文 span 落地且键不相交？ → 是：T3。否 ↓
否则：T2
```

| 类型 | 特征 | 处置 | 例子 |
| ---- | ---- | ---- | ---- |
| **T1 版本演进** | 两事实的 source_ref 在同一文档版本链上（或源文档间有 replaces 关系） | 不是冲突：自动建立事实级 SUPERSEDES 边（§3.4 已在承接判定中完成），无需人工 | GB/T 31486-2024 修改了 2015 版的容量限值 |
| **T2 真矛盾** | 无版本关系，语义互斥 | **v1 全部进冲突工单人工裁决**；评分公式仅作工单 UI 的参考排序分，不触发自动动作（§11：v1.5 用积累的人工裁决数据标定阈值后再开自动档） | 文档 A 说审批上限 50 万，文档 B 说 100 万 |
| **T3 限定差异** | 表面矛盾，适用 scope 不同 | 两条都保留为有效，各自标 scope；**v1 由人工在工单中判定并人工填写 scope 值** | 京沪海规 vs 国标对同一指标的不同要求 |
| **T4 多源重复** | 主谓宾全同，来源不同 | 合并佐证：一条事实挂多 source_ref，置信度上调，来源列表保留 | 三个文档都确认同一参数 |

**scope 结构（现在就定，自动化后移）**：scope 为封闭枚举键值 map——`temporal`（区间）/ `region`（行政区划码）/ `product_line`（IRI）/ `regulatory_domain`（IRI）。**硬门禁：作为 T3 判定依据的 scope 值必须回指源文 span（原文中确实出现限定语）；LLM 推断出的 scope 只能作为工单里的参考信息，不得自动生效**——防止 T2 真矛盾被误判为 T3 后以"都有效"长期共存且无人知晓（nightly 抽样复核兜底，§5.2）。

### 4.2 冲突工单（审批中心第五类对象）

冲突工单复用审批中心状态机（`submitted → reviewing → approved/rejected → applied`），候选的 `review_state` 扩展 `conflict_pending`。参考评分公式（仅排序展示，v1 不触发动作）：

```
score = 0.35·来源权威(文档类型/机构分级) + 0.25·时效(新近者得分)
      + 0.20·佐证数(独立 source_ref 数) + 0.20·出处质量(span 指向条款原文 > 转述)
```

工单 UI 并排展示两条事实 + 各自原文出处 + 参考评分明细，人工点选胜者 / 判定 T3 限定共存（填 scope）/ 判定待定。裁决动作落审计（before/after）。

### 4.3 取代/失效的边语义约定（全文统一）

| 边 | 语义 | 使用场景 |
| ---- | ---- | ---- |
| `[:SUPERSEDES]` | **存在替代版本的更替**（版本承接语义，时间线通道遍历此链） | T1 承接判定、文档版本链 |
| `[:OUTRANKED_BY {conflict_id, score, decided_by}]` | **裁决淘汰**（无版本关系的矛盾，一方被人工裁决胜出） | T2 工单裁决 |
| `[:INVALIDATED_BY]` | **无替代的撤回/作废** | 工单裁决废弃、T3 scope 撤销、错误入库撤回 |

三者互不复用：时间线/演变史通道只走 `SUPERSEDES`（保证呈现给用户的是真版本史，机器裁决结果不混入）；`OUTRANKED_BY`/`INVALIDATED_BY` 在"失效说明"面板呈现。

### 4.4 与记忆系统的边界

本节治理的是**知识库 ABox（L4 共享语义）**。会话/用户/组织层记忆的新旧冲突（L1~L3）走记忆沉淀管线的 ADD/UPDATE/DELETE 判定（`docs/研究整理/04-多层记忆` §3.1），不复用知识库冲突工单；但 L2/L3 记忆沉淀中发现的**领域事实级**矛盾，可发起候选知识条目流程进入本节管线（04 篇已定的 L3→L4 通道）。

## 5. 知识保鲜：三条保鲜线 + 维护例程

### 5.1 文档级：生命周期状态机

```
draft → current → superseded ──┐
   ↑               │           ├──→ archived（仅检索默认视图移除，Raw 永在）
   └── (新版本终审) ─┘───────────┘
```

`current` 文档派生的知识默认可见；`superseded` 文档的知识按 §3.4 承接判定处理；`archived` 仅审计/as-of 场景可达。与既有 `status` 列的关系：`status` 更名 `ingest_status`（处理管线状态：上传/解析中/失败/就绪），与 `lifecycle`（版本时效状态）正交，职责不重叠。

### 5.2 知识级：维护例程（事件驱动为主，定时兜底）

**保鲜主通道是事件驱动的**（文档更新 → 版本链 → 承接判定 → 投影刷新，§3.4/§3.5），定时例程只做兜底。ARQ 定时任务 `kb_nightly_maintenance`，**只处理增量，且有硬上限**：

| 项 | v1 | v1.5+ |
| ---- | ---- | ---- |
| 增量重编译 | 只重算消费游标以来标脏的社区摘要（事件驱动为主，夜间兜底） | 同左 |
| 催办 | needs_review 超时（默认 14 天）催办；**30 天未复核自动转 archived**（保留可溯、不再占队列，聚合复核单位 = 按 subject/主题分组） | 同左 |
| 知识 lint | 悬空出处告警（source_ref 指向不存在的文档/切片）——廉价，纯 SQL | 补齐：孤儿实体候选清理工单、`checked_at` + 陈旧重验（LLM 对照原文，按最老优先）、Milvus 与 Neo4j current 集合对账 |
| 冲突补扫 | —（依赖自动裁决，随 §11 v1.5 开启） | T2 裁决抽样复检（本体/规则更新后旧裁决可能失效） |

**例程工程纪律（v1 就要，防失控）**：

1. **预算上限**：每次运行三项硬上限 `max_communities_recompiled / max_facts_reverified / token_budget`，超限顺延次夜并告警；LLM 成本经模型网关按任务类型分账（与记忆后台任务同一纪律）；
2. **增量游标**：checkpoint 落 PG `kb_maintenance_runs`（记 watermark/last_event_id），重编译以 `(community_id, input_hash)` 幂等，防 at-least-once 重复消费烧钱；
3. **调度互斥**：Redis 锁 `lock:kb_nightly`（TTL + 心跳续期）防多 worker 双跑；例程走独立队列 `arq:queue:kb_batch`（worker 并发 1），与在线抽取任务隔离；
4. **结构漂移**：社区成员变化率超阈值（初值 30%）时提示人工确认重跑 Leiden，不自动重分区。

### 5.3 本体级：TBox 版本链与 ABox 共存（"本体最新，旧知识也在"）

本体版本管理已有基线（ADR-5：Turtle 快照 + 版本注册 + 变更评审 + 回滚；`ontology-versions` 桶永久保留）。本节补齐**本体演进时旧知识怎么办**：

1. **语义兼容分级**（发布时标定，`ontology_versions.compat_level`，自动计算 + 版本评审人工双签确认）：

| 级别 | 变更内容 | ABox 影响 |
| ---- | ---- | ---- |
| PATCH | 标签、注释、非约束性元数据 | 无需迁移 |
| MINOR | **仅新增正公理**：新增类/属性、子类公理、新的实例属性 | 无需迁移；新公理的可推理新结论由规则物化增量补齐 |
| MAJOR | **一切含负约束的变更**（新增不相交/函数性/基数约束——它们可使既有实例违反 SHACL，按句法是"新增"实为破坏性）、删除/收窄类、修改属性定义 | v1：人工小步迁移（单机规模可承受）；v2：影响面分析器自动完成 |

2. **实例版本戳**：`kb_facts` 带 `ontology_version`；"按本体 vX 解读"= 加载对应版本 TBox 快照执行查询（版本快照永在，MinIO 永久桶）——**旧版本本体永远可加载，历史事实永远可按当时的模式还原语义**。v2 再自动化（影响面分析器：TBox 规范化 diff → 类/属性闭包 → 受影响实例清单 → 分批迁移任务（5k~10k/批，快照只记被改属性前后值）→ 审批 → 执行 → 可回滚）。
3. **非破坏演进原则**（承接国标第 9 章扩展原则）：优先用新增与收窄代替删除；确需删除的概念先标 `deprecated`。**移除门禁三条同时满足**（写入 MAJOR 发布检查单）：① 自 deprecated 起历经 ≥2 个已发布版本（不分级别）；② ABox 中该概念的实例使用计数 = 0（v1 人工核查，v2 由影响面分析器输出）；③ 无其他 TBox 公理引用。

### 5.4 易变知识不入库，只存指针

价格、库存、实时状态、外部系统权限类**易变声明不作为知识入库**——知识库只存"该去哪查"的工具/接口指针（挂到本体行动类，经 MCP 工具实时取数）。这是 llmwiki 社区最痛的教训（"lint 天天验证通过，矛盾却在知识库从不读的代码里"）：**保鲜成本过高的知识，正确的处理是不让它变成知识**。此条作为**入库准入门禁**实现（文档分类为易变数据型时，抽取管线只提工具指针候选），不只是原则。

## 6. 旧知识找回：时间机器

### 6.1 双时间线模型

| 时间维 | 含义 | v1 实现 | 例 |
| ---- | ---- | ---- | ---- |
| `t_valid_from / t_valid_to` | 业务有效时间：事实描述的世界状态何时成立/失效 | **v1 从所属文档版本的发布/实施日期批量继承**（不做逐条 LLM 判定，避免新增幻觉面）；封口值 = 继任事实的 `t_valid_from`（业务生效时间），**不是处理时刻**；源文档无明确生效日期时回退为处置时刻并记 `effective_date_known=false` 供审计区分 | 容量限值 100Ah 自 2024-03-01（新版实施日）失效，即使 2026-09 才入库 |
| `t_txn` | 事务时间：我们何时知道并入库 | = 行 `created_at`（改名即得，零成本） | 2024-05-10 上传 2024 版标准并终审 |

> v0.1 曾把封口写成 `valid_to = now`，混淆了两个时间轴——as-of(2025-01) 会同时命中旧事实和新事实，返回矛盾答案。v0.2 已修正：**处理动作时刻只进 t_txn，业务失效时刻只进 t_valid_to**。

**完整 as-of 谓词**（所有实现遵守）：

```
t_valid_from ≤ as_of  AND  (t_valid_to IS NULL OR as_of < t_valid_to)  AND  t_txn ≤ as_of
```

### 6.2 检索三态语义（产品级默认值，所有检索接口强制实现）

| 模式 | 参数 | 语义 | v1 实现落点 |
| ---- | ---- | ---- | ---- |
| **当前有效**（默认） | 无 | 只返回当前代（generation = active）知识 | PG `kb_facts.generation` 过滤；投影侧同条件；v2 事实级独立 t_valid 后叠加谓词 |
| 时间点 as-of | `as_of=<时刻>` | 返回该时刻有效的知识（审计/合规："当时的规定是什么"） | **PG `kb_facts` 索引查询 + Neo4j supersedes 链**（集合检索，不在 Milvus 做——向量库做高选择性范围过滤会退化为近暴力扫描）；v1 基于文档版本链回溯 |
| 全量含旧 | `include_superseded=true` | 被取代知识一并返回，**必须带显著标注**（"已于 X 时被 Y 取代"+ 取代链入口） | 不过滤，结果分组：current / superseded（附 supersedes 链） |

- **遮蔽而非消失**：superseded 知识从默认视图消失，但在 as-of 模式、supersedes 链遍历（"这条结论的演变史"）、出处反查（从原文切片找它派生过的知识）三条通道中永远可达。
- **needs_review 事实随新代可见**（承接判定 b 类），结果带"待复核"标注——可见性靠 generation，不靠删除。
- **社区摘要过期窗口（设计决定）**：切换后到重编译前，社区摘要服务的是旧内容，可接受；标脏事件保证最终刷新（§5.2 上限内顺延）。
- 前端三处消费：对话答案的"知识时效"徽标、知识详情页的版本时间线、图谱浏览的"显示已失效事实"开关。

### 6.3 chunk / entity / fact 三级时效的解耦（v0.2 修正）

**事实级时效 ≠ 文档级时效 ≠ 切片级时效**，三者过滤条件不同源，不得互相推导：

| 实体 | 时效标记 | 默认视图行为 |
| ---- | ---- | ---- |
| Fact（kb_facts / 图节点） | `generation` + t_valid 区间 + state | 事实级三态过滤**只在这里**生效 |
| kb_chunks（Milvus 向量） | `doc_generation` + `doc_lifecycle` 标量（**不设 is_current**） | 旧文档切片**降权不过滤**（lifecycle 参与 §7.2 软加权；v1 软加权未开时仅作结果标注）——保证"旧文档中未被取代的仍有效事实"在向量路**可召回** |
| kb_entities（Milvus / 图） | `generation`（由事实封口事件聚合投影） | 随事实代际过滤 |

> v0.1 曾给 kb_chunks 设 is_current 并随文档生命周期翻转——按此实现，旧文档 superseded 后其切片从向量路整体消失，§3.4"needs_review 默认降权但可见"落空，违背公理 4。v0.2 修正为上表。Milvus 标量不支持原位更新，翻转/投影为整行 upsert，由 `kb.fact.*` 事件消费方执行并保证幂等。

## 7. 多路召回与融合

### 7.1 四路并行召回 + 显式时间线模式

| # | 通道 | 存储/实现 | 最擅长命中 | 典型失效场景（为何必须有这路） |
| ---- | ---- | ---- | ---- | ---- |
| 1 | 向量语义路 | Milvus kb_chunks（dense+sparse 混合） | 换说法的语义匹配 | 精确编号/术语字面查询（向量会偏） |
| 2 | 词法精确路 | BM25 + PG pg_trgm | 编号、代码、专有名词字面 | 高频词淹没 / 新词无向量 |
| 3 | 图结构路（local search） | Neo4j 实体邻域 + 关系路径 | 关系型问题（"A 和 B 什么关系"）、多跳 | 纯语义相似但图上无关的噪声 |
| 4 | 社区摘要路（global search） | 社区报告 map-reduce | 全局主题/总结类问题 | 细节问题（摘要粒度不够） |
| 5 | 出处反查路 | PG `kb_facts.source_ref` 反向索引 | 从答案/实体回到原文切片；从文档找它派生的知识 | 供审计溯源与 §3.4 承接判定用 |

**时间线不是并行召回路，是显式检索模式**：as-of、"最新版改了什么"、演变史都是用户意图明确的查询，入口直接路由到 §6 的 bi-temporal 查询与 supersedes 链；做成并行路会在用户没问历史时把旧知识混进融合排序，反而需要抑制逻辑。DRIFT 折中档 v1 不做（M3 验收只要求 local/global）。

路由策略：查询先经术语对齐（§8.3）+ 问题分类（local/global/时间线/精确词），**命中多解时多路并行而不是二选一**——路数取舍在融合层完成，不在入口完成。

### 7.2 融合排序

```
各路检索【前】下推硬过滤（tenant/kb/权限/generation——在 top-k 截断之前，
  否则各路候选被无权/过期结果挤占）
  → RRF（Reciprocal Rank Fusion）粗排
  → 硬过滤兜底 + generation 校验（以 PG kb_facts 权威状态为准，防投影滞后窗口双端不一致）
  → 去重聚合：同一事实多路命中只留一条，合并命中路数（路数越多越靠前）
  → [v1.5] 重排器（bge-reranker 类，经模型网关）
  → [v1.5] 软加权：置信度 + 陈旧度 λ·(now − checked_at)（只惩罚"久未核验"，
      不惩罚"老而有效"；λ·age 对 2015 版仍 current 的标准不合理）+ scope 匹配
```

### 7.3 证据链拼装

最终注入 LLM 上下文的每条知识都携带：`IRI + label + 时效状态（current / superseded-by-X / as-of-T 有效 / 待复核）+ source_ref`。回答生成时强制引用条目 ID（AG-UI 事件流回传 evidence_refs，已有设计），前端可点开原文定位——**全程可追溯**（设计宪法第 5 条）在检索出口收口。

## 8. 知识消歧

消歧在三个时刻发生，**大头在入库时**（公理 5）。

### 8.1 术语表：消歧的户口本（新增存储，02 篇增量）

PG 新增 `terms` + `term_aliases` 表（§9），由语义层 terminology 模块管理，与 TBox 的 `skos:prefLabel/altLabel` 按语言同步投影：

```
terms:        id, iri, preferred_label, language (BCP-47，同 IRI 允许多语言行),
              definition, kb_id (NULL = 平台级共享术语，为 v2 跨 kb 对齐预留),
              status, scope, ontology_version
term_aliases: term_id, alias, alias_normalized (匹配用规范化列), alias_type(缩写/俗称/旧称/译名),
              language, source_ref, UNIQUE(term_id, alias, language)
```

- 一个概念一个 IRI 一个 prefLabel（每语言一条），多个 alias；**旧称也是 alias**（标准换版后旧术语指向新 IRI，检索旧叫法能命中新知识）——这是"知识最新、旧叫法也能找到"的关键。
- 配套 Milvus 集合 `kb_terms`（term embedding；标量 term_id, iri, kb_id, language）支撑 §8.2 第 3 步语义相似度——02 篇分工矩阵写了"术语语义索引"但集合清单漏列，此处补齐。

### 8.2 入库时：术语对齐三步判定（流水线第 4 步，v1 范围）

对每个候选实体/概念，依序执行：

1. **精确匹配**：按 `alias_normalized` 命中（规范化：大小写、全半角、空白，入库时预计算）→ 绑定既有 IRI；
2. **词典匹配**：别名表 + 领域同义词典命中 → 绑定；
3. **语义相似度**：kb_terms 向量检索——**高置信（≥ 0.92）自动绑定；低于阈值（含 0.80~0.92 灰区）一律进歧义工单**（v1 不设 LLM 判别档，工单反正要做；人工裁决"合并/区分"的结果回写别名表，灰区随使用收窄——先人工喂表，v1.5 再把 LLM 判别档作为工单预分流引入）。

三态出口：**绑定**（label 不同则写 alias）/ **新建**（登记新 term）/ **歧义工单**（UI 并排两个定义 + 原文出处，人工裁决"合并/区分/暂缓"）。对齐结果回写候选的 `entity_iri`，抽取后续关系用对齐后的 IRI——保证图谱里同名实体唯一归位。

### 8.3 检索时：查询消歧

1. 查询词先经术语对齐（复用 §8.2 只读路径）得到 canonical IRI 集合；
2. **单解**：直接按 IRI 检索（图谱路 + 向量路带 IRI 过滤）；
3. **多解**（同形异义，如"苹果"多个 IRI）：**分组返回，各组带"这是《XX》中的定义"标签**——宁可多给，不许静默二选一；[v1.5] 上下文与候选 scope/社区匹配度高时自动选定并注明依据；
4. **零解**：回落纯语义检索 + 提示"未对齐到术语表，可能为新概念"，并可反哺候选术语流程。

### 8.4 输出时：身份三元组引用

LLM 回答中每条知识引用必须携带**身份三元组**：`IRI + prefLabel + 时效状态`。新旧并存的场景（`include_superseded` 查询）答案必须分组表述，禁止新旧混排不分。输出校验器检查：引用的条目 ID 必须真实存在于本次召回集合（防幻觉引用）。

## 12. 与平台其他服务的关系

- **本体核心**：术语表与 TBox 双向投影；冲突分诊的 T1 依赖本体 replaces/supersedes 关系；TBox 版本链（§5.3）是本体核心版本管理的直接延伸。
- **记忆服务**：边界见 §4.4；L4 与知识库共用保鲜思想（TTL/衰减/失效边/版本化，`docs/研究整理/04-多层记忆` §3.3），机制同构、工单分流。
- **审批中心**：新增第五类审批对象（冲突工单）；本体 MAJOR 迁移亦走审批。
- **Agent 服务 / MCP 出口**：`knowledge.search` 工具暴露三态参数（默认 current）；`ontology.query` 支持"按版本解读"；答案证据链格式在 AG-UI evidence_refs 中落地。
- **审计**：一切取代/裁决/迁移动作写 audit_logs（before/after），满足"谁在何时依据什么取代了哪条知识"的追问。
