# 29 - 前端复杂组件开源选型与自研决策（采用 / 封装 / 自研）

> 状态：v1.0 | 日期：2026-09-27 | 定位：**前端复杂组件"造轮子 vs 用轮子"的工程决策权威**——逐组件给出开源方案适配度评估与三级判定，避免重复造轮子，也避免为贴合开源而扭曲设计。
> 判定口径（用户定调）：**综合适配度 ≥80% 用开源，<80% 自研**。综合适配度 = 功能覆盖（权重 50%）+ 样式/令牌适配成本（25%）+ 协议与数据结构契合（15%）+ 维护活跃与许可证（10%）。
> 三级判定：🟢 **直接采用**（headless/底层库，样式走 shadcn 映射与 design-system 令牌）｜🟡 **采用+封装适配层**（核心能力开源，包一层自研 adapter 承接业务语义与玻璃主题）｜🔴 **自研**（业务语义强或无匹配方案，基件仍复用 design-system）。
> 上游依据：[24 篇](24-前端组件库扩充与外部样式借鉴.md)（样式借鉴已吸收，本篇不重复）、[26 篇](26-前端页面交互态详细设计.md)（83 项交互态=需求锚点）、[03 篇](03-前端架构与UI设计规范.md)（React+shadcn+液态玻璃路线）、[16 篇](16-前端工程与页面详细规格.md)（数据层与 SSE）。
> 调研方法：三路并行核实（npm registry / GitHub API / 官方文档实时数据，2026-09-26/27），非记忆值；关键事实均标注核实来源结论。

## 1. 生态级决策（先定底盘，再定组件）

### 1.1 底盘：shadcn/ui 沿用，新增组件优先 Base UI 版（FE-ADR-FE1）

shadcn 于 2026-07 起将默认底盘从 Radix 切换为 **Base UI**（官方 changelog 证实，Radix 降为 legacy 但双轨维护）。决策：**已用 Radix 版组件不迁移**（shadcn 承诺双轨维护，无迁移压力）；registry 新增拉取组件时**优先取 Base UI 版**。对上层令牌与玻璃类名零影响（shadcn 组件本就拷源码入仓）。

### 1.2 图标：设计稿保留 sprite，实现代码用 lucide-react（FE-ADR-FE2）

[lucide-react](https://lucide.dev) 1.48+，**ISC 许可**（商用无碍，LICENSE 披露），1500+ 图标，`strokeWidth` 为 prop（1.5px 与现有 SF Symbols 观感 sprite 一致），ESM tree-shakable。决策：**设计稿画板（components/ui-pages/interactions）的内联 sprite 不动**（评审基线不被破坏）；**前端实现代码统一 lucide-react**，M1 建立现有 53 sprite → lucide 名称映射表（挂账 22 篇），新图标一律 lucide。

### 1.3 依赖引入纪律（FE-ADR-FE3）

只允许**headless 或样式完全可接管**的库进入 package.json；带自有样式体系的组件库（AntD/MUI 全家桶类）一律不引入——与 shadcn 拷源码模式冲突。每个三方依赖在 §6 台账登记"替代退出方案"（被弃用时换成什么），防止锁死。

## 3. 分域论证（决策依据展开）

### 3.1 图形画布域

**为什么 React Flow 双画布通吃**（核实：12.12.0，MIT，月下载 ~4160 万，高频发版）：节点=任意 React 组件，我们的 8 色实底分类卡、SHACL 违例闪烁（CSS 动画）、深链脉冲（pulse-ring 类已有）、类树双向联动（受控 selectedIri state）都是它的原生扩展点；拖拽建类、连线弹谓词（IX-ON-02）、框选、snapToGrid 内建。**风险与对策**：DOM 渲染在 2000 节点级需 `onlyRenderVisibleElements` + 节点 memo + 边虚拟化；封装层 `GraphCanvas/OntoCanvas` 把这些调优固化，页面层无感（对应 03 篇 §5 已定封装契约）。G6 5（canvas，性能余量大）作**规模升级备选**——若实测 >2000 节点掉帧，仅图谱浏览页换 G6（OntoCanvas 编辑交互 G6 需自写插件，不换）；封装层接口不变即该换芯不换壳。

**布局**：elkjs（层次/有机/正交边/compound 子图，子图聚焦=IX-EX 需求）功能首选，许可 EPL-2.0（npm 依赖使用不传染，登记 LICENSE 披露即可；若法务要求 MIT-only 则 @dagrejs/dagre 替换，牺牲边路由与子图）。**决策：先 elkjs，许可异议时 dagre 降级路径已明。**

### 3.2 编辑器域

CodeMirror 6 一石三鸟（Turtle/SPARQL/JSON），合计 <250KB gzip 且三场景共享实例；legacy-modes 的 turtle/sparql 为 StreamLanguage 语法级高亮——对本项目"高亮+行号+只读态"够用，SHACL 结构校验是**后端职责**（宪法 2：确定性校验不走前端），前端「试校验」（IX-ON-08）调后端端点渲染结果，不引入前端 SHACL 引擎。Monaco（npm unpacked 100MB 级）体积排除。

### 3.3 表单与数据域

**JsonSchemaForm 拆成两个组件**（这是本篇最重要的细分决策，防止一刀切）：
- `DynamicSchemaForm`（适配器接入参数、工具注册参数——Schema 运行时才知道）：`@rjsf/core` + 官方 `@rjsf/shadcn` 主题（已核实随官方 monorepo 同步发版，非社区弃坑件）。适配度 80% 压线达标：功能 95% / 样式覆写成本是主要扣分项。**退出方案**：若主题覆写成本失控，降级为 RHF+zod+按 Schema 递归的 80 行自研渲染器（字段类型有限：string/number/boolean/enum/array）。
- `OntoMetaForm`（GB/T 48000.3 类 8 项/属性 10 项固定表单）：RHF+zod 手写——需要 IRI 格式校验、出处链接、修订历史迷你时间线等非 Schema 诉求，固定表单手写最干净（88%）。

**表格/虚拟/日期三件**无争议：TanStack v9（shadcn 官方 DataTable 同款）+ react-virtual + day-picker **锁 v9**（shadcn registry 未跟 v10，升级等 shadcn 官方迁移公告）。

### 3.4 AI 对话域（本轮最关键结论）

**AI Elements 采用、ai-sdk 不采用**。核实结论：AI Elements 1.9 经 shadcn registry 拷源码入仓、组件纯 props 驱动（官方 README 即有 useState 模拟流示例），**不绑定 ai-sdk 运行时**；组件与我们 26 篇对话交互态近乎 1:1（Tool 组件六态含 awaiting-approval=IX-G-04 回写确认、Reasoning=思考档位块、Inline Citation=引用角标、Sources=证据参考、Prompt Input+Attachments=输入栏五件套底座）。适配度 85%：扣分项=Tool 组件类型引用 `ai` 包（type-only 剥离或留作 devDep）+玻璃主题覆写。
**不采用 ai-sdk useChat**：我们的 SSE 是自研 AG-UI 16 事件协议（16 篇 §3 含 seq 对账/快照补齐），无官方 AG-UI×ai-sdk 桥（`@ag-ui/vercel-ai-sdk` 404 已核实）；写 ChatTransport 适配等于为白嫖 hooks 引入一层翻译——自建归约器（16 篇已定稿）直接产出 props 更短。assistant-ui（备选）runtime 抽象更重，不取。TanStack AI（0.x）观察不引入。

### 3.5 交互基件域

cmdk/vaul/sonner/input-otp/day-picker/react-dropzone 六件全部是 shadcn 官方底层同源件（95% 档），零犹豫采用。react-dropzone 不覆盖剪贴板粘贴——F-01 图片粘贴用原生 onPaste 自写补齐（~30 行）。树双件分治：**有拖拽用 react-arborist，纯勾选用 @headless-tree**（headless 与玻璃零冲突）。
