## 2. 阅读顺序

- **新人/接手模块的工程师**：01（锚点）→ 05（语义契约）→ 06（数据契约）→ 其余按所做模块选读；模块级开发再读对应 `docs/<模块>/` 分篇与 `services/<层>/README.md`（模块 spec）。
- **做语义/知识方向的**：01 → 05 → 06 §2.4~2.5 → 08 §4（审核门禁）。
- **做平台/基建方向的**：01 → 07 → 06 → 08。

## 3. 架构变更流程

1. 先改 [01 锚点](./01-总体架构与分层.md)（分层、路径、选型的任何变化必须先落在锚点）；
2. 评审通过后更新受影响分篇（02~08）与各模块 README spec；
3. 涉及目录改名/新增时，同步修订根 README 的项目结构；
4. 与锚点冲突的文档以锚点为准——发现冲突直接提锚点修订，不要在分篇里"就地绕过"。
