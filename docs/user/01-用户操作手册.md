## 1. 产品简介

ontology-agent 是一个以**本体（Ontology）为语义基座**的智能体平台：你把业务知识沉淀成「本体 + 知识库」，平台据此让 Agent 在对话中给出**有证据、可追溯**的回答，并把决策安全地回写到业务系统。平台铁律是**候选非成品**——AI 生成的一切候选内容都要经过人工终审才成为权威知识。

### 1.1 核心概念速查（非技术语言）

| 概念 | 通俗解释 |
| ---- | ---- |
| 本体 | 你的业务的「词汇表 + 规则书」：有哪些类东西（设备、故障）、它们之间什么关系、要守什么规则 |
| 知识库 | 你上传的文档经过抽取后形成的知识池；文档被切成小片并抽成「实体—关系」三元组 |
| 会话 | 你与 Agent 的一次对话；平台会记住会话上下文（记忆分层，见术语表） |
| 证据 | 回答旁的引用卡片：来自哪份文档、哪个知识点、置信度多少——回答不是凭空来的 |
| 候选与终审 | AI 抽取/生成的内容先是「候选」，经人在审核页拍板（通过/编辑/拒绝）后才进权威库 |
| 回写 | Agent 的决策变成业务系统的真实变更（如开一张工单）；带幂等保护与全程台账，可对账可追溯 |

常用能力一览：对话问答（P1）→ 知识入库（上传/抽取/终审 P3/P4）→ 检索验证（P5/P8）→ 本体治理（建模/评审 P6/P7）→ 记忆与扩展（P9/P10/P11）→ 系统管理（P12）。

## 2. 角色与权限速览

角色权威定义见 [frontend/02 §1.1](../frontend/02-信息架构与页面设计.md) 与 [08 篇 §2.2](../architecture/08-横切关注点与工程规范.md)（`ontologist`=知识工程师、`curator`=业务专家、`member`=开发者）：

| 角色 | 能做什么 |
| ---- | ---- |
| `super_admin` 平台超级管理员 | 跨租户运维：租户管理、全局模型网关 |
| `admin` 租户管理员 | 用户/角色、模型渠道与成本、审计、插件上架与安装、外部 MCP 管理 |
| `ontologist` 本体建模员（知识工程师） | 工作台编辑本体、提交变更单、知识库写入、规则侧审核 |
| `curator` 知识审核员（业务专家） | 抽取终审、记忆升级审核、变更业务评审、规则/行动类审核 |
| `member` 普通成员（开发者） | 对话、检索、图谱浏览、看任务；管自己的 Agent 与工具接入 |

> 另有 `guest`（访客）仅开放公开入口只读。菜单按角色过滤渲染；无权限的路由显示 403 页而不隐藏 URL。

### 2.1 治理三档对用户的意义

档位是**租户级配置**（仅管理员可改），决定审核要几个人点头（权威见 [08 篇 §2.4](../architecture/08-横切关注点与工程规范.md)）：

| 档位 | 审批链 | 对你的影响 |
| ---- | ---- | ---- |
| solo | 提交人即审批人 | 一人通过即生效（高置信候选可自动通过，但必留痕、可回滚）；适合个人/小团队 |
| team | 单审批人 | 需要另一个人审批；适合团队 |
| enterprise | 双负责人 + 四眼原则 | 知识工程师与业务专家都要签，决策人不得等于提交人；适合企业组织 |

三档共同底线：SHACL/一致性等**硬校验任何档位不可跳过**；自动通过必留痕、可回滚。**未完成置信度校准前，solo 档也不开自动通道**。

## 3. 快速上手

### 3.1 业务用户：5 分钟发起第一次对话

1. 登录后进入 `/chat`（默认首页），点右上「＋新对话」；
2. 在顶部选择 Agent（如 nanobot）；
3. 输入问题（例：「帮我梳理设备故障类目」）并发送；
4. 观察：回答流式逐字出现；中途折叠的「工具调用时间线」能看到 Agent 检索了什么；
5. **看证据**：回答下方的证据卡片（📎）标注了来源文档、三元组与置信度；点击证据实体可跳转图谱浏览器查看它在知识网络中的位置。

预期结果：回答流式出现、工具时间线可见、至少一张证据卡片可点击——三样都在说明链路健康。

### 3.2 知识工程师：30 分钟建一个小本体并抽取一页文档

1. `/ontology/workbench`：选择/新建本体，从左侧资源树拖拽建 3~5 个类，连线建关系（如 部件—partOf→设备）；
2. 右侧表单补名称、父类、属性、描述，点「应用修改」；
3. 保存草稿 → 底部校验面板跑 SHACL/推理，违例清零后「提交评审」；
4. solo 档自审通过即发布；team/enterprise 档等审批（`/ontology/versions` 看进度）；
5. `/kb/documents` 上传一页文档（Word/PDF）→ 触发抽取（可在 `/tasks` 看七步进度）；
6. `/kb/review` 终审抽取出的候选三元组（对照原文高亮，逐条或批量决策）；
7. `/kb/playground` 输入一个问题验证检索效果——知识已可用。

预期结果：本体已发布（版本 +1）、文档七步流水线全绿、候选终审完毕、Playground 能检索到刚入库的知识。

### 3.3 管理员：10 分钟配置模型与外部 MCP

1. `/system/models`：点「＋接入渠道」填提供商/模型/优先级/预算，保存后做连通性测试；成本看板可看趋势；
2. `/extensions/mcp`：点接入向导 → 填 Server URL 与鉴权 → 连接测试 → 自动发现工具清单 → 勾选纳管；
3. （可选）`/extensions/market` 安装所需插件（安装向导见 §4 P11）；
4. `/agents`：为 Agent 勾选可用工具（平台工具 + 刚接入的 MCP 工具）。

预期结果：模型渠道连通性测试通过、外部 MCP 工具出现在工具注册中心、Agent 工具勾选列表可选到它们。

## 4. 分页面操作指南

页面与线框权威见 [frontend/02 §3](../frontend/02-信息架构与页面设计.md)。以下 P1/P4/P6/P7/P11 为重点页（细），其余中等粒度。

页面总览（详细路由与权限见 frontend/02 §2 路由表）：

| 页面 | 路径 | 一句话用途 | 主要角色 |
| ---- | ---- | ---- | ---- |
| P1 对话工作台 | `/chat` | 与 Agent 对话、看证据 | 全部 |
| P2 任务中心 | `/tasks` | 异步任务进度与详情 | 全部 |
| P3 文档管理 | `/kb/documents` | 上传文档、看抽取进度 | member 上传 / curator 管理 |
| P4 抽取审核 | `/kb/review` | 候选实例人工终审 | curator、admin |
| P5 检索 Playground | `/kb/playground` | 三模式检索调试 | 全部 |
| P6 本体建模工作台 | `/ontology/workbench` | 可视化建模与校验 | ontologist、admin |
| P7 版本与评审 | `/ontology/versions` | diff 评审、发布、回滚 | ontologist 提交 / curator、admin 评审 |
| P8 图谱浏览器 | `/ontology/explorer` | 实体搜索与路径查询 | 全部 |
| P9 记忆管理 | `/memory` | 四层记忆治理 | member 查看 / curator 审核 |
| P10 Agent 管理 | `/agents` | Agent 注册与工具注入 | member（自己的）/ admin |
| P11 扩展中心 | `/extensions/*` | 工具/插件/外部 MCP | admin 为主 |
| P12 系统管理 | `/system/*` | 租户/用户/模型/审计 | admin、super_admin |

### P1 对话工作台 `/chat`

- **目的**：与 Agent 对话；流式渲染、工具调用可视化、证据引用。角色：全部。
- **界面分区**：左侧会话列表（260px，过滤搜索）｜右上 Agent 选择器与「＋新对话」｜中部消息流（工具调用时间线默认折叠）｜底部输入框（发送/停止）。
- **核心操作**：
  1. 发送问题 → 回答流式出现；工具调用时间线展示每步耗时（如 `kb.search 1.2s`）；
  2. 点击证据卡片 → 跳转 `/ontology/explorer?entity={id}` 定位实体；
  3. 点「⏹停止」中断生成；
  4. 从图谱浏览器「去对话」跳来时，输入框已预填实体上下文。
- **注意**：同一会话同时只能有一个运行中任务（否则提示 4102）；回答若标注「证据链暂缺」，说明检索降级（见 §6.2）。
- **常见问题**：发送后没反应？先看会话是否已关闭（4101）；换个简单问题排除模型渠道问题。

### P2 任务中心 `/tasks`

- **目的**：异步任务（抽取、批量导入、插件安装）的列表、进度与详情。角色：全部。
- **界面分区**：顶部过滤器（状态/类型/时间范围）+ 刷新｜任务表格（名称/类型/状态徽标/进度条/创建时间）｜任务详情抽屉（状态时间线 + 日志入口）。
- **操作**：按状态/类型/时间过滤 → 点行开抽屉 → 时间线实时推进（SSE）→ 失败任务「查看日志」→ 抽取类任务完成给「去审核」直达 P4。
- **注意**：任务超时有预算（预处理 10min/抽取 60min/对齐 20min/校验 10min），超时按失败处理并告警；卡住处理见 §6.3。
- **常见问题**：进度条不动不一定是卡死——批量抽取按文档大小可能长时间停在「抽取中」，以详情抽屉的时间线是否有新事件为准。

### P3 知识库-文档管理 `/kb/documents`

- **目的**：文档上传、抽取流水线状态、分片预览。角色：member 上传、curator 管理。
- **界面分区**：顶部搜索/类型/状态过滤器 + 「⬆上传文档」｜文档表格（名称/大小/状态/流水线步骤条/操作）｜预览抽屉（左分片列表、右分片原文与元数据）。
- **操作**：拖拽上传（multipart）→ 自动建抽取任务 → 列表看流水线进度（七步）→ 「预览」开抽屉看分片列表与原文/元数据 → 完成后行内「去审核」跳 P4。
- **注意**：文档原文存对象存储，预览读分片；「待抽取」状态需手动点「抽取」触发；删除文档会连带其分片与候选（进入审核的除外）。
- **常见问题**：上传失败提示 503？对象存储暂不可用，稍后重试（§6.2）。

### P4 知识库-抽取审核 `/kb/review`（重点页）

- **目的**：候选实例**人工终审**（候选非成品门禁）。角色：curator、admin。
- **界面分区**：顶部过滤器（文档/类型/置信度）+ 批量操作｜左侧候选列表（三元组 + 置信度）｜右侧原文对照面板（命中句高亮）+ 决策按钮。
- **核心操作**：
  1. 过滤候选（建议先按置信度降序，高置信批量过、低置信逐条看）；
  2. 选中候选 → 右侧高亮显示来源句，核对「三元组是否忠实于原文」；
  3. 决策四选一：**接受**（成为权威实例）/ **编辑后接受**（改谓词宾语再入审）/ **拒绝**（选原因，进负样本池反哺抽取）/ **跳过**；
  4. 批量：勾选多条 → 「✓批量通过」或「✕拒绝」；
  5. **快捷键**：`J` 通过 / `K` 拒绝 / `N` 跳过（按 frontend/02 设计稿；与输入框冲突的细节待实现定稿）。
- **注意**：SHACL 违例不清零也会进待审（附校验报告），由你裁决修复重跑或驳回——但「入库」的前置条件是终审通过；批量上限暂定 200 条/批。
- **常见问题**：为什么这条置信度很高但不符原文？置信度是模型自报的，终审就是防它的——拒绝即可，拒绝记录会用于校准。

### P5 检索 Playground `/kb/playground`

- **目的**：GraphRAG 检索调试，三模式对比。角色：全部。
- **界面分区**：顶部问题输入 + 模式切换（local/global/drift）+ 检索按钮｜左栏检索结果（答案摘要 + 引用角标，悬停预览）｜右栏图谱证据链画布（八色图例）。
- **操作**：输入问题 → 选模式（local=实体邻域 / global=社区摘要 / drift=混合）→ 检索 → 左侧结果与右侧证据链联动（hover 引用高亮对应节点）→ 点节点跳 P8。
- **注意**：这是调参与验证页，建议每次本体/检索参数变更后在此对比效果（正式回归见 08 篇 §7 评估体系）。
- **常见问题**：三模式答案差异大是正常的——它们检索的知识面不同（局部事实 vs 全局汇总 vs 混合）。

### P6 本体建模工作台 `/ontology/workbench`（★最核心页面）

- **目的**：类/属性/公理/规则的可视化建模与治理。角色：ontologist（admin 亦可）。
- **五区布局**：
  | 区 | 内容 |
  | ---- | ---- |
  | ① 顶部版本操作栏 | 本体与版本选择、草稿状态、保存草稿 / 提交评审→P7 / 对比 |
  | ② 左侧资源树（260px） | 类/属性/公理/规则四 Tab，搜索，可拖入画布 |
  | ③ 中央画布（OntoCanvas） | 拖拽新建、连线建关系、框选、缩放；节点四型（类/属性/规则/约束） |
  | ④ 右侧属性表单（320px） | 后端 JSON Schema 驱动：名称/父类/属性/描述；GB/T 48000.3 必填校验 |
  | ⑤ 底部校验面板（220px，可折叠） | SHACL 违例 / 推理结果 / 变更预览 三 Tab |
- **核心操作**：
  1. 选择本体与版本，载入 TBox 到画布；
  2. 画布编辑：从左树拖入或双击画布建类；连线建关系；右表单改元数据 → 「应用修改」；
  3. 「保存草稿」——以 changeset 增量保存，不直接动权威版本；
  4. 校验：底部面板列出 SHACL 违例（例：「故障.发生时间: 基数违规 minCount=1」），点「定位」画布闪烁对应节点 → 修改 → 复验；
  5. 违例清零后「提交评审」跳 P7。
- **注意**：硬校验（SHACL/一致性/不变式）是正确性底线，**任何治理档位都跳不过**（08 篇 §2.4）；草稿不会影响线上检索，发布后才会。
- **常见问题**：提交按钮不可用？多为存在未清零的阻断级违例，看校验面板第一项。

### P7 版本与评审 `/ontology/versions`（重点页）

- **目的**：changeset 列表、三元组级 diff、评审流（发布/驳回/回滚）。角色：ontologist 提交，curator/admin 评审。
- **界面分区**：顶部版本对（如 v3.1 已发布 ← v3.2 评审中）+ 回滚菜单｜中部 changeset 列表｜进入后 DiffViewer + 评审操作。
- **核心操作**：
  1. 列表点「评审」进入 changeset；
  2. Diff 视图逐条看三元组增删改（`+`绿 `−`红 `~`黄），可逐条接受/拒绝；
  3. 「✓通过并发布」：进入物化流程（物化进图库 → 全站生效），完成后图谱立即可见新语义；
  4. 「✕驳回」必附意见，回到提交人在 P6 修改；
  5. 回滚：选任意已发布版本 → RollbackDialog **二次确认 + 填审计理由**。
- **注意**：**通过 ≠ 生效**——只有发布（published）才生效；同一变更单同时只有一个在评审中的工单；enterprise 档需要知识工程师 + 业务专家双签。
- **常见问题**：发布要多久？评审通过后需物化进图库再全站生效，进度可在任务中心看；回滚会丢数据吗？回滚的是本体版本，实例数据按版本边界处理，且必须填审计理由备查。

### P8 图谱浏览器 `/ontology/explorer`

- **目的**：全局实体搜索、邻域展开、路径查询。角色：全部。
- **界面分区**：顶部全局实体搜索（`⌘K`）+ 两实体路径查询入口｜中部全屏图谱画布｜右侧实体详情抽屉（380px：属性表 + 来源文档 + 关联证据）。
- **操作**：`⌘K` 搜实体 → 画布看邻域 → 双击节点逐层展开（可按关系类型过滤）→ 「两实体路径查询」设起止与最大跳数 → 右侧抽屉看实体属性/来源文档/关联证据，「去对话」携上下文跳 P1。
- **常见问题**：搜索不到实体？确认它已通过终审入库（候选数据在发布前对检索不可见）；或换同义名称试术语对齐后的叫法。

### P9 记忆管理 `/memory`

- **目的**：四层记忆浏览与治理；L2→L3 升级审核。角色：member 查看，curator/admin 审核。
- **界面分区**：顶部四层 Tab（L1 工作记忆/L2 会话摘要/L3 组织图谱/L4 长期知识）｜左栏记忆条目列表（来源会话/摘要/状态）｜右栏时间线（该记忆的沉淀轨迹）。
- **操作**：切层 Tab → 过滤 → 候选记忆点「升级审核」对照原文决策（复用批量审核表交互）→ 通过写入 L3，时间线留痕。
- **注意**：记忆默认不自动升级到组织级；L1 为会话热数据只读展示。

### P10 Agent 管理 `/agents`

- **目的**：托管 Agent 注册、适配器配置、工具注入、运行历史。角色：member 管自己的，admin 全量。
- **界面分区**：主列表为 Agent 卡片墙（状态徽标：运行中/已停止/异常）｜详情页四 Tab：基本信息 / 工具配置 / 适配器 / 运行历史。
- **操作**：「＋注册 Agent」→ 选适配器类型与参数（表单由 Schema 驱动）→ 工具配置勾选（平台工具 + 已纳管 MCP 工具）→ 启动运行时插槽 → 运行历史回放（会话跳 P1 续聊、任务跳 P2）。
- **注意**：Agent 状态为「异常」先看适配器参数与凭据是否过期；工具清单只显示你有权限勾选的。

### P11 扩展中心 `/extensions/*`（重点页）

三个 Tab：**工具注册中心 / 插件市场 / 外部 MCP Server**。角色：admin 为主（市场全员可浏览）。

- **工具注册中心**：工具列表（内置/MCP/插件来源、scope、状态、启停）；详情抽屉看输入输出 Schema 与调用统计。纳管后的工具在 P10 可勾选注入 Agent。
- **插件市场**：
  1. 搜索/分类浏览插件卡片（图标/评分/权限 scope 数）；
  2. 详情页看 README、版本、**权限清单**；
  3. 点「安装」进入**三步向导**：①选择版本 → ②**scope 确认**（高危项红色标注，逐项确认是**强制步骤**，不确认不能下一步）→ ③安装（转为任务，进度在 P2）；
  4. 上架新插件走审核工作流（自动门禁 → 人工审核 → 签名）。
- **外部 MCP Server**：接入向导：填 URL + 鉴权 → 连接测试 → 自动发现工具清单 → 勾选纳管。
- **注意**：外部工具默认不可信——接入了也要经审核与授权才对 Agent 可见；插件出网受白名单与配额限制，超限会被终止并留痕。
- **常见问题**：连接测试失败？检查 URL/鉴权凭据与对方服务是否可达；工具列表是空的？对方 server 可能未暴露 tools 能力或被租户策略过滤；某插件装完不能用？在 P2 找到安装任务看失败原因（常见：版本不兼容、配额超限）。

### P12 系统管理 `/system/*`

- **目的**：租户/用户/角色、模型网关与成本、审计日志。角色：admin、super_admin。
- **界面分区**：Tab 切换——租户（super_admin）/ 用户 / 角色 / 模型网关 / 审计日志；用户表含账号/姓名/角色标签/状态/最后登录；成本看板为近 30 天趋势 + 模型占比环形图。
- **操作**：
  - 用户：「＋邀请成员」分配角色；角色矩阵（角色 × 权限点勾选）变更即时生效于菜单/路由；
  - 模型网关：渠道表增删 + 连通性测试；成本看板看近 30 天 Token/费用趋势与模型占比；
  - 审计：按操作者/动作/对象/时间过滤；点 trace_id 展开该请求全链路（关联工具调用与成本）；导出走任务中心，日志本身只读。
- **注意**：治理档位（solo/team/enterprise）是租户级配置、仅 admin 可改，变更本身进审计（08 篇 §2.4）；角色矩阵与代码种子数据同源，页面改的是租户内的映射。
- **常见问题**：成本看板数据滞后？成本按调用落库后聚合，存在分钟级延迟；审计能删吗？不能——审计只追加、无更新/删除接口，导出走任务中心。

## 5. 最佳实践

### 5.1 建本体的六步实战（简化版）

按 OB2 建模法（对象—行为—规则，事件串联逆向闭环）：

1. **定场景**：先写清这个本体服务哪个业务问题（锚点钦定首场景：电力配电网停电分析）；
2. **列对象**：把场景里的名词列成类（设备、部件、故障…），控制初版在 20~50 类；
3. **连关系**：类之间连线（isa / partOf / locatedIn…），右侧表单补属性与描述；
4. **立规则**：SHACL 约束（基数、值域）+ 守卫规则——确定性的规则**不要**指望 LLM 兜底；
5. **串闭环**：用事件类把「事件 → 规则 → 行动 → 回写」串起来（逆向闭环）；
6. **小步发布**：每个 changeset 小而聚焦，diff 好审；发布后用 P5 验证检索效果再继续。

两条经验：规则宁可先少后加（规则越多校验越严，误杀候选）；首版类目参考平台种子本体（电力停电分析场景，锚点 §7 钦定）再裁剪，不要从白纸开始。

### 5.2 术语唯一性怎么维护

- 抽取流水线自带**术语对齐**步骤（extracting→aligning），同义表述会归一到权威术语；
- 建模时坚持「一个概念一个类」：建新类前先搜索是否已有等价类；
- 属性命名同样唯一：同一含义不要既有 `name` 又有 `title`；
- 审核时发现同义重复候选，拒绝并选正确术语（拒绝进负样本，帮助后续对齐）。

### 5.3 什么时候用哪档治理

| 情况 | 建议 |
| ---- | ---- |
| 个人/小团队试用、内部演示 | solo：快速迭代，一人拍板（自动通道未开放前仍需手动过单） |
| 多人协作、有基本分工 | team：提交与审批分人，防手滑 |
| 生产环境、对外或合规场景 | enterprise：双负责人 + 四眼原则；高风险回写还有执行前二次确认 |

### 5.4 审核效率建议（给 curator/ontologist）

- 按置信度分桶处理：高置信桶用批量通过 + 抽查，低置信桶逐条对照原文；
- 拒绝务必选原因：拒绝记录进负样本池，直接反哺抽取质量与置信度校准；
- 大文档先在 P3 预览分片质量，源头脏（乱码/错切）就重新上传修复版，别硬审；
- 每批控制在批量上限（暂定 200 条/批）以内，小批多次优于大批一次。

## 6. 故障自助

### 6.1 常见错误码速查

| 错误码 | 含义 | 你可以做的 |
| ---- | ---- | ---- |
| 401 | 未登录 / 令牌过期 | 重新登录（access 2h 过期属正常，自动 refresh 失败才需手动） |
| 403 | 无权限 | 找租户管理员核对角色/scope；无权限页面本来就会显示 403 |
| 404 | 资源不存在 | 确认深链参数（实体/文档 id）是否已被删除 |
| 4101 SESSION_CLOSED | 会话已关闭 | 新建会话重发 |
| 4102 TASK_ALREADY_RUNNING | 同会话已有运行中任务 | 等当前任务完成，或点「⏹停止」后再发 |
| 429 | 触发限流 | 稍后重试；持续出现联系管理员调配额 |
| 5001 LLM_TIMEOUT | 模型调用超时（总预算约 60s） | 重发一次；频发则看系统状态页/联系管理员（模型渠道问题） |
| 5004 STORAGE_UNAVAILABLE | 存储暂不可用（PG / Redis / Neo4j / Milvus / MinIO 任一依赖不可用，与 02 篇错误码表一致） | 通常稍后自动恢复；写入类操作可重试，事务已回滚不会产生半个结果，重复副作用有幂等键保护 |
| 5xx（其他） | 服务端异常 | 稍后重试；持续出现携带 trace_id 报障（§6.4） |
| 503（文件操作） | 对象存储暂不可用 | 上传/附件稍后再试；对话主链路不受影响 |

> 2026-09-26 评审修复F：**用户可见错误码以 [api/01 §4 总表](../api/01-REST-API契约.md) 为权威**，本表仅为高频速查；名称与语义不一致时以 api/01 为准。

### 6.2 看到降级标注怎么办

| 你看到的 | 意思 | 怎么办 |
| ---- | ---- | ---- |
| 回答附「证据链暂缺」 | 检索降级（图库或向量库暂不可用），回答质量可能下降 | 重要结论等恢复后再验证一次 |
| 「模型切换提示」 | 主模型超时/限流，已自动切换备用模型 | 无需操作；对质量敏感就重发一次 |
| 会话「记性变短」 | 热记忆暂不可用，退化为直读最近消息 | 恢复后自动复原 |
| 某工具暂时不可用 | 外部服务熔断（约 30s 后半开探测恢复） | 换个问法或稍后重试 |

### 6.3 SSE 断线的表现与任务卡住

- **SSE 断线表现**：流式输出突然停住或页面提示重连。处置顺序：
  1. 先等几秒——前端会**自动重连**（目标 <5s），恢复后继续输出；
  2. 长时间未恢复再刷新页面：已完成的消息已落库不会丢，正在生成的那条可能需要重发；
  3. 刷新后仍连不上，属于平台侧网络/服务问题，报障处理（§6.4）。
- **任务卡住**：到 `/tasks` 打开任务详情看时间线停在哪一步、错误信息是什么；失败任务修复后会**从断点续跑**（已完成的步骤不重做）；抽取类任务完成后去 P4 审核。

### 6.4 报障时给管理员什么

| 信息 | 哪里找 |
| ---- | ---- |
| trace_id | 报错提示 / P12 审计日志里点开的请求全链路 |
| 时间与租户 | 浏览器地址 + 你的账号所属组织 |
| 复现步骤 | 从哪个页面、点了什么、输入了什么 |
| 截图 | 含错误码与页面 URL |

有了 trace_id，管理员可以按一次请求全链检索（关联工具调用与成本），定位效率最高。

## 7. 术语表

| 平台词汇 | 说明 |
| ---- | ---- |
| 本体 / Ontology | 业务概念的规范化定义与规则 |
| TBox / ABox | 本体本身的schema（类、关系、公理） / 按本体装进来的实例数据 |
| 三元组 | 知识的最小单位：（主语，谓语，宾语），如（故障，发生于，部件A） |
| SHACL | 本体约束校验语言，「硬校验」的执行者 |
| GraphRAG | 基于知识图谱的检索增强生成；local/global/drift 为三种检索模式 |
| 社区 | 图谱中聚类出的实体群（global 检索的摘要单元） |
| changeset / 变更单 | 本体的一次受控修改集，评审与回滚的单位 |
| 候选 / 终审 | AI 产物先为候选；人工拍板（通过/编辑/拒绝）后成权威数据 |
| 审核工单 | 终审流程的载体：pending → approved/rejected → applied（本体走 changeset 联动） |
| 负样本池 | 被拒绝的候选集合，用于反哺抽取质量与置信度校准 |
| 抽取流水线 | 文档入库七步：预处理→配置→抽取→术语对齐→校验→终审→归档 |
| 置信度 | 模型对抽取结果的自报把握程度；终审与抽样率的参考输入 |
| 物化 | 本体发布后同步进图库供全站检索的过程 |
| 治理档位 | solo / team / enterprise，审核要几个人点头 |
| Agent | 平台托管的智能体（对话、调工具、执行任务） |
| MCP | 平台与外部工具/系统的连接协议 |
| 插件 / 工具 | 市场安装的能力包 / 可被 Agent 调用的原子能力 |
| scope | 权限点（如 `kb:write`），声明式、默认拒绝 |
| 熔断 | 外部服务连续失败时暂时停用（约 30s 后自动探测恢复） |
| 记忆 L1~L4 | 工作记忆 / 会话摘要 / 组织图谱 / 长期知识 四层 |
| SSE | 服务端推送事件流——流式回答的传输方式 |
| 幂等键 / 受理凭证 | 回写防重复的唯一键 / 业务系统受理成功的凭据 |
| trace_id | 一次请求的全链路追踪号，报障时提供给管理员 |
| 评估基线 | 检索质量/任务成功率/抽取精确率的基准线，变更必须不退化 |
