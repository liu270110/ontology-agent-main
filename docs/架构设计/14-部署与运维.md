## 1. v1 单机 Compose 全量编排

### 1.1 网络划分与隔离理由

| 网络 | 成员 | 说明 |
| ---- | ---- | ---- |
| `frontend` | nginx（唯一对外 80/443） | 外部流量只能到此；backend / 存储不暴露宿主端口 |
| `backend` | nginx、backend、worker、worker-idle、relay、plugin-daemon、五存储 | 服务间与存储通信网 |
| `sandbox`（`internal: true`） | 插件容器、plugin-daemon（双臂）、egress-proxy（双臂） | 插件沙箱：**默认无出网**（05 篇 §6.3 network 默认全部拒绝），白名单经 egress-proxy（iptables/代理出口）放行 |

隔离理由：插件是平台唯一不可信代码入口（05 篇 §1 一条入口）。三层网保证三件事：外部只能打到 nginx；插件容器与 backend 网**没有路由**，数据访问只能经 plugin-daemon 暴露的内部 API / MCP（05 篇边界铁律 4：插件不得直连五存储）；出网默认全拒，白名单仅放行 `install_source`（PyPI 镜像）与各 harness 登记的必需端点（05 篇 §6.3 默认配置）。

### 1.2 docker-compose.yml 骨架

```yaml
services:
  nginx:
    image: nginx:1.27-alpine
    restart: unless-stopped
    ports: ["80:80", "443:443"]
    networks: [frontend, backend]
    volumes:
      - ./nginx/conf.d:/etc/nginx/conf.d:ro
      - ./certs:/etc/nginx/certs:ro
      - web_dist:/usr/share/nginx/html:ro        # 前端静态（CI 产物）
    depends_on: [backend]

  backend:                                        # FastAPI（01 篇 §1 装配入口）
    image: ontagent/backend:${TAG}
    restart: unless-stopped
    networks: [backend]
    env_file: .env
    secrets: [jwt_secret, neo4j_password, minio_secret_key]
    user: "1000:1000"
    read_only: true
    tmpfs: [/tmp]
    healthcheck:
      test: ["CMD", "curl", "-sf", "http://localhost:8000/healthz"]   # /readyz 查五存储依赖（01 篇 §4）
      interval: 15s
      timeout: 3s
      retries: 3
    depends_on:
      postgres: { condition: service_healthy }
      redis:    { condition: service_healthy }
      neo4j:    { condition: service_started }
      milvus:   { condition: service_started }
      minio:    { condition: service_started }
    deploy: { resources: { limits: { cpus: "2", memory: 2g } } }

  worker:                                         # ARQ 在线队列 worker（与 backend 同镜像）
    image: ontagent/backend:${TAG}
    command: arq app.foundation.queue.online_settings
    restart: unless-stopped
    networks: [backend]
    env_file: .env
    healthcheck: { test: ["CMD", "pgrep", "-f", "arq"], interval: 30s, timeout: 5s, retries: 3 }
    depends_on: [redis, postgres]
    deploy: { resources: { limits: { cpus: "2", memory: 2g } } }

  worker-idle:                                    # 空闲队列 worker（06 篇 §5.5.2 双队列）
    image: ontagent/backend:${TAG}
    command: arq app.foundation.queue.idle_settings
    restart: unless-stopped
    networks: [backend]
    env_file: .env
    depends_on: [redis, postgres]
    deploy: { resources: { limits: { cpus: "2", memory: 2g } } }

  relay:                                          # Outbox 中继（02 篇 §7 中继进程，单实例）
    image: ontagent/backend:${TAG}
    command: python -m app.foundation.events.relay
    restart: unless-stopped
    networks: [backend]
    env_file: .env
    depends_on: [postgres, redis]
    deploy: { resources: { limits: { cpus: "0.5", memory: 256m } } }

  plugin-daemon:                                  # 插件运行时守护（05 篇 §5.3 沙箱宿主，双臂）
    image: ontagent/plugin-daemon:${TAG}
    restart: unless-stopped
    networks: [backend, sandbox]
    env_file: .env
    read_only: true
    user: "1000:1000"
    healthcheck: { test: ["CMD", "curl", "-sf", "http://localhost:9100/healthz"], interval: 30s, timeout: 5s, retries: 3 }
    deploy: { resources: { limits: { cpus: "2", memory: 2g } } }

  egress-proxy:                                   # 沙箱出网白名单出口（iptables/Squid）
    image: ontagent/egress-proxy:${TAG}
    restart: unless-stopped
    networks: [sandbox]
    # 白名单源：05 篇 §6.3 install_source + 各 harness 登记端点；默认全拒

  redis:
    image: redis:7-alpine
    restart: unless-stopped
    networks: [backend]
    healthcheck: { test: ["CMD", "redis-cli", "ping"], interval: 10s, timeout: 3s, retries: 5 }
    volumes: [redis_data:/data]
    deploy: { resources: { limits: { cpus: "1", memory: 1g } } }

  postgres:
    image: postgres:16-alpine
    restart: unless-stopped
    networks: [backend]
    environment: { POSTGRES_PASSWORD_FILE: /run/secrets/pg_password }
    secrets: [pg_password]
    healthcheck: { test: ["CMD-SHELL", "pg_isready -U postgres"], interval: 10s, timeout: 3s, retries: 5 }
    volumes: [pg_data:/var/lib/postgresql/data]
    deploy: { resources: { limits: { cpus: "2", memory: 4g } } }

  neo4j:                                          # Neo4j 5 + n10s（00 篇 §6）
    image: neo4j:5-community
    restart: unless-stopped
    networks: [backend]
    environment:
      NEO4J_AUTH: none                            # 生产改密 + 内网隔离，见开放问题
      NEO4J_PLUGINS: '["n10s"]'
    healthcheck: { test: ["CMD-SHELL", "wget -qO- http://localhost:7474 || exit 1"], interval: 30s, timeout: 5s, retries: 5 }
    volumes: [neo4j_data:/data]
    deploy: { resources: { limits: { cpus: "2", memory: 4g } } }

  milvus:                                         # standalone：内嵌 etcd，对象存储复用本 minio
    image: milvusdb/milvus:v2.4-standalone
    restart: unless-stopped
    networks: [backend]
    environment: { ETCD_USE_EMBED: "true", COMMON_STORAGETYPE: remote }
    healthcheck: { test: ["CMD", "curl", "-sf", "http://localhost:9091/healthz"], interval: 30s, timeout: 5s, retries: 5 }
    volumes: [milvus_data:/var/lib/milvus]
    deploy: { resources: { limits: { cpus: "4", memory: 8g } } }

  minio:
    image: minio/minio:latest
    command: server /data --console-address ":9001"
    restart: unless-stopped
    networks: [backend]
    environment: { MINIO_ROOT_PASSWORD_FILE: /run/secrets/minio_secret_key }
    secrets: [minio_secret_key]
    healthcheck: { test: ["CMD", "mc", "ready", "local"], interval: 30s, timeout: 5s, retries: 5 }
    volumes: [minio_data:/data]
    deploy: { resources: { limits: { cpus: "1", memory: 1g } } }

volumes: { web_dist: {}, redis_data: {}, pg_data: {}, neo4j_data: {}, milvus_data: {}, minio_data: {} }

networks:
  frontend: {}
  backend: {}
  sandbox: { internal: true }                     # 无外网路由；白名单出口仅 egress-proxy

secrets:
  jwt_secret:        { file: ./secrets/jwt_secret }
  pg_password:       { file: ./secrets/pg_password }
  neo4j_password:    { file: ./secrets/neo4j_password }
  minio_secret_key:  { file: ./secrets/minio_secret_key }
```

## 2. nginx 配置要点

```nginx
server {
    listen 443 ssl http2;
    ssl_certificate     /etc/nginx/certs/fullchain.pem;   # TLS 终结（轮换见 §7）
    ssl_certificate_key /etc/nginx/certs/privkey.pem;

    # 前端静态托管（SPA 回退）
    root  /usr/share/nginx/html;
    location / { try_files $uri /index.html; }

    # REST 反代（01 篇 §3 /api/v1）
    location /api/ {
        proxy_pass http://backend:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }

    # SSE（AG-UI 事件流）——三行关键配置
    location /api/v1/sessions/ {
        proxy_pass http://backend:8000;
        proxy_buffering off;          # ① 关响应缓冲，事件即时下发
        proxy_cache off;              # ② 关缓存
        proxy_read_timeout 3600s;     # ③ 长连接读超时（长会话不断流）
        proxy_http_version 1.1;
        proxy_set_header Connection "";
    }

    # MCP Streamable HTTP（05 篇 §3.1 /mcp：POST/GET 双向、长请求）
    location /mcp {
        proxy_pass http://backend:8000;
        proxy_buffering off;
        proxy_read_timeout 300s;
        proxy_http_version 1.1;
    }
}
```

## 3. 环境变量与密钥注入

- **.env 约定**：Compose 自动加载同目录 `.env`；`.env.example` 模板入库（含全部 12 篇 §6.3 变量与注释），`.env` 本体不入版本库（.gitignore）。
- **secrets 注入**：优先 docker secrets（file 型，容器内 `/run/secrets/*`），配置侧用 `ONTO_AGENT_*_FILE` 让 pydantic-settings 读文件为 `SecretStr`（12 篇 §2.2：库内只存 credential_ref 引用）；不可用 docker secrets 的场景退化为 bind 挂载 `./secrets/` 目录（权限 0600，宿主侧不入库）。两类等价物：`jwt_secret / pg_password / neo4j_password / minio_secret_key`（§1.2）。
- **与 12 篇配置分层的关系**：`.env` 是 12 篇 §6.1 四层中的第 2 层（本地/单机缺省）；生产以容器环境变量（第 3 层）+ `settings.prod.toml` 覆盖（第 4 层）为准；**secrets 不进任何配置文件层**，只走文件注入。

## 4. 备份与恢复

策略引用 02 篇 §7：PG 每日全量 + WAL 归档；MinIO 版本化桶 + 异地同步；Neo4j 每日 dump；Milvus 可重建（源数据在 PG/MinIO）。本篇补 RPO/RTO 目标（**初值，随演练标定**）：

| 存储 | 策略（02 篇 §7） | RPO 目标 | RTO 目标 |
| ---- | ---- | ---- | ---- |
| PostgreSQL | 每日全量 + WAL 归档 | ≤ 5 分钟 | ≤ 1 小时 |
| Neo4j | 每日 dump | ≤ 24 小时 | ≤ 2 小时 |
| Milvus | 可重建（源在 PG/MinIO） | ≈ 0（重建即得） | ≤ 4 小时（全量重灌） |
| MinIO | 版本化桶 + 异地同步 | ≤ 24 小时 | ≤ 2 小时 |
| Redis | 不备份（L1 归档进 PG；队列/事件以 PG outbox 为准） | 数据可失 | ≤ 10 分钟（重启即恢复） |

**恢复演练要点**（季度一次，全程旁路实例、**不停系统**）：

1. 从最新全量 + WAL 起一份隔离 postgres 容器（不同端口、接入临时网络，不进 backend 网）；
2. 回放 WAL 至最新，核对 `candidates / audit_logs / outbox_events` 行数与抽样内容；
3. `mc mirror` 恢复 MinIO 到独立桶，抽验 `ontology-versions` Turtle 快照可被 rdflib 加载；
4. `neo4j-admin restore` 到临时容器，抽验 ABox 实例计数与 04 篇 Fact 时间线属性；
5. 从恢复后的 PG/MinIO 重建 Milvus 索引到临时集合（验证 04 篇 §10 场景 8"Derived 层重灌"）；
6. 对账脚本比对在线 vs 恢复实例的关键计数（允许 Outbox 投影滞后窗口内的差异）；
7. 演练报告（RTO 实测、问题清单）归档并更新本表目标值。

## 5. 监控告警基线

指标来源：backend / worker / relay 同镜像暴露 `/metrics`（12 篇 §5.3），Prometheus 抓取；主机资源以 node-exporter 采集。v1 是否随 Compose 部署 Prometheus/Grafana 见开放问题。告警规则表（阈值均为初值）：

| 规则 | 判定要点 | 阈值 | 级别 | 处置 |
| ---- | ---- | ---- | ---- | ---- |
| 服务存活 | `up{job=~"backend\|worker\|relay\|plugin-daemon"} == 0` | 持续 1 分钟 | P1 | 自动重启 + 值守介入 |
| 5xx 率 | 5xx / 总请求（RED，12 篇 §5.3） | > 2% 持续 5 分钟 | P1 | 回滚或降级 |
| SSE 断连率 | 断连数 / 活跃连接 | > 30% 持续 10 分钟 | P2 | 排查代理/网络（先查 §2 三行配置） |
| 队列积压 | 在线队列深度（ARQ） | > 100 持续 15 分钟 | P2 | 扩 worker 并发 |
| 审批超时 | pending 工单最老年龄 | > SLA（默认 24h） | P3 | 通知催办 |
| LLM 预算阈值 | 租户用量 / 预算（12 篇 §2.5 记账汇总） | ≥ 80% 预警；100% 触发预算策略 | P2 | 租户通知 + 12 篇 §2.3 降级 |
| 插件沙箱异常重启 | 插件容器重启计数增量 | 30 分钟内 > 3 次 | P1 | 安全事件流程（下架插件 + 审计） |
| 磁盘水位 | 系统盘 / 数据盘使用率 | > 80% | P2 | 扩容/清理 extract-artifacts（90 天滚动） |

## 6. 升级与回滚

- **镜像标签策略**：`ontagent/backend:vX.Y.Z+<git_sha>`，生产禁用 `latest`；compose 以固定 TAG 部署，回滚 = 换上一 tag 重新 `up -d`。单机无灰度，要求 **N-1 镜像兼容 N 数据库**（见 Alembic 原则）。
- **Alembic 迁移前滚原则**：生产禁止 downgrade；破坏性变更走 expand → migrate → contract 跨两个版本（先加列双写兼容，稳定后再收）；迁移脚本与代码同镜像同版本，启动时自动 `upgrade head`。
- **Turtle 版本回滚（ADR-5）**：本体回滚 = 激活历史 Turtle 快照（MinIO 快照永不删除，02 篇 §5 `ontology-versions` 永久桶）+ 注册状态置 `rolled_back`（02 篇 `ontology_versions.state`），不改对象存储本身。
- **插件独立升级通道（05 篇 §5.4/§6.4）**：外置插件版本独立演进、市场分发，`oa plugin install/uninstall` 独立于平台发版；插件下架/回退不影响 `core-*` 内置插件与平台本体。

## 7. 安全基线

- **容器非 root**：全部服务 `user: "1000:1000"`；插件沙箱额外加 `no-new-privileges` 与 cap 最小化；
- **只读根文件系统**：backend / plugin-daemon `read_only: true` + tmpfs 写 `/tmp`（§1.2）；数据一律落挂载卷；
- **定期审计导出**：`audit_logs`（01 篇 2.7）月度导出 JSON Lines + 哈希校验，异地归档留存（合规留存桶规划为 02 篇增量，见开放问题——02 篇 `exports` 桶 7 天生命周期不适合审计留存）；
- **TLS 证书轮换**：Let's Encrypt 经 certbot 容器每 60 天自动续期（或企业 CA 年度轮换），续期后 `nginx -s reload` 平滑生效；证书与私钥文件挂载只读（§1.2）。

## 8. k8s 迁移触发条件

继承 02 篇 §7"写明即拆"结论，出现任一即启动 k8s 迁移评估：

- PG 写入 QPS 持续 > 500 或表 > 500GB（读写分离先行）；Neo4j > 5 亿关系（评估 NebulaGraph/TuGraph）；Milvus 多租户隔离要求变高 → 独立集群；
- 模块 CPU 密集（推理/OCR）互相拖累 → 该模块拆独立服务（02 篇：事件总线已就绪，拆分成本低；k8s 承担独立部署与伸缩）；
- 可用性要求超出单机：需要多副本、滚动升级、自愈探针（本篇 healthcheck 即 k8s probe 的前形）；跨主机存储（单机卷不再满足容量/备份窗口）。

## 9. 模型推理服务部署（两阶段路线）

> 定位：模型网关（12 篇 §2）背后的推理渠道部署形态。铁律与 12 篇 §2.6 同款：**网关接口不动，渠道随资源演进**——阶段切换只改 `model_channels` 配置，上层业务代码零改动。不做长期双轨并行，任一时刻只有一条现役渠道。

### 9.1 阶段一（当前：单机开发/试用，无独立 GPU 服务器）

- 运行时：**Ollama**（Windows 原生，免 WSL2），渠道 provider `ollama/<model>`。
- 模型清单（现役渠道）：

| 用途 | 模型 | 形态 | 显存 |
| ---- | ---- | ---- | ---- |
| 主对话 / Agent 工具循环 | Qwen3-8B | GGUF Q4_K_M | ~5 GB |
| Embedding（02 篇 §4 统一） | bge-m3 | Ollama 官方 | ~1.2 GB |
| NER 抽取 | GLiNER（tools/jev-local） | CPU 模式 | 0（让显存给 LLM） |

- 配置基线：上下文 ≥ 16K（默认 4K 对 Agent 多轮工具循环不够）、flash attention 开启、`OLLAMA_NUM_PARALLEL=1` 省显存。
- 显存预算（8 GB）：上表合计 ~6.2 GB，与桌面占用相抵即打满；**训练与推理互斥**——QLoRA 训练期间停 Ollama 释放显存。
- 结构化输出（抽取出合法 JSON）：走 OpenAI 兼容 `response_format: json_schema`（LiteLLM 统一透传），**禁止**业务代码使用 Ollama 私有 `format` 参数（§9.3 约束 1）。

### 9.2 阶段二（正式环境：Linux GPU 服务器）

- 运行时：**vLLM**（官方 Docker 镜像，OpenAI 兼容 server），渠道 provider 指向 vLLM endpoint（LiteLLM `hosted_vllm/` 前缀）。
- **切换触发条件**（满足任一即启动切换，写明即升级）：
  1. 获得独立 GPU 服务器（≥ 24 GB 显存，4090/A10 级）；
  2. 并发会话 > 5，或 Agent 长上下文吞吐 / prefix 复用明显不足；
  3. 微调模型进入高频迭代，需要 LoRA 热挂载（免 merge 免转格式）。
- vLLM 兑现的能力：PagedAttention + 连续批处理（并发吞吐）、prefix cache（Agent 多轮循环省重复 KV）、guided json（抽取结构化保障）、`--enable-lora` 适配器动态加载（§9.4 阶段二闭环）。
- 编排形态：**不并入 §1 Compose**（GPU 宿主单独跑），网络可达 backend 网即可；§8 k8s 迁移触发条件中"推理模块拆独立服务"即指本节，届时 vLLM 为独立 Deployment + GPU 节点池。

### 9.3 跨阶段统一约束（保证切换零代码）

1. **接口子集**：业务代码只经 ModelGateway 统一接口（chat / embed / tools / `response_format`）+ OpenAI 兼容标准字段，任何下游运行时私有参数（Ollama `format`、vLLM `extra_body`）只允许出现在 `foundation/llm` 适配层（12 篇 §2），违者评审打回；
2. **训练产物权威形态**：LLaMA-Factory QLoRA → merge 后 **BF16 safetensors 为唯一权威产物**（归档 MinIO，桶规划为 02 篇增量，见 §10）；GGUF（阶段一）与 AWQ（阶段二）都是部署衍生品，随用随转、不入权威库；
3. **切换校准**：渠道切换前后以同一评测集双跑，核心指标（抽取 F1 / 工具调用成功率）劣化 > 2% 阻断切换、回退旧渠道；
4. **模型选型约束**：现役模型必须同时存在官方权重与 GGUF 两种发行形态（Qwen3 系满足），保证两阶段可用同一模型。

### 9.4 微调链路（两阶段共用框架：LLaMA-Factory）

- 资源边界：本机 8 GB 只做 4B 级 QLoRA（短上下文、小 batch）；7B+ 租卡（AutoDL 4090 级，按小时计费）训练，产物拉回归档（§9.3 约束 2）。
- 阶段一闭环：merge → 导出 GGUF（LLaMA-Factory 一步支持）→ Modelfile import 进 Ollama；偶发操作，单轮约十几分钟，可接受。
- 阶段二闭环：LoRA 适配器 `--enable-lora` 直接挂载 vLLM（API 动态加载切换，训完即测）；或 merge → AWQ 量化后作为新基座上线。
