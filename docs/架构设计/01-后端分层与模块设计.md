### 1.1 各层禁令

| 层 | 允许 | 禁止 |
| ---- | ---- | ---- |
| gateway | 调 application；DTO 校验 | 写业务规则；直接调 data/semantic |
| application | 编排 domain + semantic + data(UoW)；发事件 | HTTP 细节；绕过领域模型直改数据库 |
| domain | 纯 Python + pydantic | import 任何 SDK/框架（SQLAlchemy、fastapi、redis…） |
| semantic | RDF/推理引擎/Milvus/Neo4j（经 data 适配或自带只读客户端） | 依赖 domain 的业务对象（输出候选/报告，由上层落库） |
| data | 各存储 SDK、仓储实现 | 业务判断 |
| foundation | 横切设施 | 依赖以上任何业务层 |

## 2. 模块设计

通用结构：每个模块 = 领域模型 + 仓储接口 + 应用服务 + 路由。以下只写关键差异点。

### 2.1 Agent 服务

- **领域模型**：`Session`（会话，含上下文窗口引用）、`Task`（状态机：`pending → running → waiting_approval → succeeded/failed/cancelled`）、`AgentSlot`（托管插槽：平台原生 / pi RPC / nanobot API / Claude Agent SDK / openclaw gateway，统一 `run(task) -> EventStream` 协议）。
- **平台原生运行时**：agent loop = 意图理解 → 上下文组装（记忆召回 + GraphRAG + TBox 摘要）→ 推理分级路由 → LLM / 规则 → 工具调用循环 → 事件流出。工具经工具集服务取 schema（按需下发，防上下文爆炸）。
- **事件流**：AG-UI 蓝本 16 事件（`RUN_STARTED / TEXT_MESSAGE_* / TOOL_CALL_* / STATE_DELTA / RUN_FINISHED`…），经网关 SSE 下发。
- **外部托管**：每个外部 agent 工具按 01 篇调研结论适配（pi 走 RPC/JSON 流、nanobot 走 OpenAI 兼容 API、openclaw/hermes 容器化整网关）；统一收事件到平台事件流，统一经工具集注入平台能力。
- **上下文压缩**：会话超窗走 compaction（参考 pi 的 JSONL 树 + compaction 设计），L1 工作记忆保持全量在窗。

### 2.2 本体核心（语义层主体，平台灵魂）

- **建模对象**（GB/T 48000.3 元数据规范 → 语义层 `modeling` 的 Python 模型，双向映射 RDF）：
  - 实体类型 8 项元数据：IRI / Name / Label / Definition / 属性集 / SubclassOf / HasSubclass / EquivalentClass；
  - 属性 10 项元数据（含 Domain / Range / TypeOfTerms）；
  - OB2 三要素映射：对象 → `owl:Class`；行为 → 行动类（`describesAction` 体系，带前置条件/状态流转属性）；规则 → 独立公理/约束资源（SHACL shape 或 SPARQL CONSTRUCT 模板），**与对象解耦、独立版本化**。
- **存储**（ADR-5）：TBox = 版本化 Turtle 文件存 MinIO，rdflib 内存图服务读写，PG 存项目/版本注册元数据；ABox 实例存 Neo4j（n10s 导入 TBox 提供类型信息）；一致性校验/推理在语义层完成，**物化结果回写属性图**。
- **推理分级路由器**（设计宪法第 2 条的代码落点）：
  | 请求类型 | 路由 | 实现 |
  | ---- | ---- | ---- |
  | SHACL 校验 | validation | pySHACL，毫秒级 |
  | 一致性/分类（TBox） | reasoning | owlready2 + HermiT，低频批量 |
  | 隐含关系推导 | rules | SPARQL CONSTRUCT 物化 |
  | 复杂语义判断 | LLM（经 foundation/llm） | 输出必须过 SHACL/规则校验后才采纳 |
- **版本与治理**：每次变更生成新版本（Turtle 快照 + diff），`ChangeRequest` 走审批中心；回滚 = 激活历史版本快照；术语唯一性在 terminology 模块做入库门禁。

### 2.3 知识库 graphrag-ontology

- **七步流水线**（ARQ 异步任务链，kb_pipeline 编排）：`文档预处理 → 环境配置 → 批量抽取 → 术语对齐 → 一致性校验 → 约束校验 → 人工归档`。
- **预处理矩阵**：Word/文本→Markdown 分片；可复制 PDF→纯文本；扫描件→OCR（pymupdf/Tesseract）；流程图→多模态 LLM；表格→标准化 + 跨表人工。
- **分类型抽取**：extraction 模块维护四类提示词模板（文本知识/数据/时序流程/多模态），输出固定结构 + 原文出处指针（doc_id + chunk_id + span）。
- **候选非成品**：抽取产物一律落 `Candidate`（候选实例），进审批中心；终审通过才写 Neo4j ABox + Milvus 索引（四大国标底线的代码落点）。
- **GraphRAG**：索引构建（实体/关系抽取 → Leiden 社区 → 多粒度社区摘要）；检索路由 local/global/DRIFT；本体增强 = 抽取时 schema 约束 + 检索时本体查询扩展 + 回答附图谱证据路径。

### 2.4 记忆服务

四层模型直接落研究 04 篇：

| 层 | 存储 | 写入门禁 |
| ---- | ---- | ---- |
| L1 会话（工作记忆） | Redis + PG 会话日志 | 实时写，会话结束归档 |
| L2 用户（情景+个人语义） | PG + Milvus（mem0 式两阶段） | 会话结束后台自动抽取，静默写 |
| L3 组织（共享情景） | Neo4j 时序图（Graphiti 式 invalidation 边） | **审批中心审核后升级** |
| L4 本体/知识 | 本体核心 + GraphRAG（即 2.2/2.3） | 知识工程门禁（候选非成品） |

沉淀三步 = mem0 抽取/更新（ADD/UPDATE/DELETE 决策）+ 分级门禁；检索 = 四层并行召回按权重合并注入。遗忘 = TTL / 时间衰减 / invalidation 边 / 版本化，全程不物理删除。

### 2.5 MCP 网关（网关层 `mcp_endpoint` + 应用层 `action_service`）

- **出口**：平台 MCP Server（FastMCP，Streamable HTTP，`/mcp`），暴露 `knowledge.search / ontology.reason / ontology.validate / ontology.query / memory.read / memory.write / action.invoke` + resources（TBox 摘要、术语表）+ prompts（领域任务模板）。每个工具带本体语义标注（对应对象/规则/权限）。
- **接入**：MCP Host 管理（外部 server 注册、`tools/list` 拉取、默认不可信需审核、失败熔断）。
- **业务集成**：OpenAPI 导入自动生成工具描述 + 人工语义标注；行动结果强制回流（action_service 负责写回本体实例 + 记忆 + 审计）。
- **安全红线**：鉴权 OAuth2/API Key 按租户隔离；授权只认平台 scope + ACL，**MCP annotations 仅作 UI 提示**；高风险动作强制审批中心二次确认。

### 2.6 插件服务 + 技能服务 + 工具集服务

- **插件**：MCP 为主轨（`server.json` 扩展：分类/版本/权限 scope/签名/协议版本区间），REST OpenAPI 为辅轨（自动转工具）；审核上架流水线 = 清单校验 → 自动门禁（schema/静态扫描/投毒检测/依赖审计）→ 人工审核（敏感类目）→ 签名上架 → 运行期监测。运行时隔离：独立守护进程/容器 + 出网白名单。
- **技能（Skills）**：SKILL.md 为格式标准（对齐 agentskills.io，与 pi/hermes/claude 兼容），元数据 + 版本 + 检索；本质是**程序记忆的版本库**，与记忆服务打通（04 篇），分发渠道与插件市场共用。
- **工具集**：统一注册中心（MCP tools / 本地 tools / 业务 API 工具同一张注册表），Tool Search 按需下发 schema；观测（调用统计/成功率/延迟/成本）反哺市场排序。

### 2.7 IAM / 审批中心 / 审计 / 通知

- **IAM**：`Tenant → User → Role → Permission`；Permission = `资源:动作`（如 `ontology:write`、`memory:L3:read`）；工具级 + 数据级（行级）授权在授权判定策略集中实现，供网关与 MCP 出口共用；API Key 供 MCP 外部调用。
- **审批中心**：一个状态机复用五类对象（本体变更 / 候选记忆升级 / 插件上架 / 高风险动作 / 知识冲突裁决工单——第五类由 04 篇冲突分诊引入）：`submitted → reviewing → approved/rejected → applied/rolled_back`；通知服务产生待办，前端统一"审批中心"页面处理。
- **审计**：中间件 + 领域事件双来源，写 PG（audit_logs），敏感操作含前后快照。
- **通知**：v1 站内信（PG + Redis 推送），v2 接企业微信/钉钉/飞书。

## 3. API 规范

> 本表是 REST 基础规范；REST / MCP / CLI 三出口的完整协议规范、插件内外置边界见 [05-对外服务协议与插件边界](./05-对外服务协议与插件边界.md)。

| 规范项 | 定稿 |
| ---- | ---- |
| 版本 | `/api/v1/...`，URL 版本化 |

| 统一响应 | `{ "code": 0, "message": "ok", "data": ... }`；错误码分段（1xxx 网关 / 2xxx 认证 / 3xxx 业务 / 4xxx 语义 / 5xxx 存储） |
| 分页 | cursor 分页（`?cursor=&limit=`），管理后台表格可用 offset |
| 流式 | `GET /api/v1/sessions/{id}/events`（SSE，AG-UI 事件）；POST 动作走普通 REST |
| 文件 | 上传直传 MinIO 预签名 URL，后端只登记元数据 |
| 文档 | FastAPI 自动 OpenAPI；前端用 openapi-typescript 生成类型化 client |
| MCP | `/mcp` Streamable HTTP，`Mcp-Session-Id` 会话，兼容 2025-06-18 / 2025-11-25 协商 |

## 4. 错误处理与可观测

- 异常分层：领域异常（业务语义）→ 应用层转译 → 网关统一错误码 + RFC7807 风格详情；语义层校验失败返回结构化 SHACL 报告（不吞成 500）。
- 追踪：OpenTelemetry 全链路（网关 → 应用 → 语义 → 存储 → LLM），trace_id 贯穿审计与日志；LLM 调用单独记账（token/成本/渠道）。
- 健康：`/healthz`（存活）+ `/readyz`（依赖检查：PG/Neo4j/Milvus/MinIO/Redis/LLM 连通）。
