## 1. 仓库布局与分支模型

```
ontology-agent/                 # monorepo（前后端同仓，跨栈契约变更一次提交）
├── backend/                    # 01 篇 §1 六层（本篇 §2 细化到文件级）
├── frontend/                   # 16 篇工程结构
├── tools/oa/                   # oa CLI（05 篇 §4，独立发 PyPI）
├── deploy/                     # 14 篇 compose/nginx/prometheus
├── docs/                       # 本目录（架构设计/研究整理/研究资料）
└── .workflow/ .zcode/          # Gitee Go 流水线（.workflow/）、仓库级 AI 协作配置
```

- **分支**：`develop` 集成分支（现用）；sprint 分支 `sprint/mX-wY`；功能分支 `feat/<模块>-<内容>`、`fix/...`；里程碑末合 `master` 打 tag。
- **Commit**：Conventional Commits（`feat/fix/docs/refactor/test/chore`，中文描述）——与仓库现有风格一致。
- **PR**：一个 PR 对应一个纵向切片或一个模块内任务；模板含 DoD 清单（00 篇 §7.1）勾选。

## 2. backend/ 文件级骨架（01 篇 §1 的落地细化）

```
backend/app/
├── main.py                     # 装配：中间件链→路由→/mcp 挂载→生命周期
├── gateway/
│   ├── routes/                 # 每模块一个 router 文件（chat.py ontologies.py … 与 13 篇端点一一对应）
│   ├── middleware/{auth,tenant,ratelimit,audit,exception,request_id}.py
│   ├── sse/{encoder,registry}.py       # AG-UI 16 事件编码 + 会话事件流注册
│   ├── mcp_endpoint.py         # 09 篇 §2：FastMCP 挂载/会话/协商
│   ├── schemas/                # Pydantic DTO，与领域模型隔离（路由↔应用层的转换在此）
│   └── deps.py                 # get_current_user/get_tenant/get_uow
├── application/
│   ├── chat_orchestrator.py kb_pipeline.py memory_pipeline.py
│   ├── approval_service.py action_service.py events.py
│   └── agent_service/{runtime.py,slots/{pi,nanobot,openclaw,claude_sdk}.py,context_builder.py,compaction.py}
├── domain/
│   ├── shared/                 # IRI/Version/Provenance 值对象 + DomainEvent 基类
│   └── <模块>/                 # 每模块固定三件：models.py / repository.py(接口) / events.py
│                               # ontology/ 另有 rules.py terms.py；plugin/ 另有 manifest.py signing.py
├── semantic/
│   ├── tbox/{store.py,cache.py} modeling/{ob2.py,gb48000.py,rdf_map.py}
│   ├── validation/service.py reasoning/{router.py,hermit.py}
│   ├── rules/{engine.py,templates.py,scheduler.py}
│   ├── terminology/{gate.py,aligner.py} graphrag/{index.py,retriever.py}
│   └── extraction/{textual.py,data.py,temporal.py,multimodal.py}   # 提示词消费方（18 篇）
├── data/
│   ├── orm/ repositories/ graph/ vector/ objectstore/ cache/ uow.py
└── foundation/                 # 12 篇：config/ llm/ events/ queue/ logging/ telemetry/ security/
```

- **模块三件套纪律**：`domain/<模块>/repository.py` 只放接口（Protocol）；实现一律在 `data/repositories/`。跨模块只允许 import 对方的 `models.py` 与 `repository.py` 接口，禁止深入实现。
- **M1 骨架范围**：gateway（auth/tenant/request_id/exception 四中间件）+ domain/shared + domain/iam + data（orm/repositories/cache）+ foundation（config/security/logging）+ 对应 routes——其余模块建空包 + `README` 占位，占位包不参与 import-linter 豁免。

## 3. 命名与代码风格

| 项 | 规范 |
| ---- | ---- |
| Python | 3.11+（对齐另一文档待办的 3.9→3.11 结论）、ruff（lint+format 一体）、mypy（domain/semantic `strict`，gateway/data `basic`） |
| 命名 | 模块/包 snake_case 单数（`ontology` 非 `ontologies`）；路由前缀用复数（`/api/v1/ontologies`，13 篇）；DTO 后缀 `DTO`（`OntologyCreateDTO`）；领域事件后缀 `Event` |
| 表命名 | 对齐 02 篇：snake_case 复数（`ontology_versions`），IRI 字段名 `iri`，外键 `<实体>_id` |
| JSON | 字段 camelCase（对外契约，13 篇）；Python 内 snake_case，DTO 层 `alias_generator` 转换 |
| 时间 | 一律 UTC + ISO8601；bi-temporal 字段名对齐 04 篇（`t_valid/t_txn`） |
| 异常 | 领域异常 `XxxError(ErrorCode)`，错误码常量集中在 `foundation/errors.py`（13 篇码表唯一来源） |

## 4. 分层依赖的 CI 强制配置（00 篇 §7.1 的落地）

**import-linter**（`pyproject.toml`）contracts：

```ini
[importlinter]
root_package = app

[importlinter:contract:layers]
name = 六层分层
type = layers
layers =
    app.gateway
    app.application
    app.domain | app.semantic
    app.data
    app.foundation

[importlinter:contract:domain-pure]
name = domain 零框架依赖
type = forbidden
source_modules = app.domain
forbidden_modules = fastapi sqlalchemy redis pydantic_settings litellm

[importlinter:contract:module-boundaries]
name = domain 跨模块边界
type = independence
modules =
    app.domain.agent
    app.domain.ontology
    app.domain.kb
    app.domain.memory
    app.domain.plugin
    app.domain.tool
    app.domain.iam
    app.domain.audit
    app.domain.marketplace
    app.domain.skill
```

> 注：`domain | semantic` 同层但互不依赖（semantic 输出候选/报告，上层落库——01 篇 §1.1）；independence contract 允许各自依赖 `app.domain.shared`。

**tests/architecture/**（pytest 常驻，与 import-linter 双保险）：

| 用例 | 断言 |
| ---- | ---- |
| `test_layers.py` | 六层 import 方向（AST 扫描） |
| `test_domain_purity.py` | domain 包 import 集合 ⊆ {stdlib, app.domain, app.shared 值对象} |
| `test_module_boundaries.py` | domain 子包互不 import（shared 除外） |
| `test_route_coverage.py` | 13 篇端点表 ↔ 路由注册 diff（防契约漂移） |
| `test_tool_whitelist.py` | MCP 网关白名单 ≡ 05 篇铁律 3 清单（防管理面误挂） |

**CI 流水线（Gitee Go）阶段**：`lint(ruff+mypy) → arch(import-linter+tests/architecture) → unit(domain/semantic/application) → integration(testcontainers, 合并触发) → build(镜像+前端 tsc) → contract(schemathesis：合并跑增量、nightly 跑全量，17 篇同口径)`。arch 阶段红 = 一票否决。

## 5. 数据迁移规范（Alembic）

- 迁移文件名 `<yyyy-mm-dd>_<sprint>_<序号>_<内容>`；一个 PR 一组迁移，禁改已合入迁移。
- 只前滚为默认策略；回滚迁移文件必须写（14 篇演练用）但不在流水线自动执行。
- 种子数据（默认角色、错误码表、内置 core-* 插件注册）走 `alembic seed` 命令，不混结构迁移。

## 6. 本地开发约定

- `docker compose --profile dev up`（14 篇编排裁剪：只起五存储 + redis，backend 本地跑）；
- `.env.example` 全量维护（与 12 篇 35 项配置表 diff 进 CI）；密钥不入库（`.gitignore` 内置）；
- `make` 目标：`make dev / lint / arch / unit / mig / seed / cli-install`；前端与 backend 契约再生成：`make api-types`（16 篇 §2）。

## 7. DoD 检查单（PR 模板内置）

1. 功能验收（对应篇的验收场景片段）2. 测试绿（新增代码覆盖达 17 篇阈值）3. import-linter + arch 测试绿 4. 审计/权限落点确认（新增端点已在 13 篇表登记 + 权限标注）5. 迁移与配置项同步（.env.example）6. 涉及决策变更已记 ADR。
