## 1. 测试策略总览

金字塔自下而上，越往上越慢越少；静态检查与架构测试是"第 0 层"门禁，不计入用例占比：

| 层 | 范围 | 主要载体 | 占比（用例数指导值） |
| ---- | ---- | ---- | ---- |
| 静态检查 | ruff + mypy（domain/semantic strict）、`.env.example` diff、前端 tsc/eslint | PR 门禁 | 门禁（不计） |
| 架构测试 | import-linter + `tests/architecture/`（§3） | PR 门禁 | 门禁（不计） |
| 单元测试 | domain 纯单测 + application 用例测试 + semantic 属性测试 + foundation | pytest，全速秒级 | ~60% |
| 集成测试 | data 层 testcontainers（五存储真实镜像）+ Outbox/事件链路 | 合并门禁 | ~15% |
| 契约测试 | REST schemathesis、MCP inspector 两版协商、三出口一致性（05 篇 §7） | 合并门禁 | ~10% |
| E2E | §4 场景库（浏览器 / `oa` CLI / MCP client 三视角） | nightly | ~10% |
| 性能/安全 | §6 预算基线回归、依赖扫描、ASVS 抽查 | nightly | ~5% |

CI 阶段划分（流水线落 **Gitee Go**；阶段顺序承接 15 篇 §4，触发时机以本表为准）：

| 阶段 | 触发 | 内容 | 红线 |
| ---- | ---- | ---- | ---- |
| PR 必过 | pull_request | lint（ruff+mypy）→ arch（import-linter + tests/architecture）→ unit → 增量覆盖率（变更行达 §6 阈值） | 任一红即拒 |
| 合并 | merge to develop | integration（testcontainers 五存储）+ contract（schemathesis / MCP inspector / 三出口一致性） | 任一红即拒合并 |
| build | 合并后 | backend 镜像 + 前端构建产物（15 篇 §4） | 红即回退合并 |
| nightly | 每夜定时 | E2E 全量 + 性能基线回归 + 安全扫描 | 红 = P2 工单，里程碑评审前必须清零 |

测试目录约定：`backend/tests/{unit, architecture, integration, contract, e2e}` + `tests/fixtures/`（§5）；前端测试目录见 16 篇 §1/§8。

## 2. 分层测试规范（对齐 01 篇 §1.1 各层禁令）

| 层 | 测试形态 | 依赖策略 | 断言要点 |
| ---- | ---- | ---- | ---- |
| domain | 纯单测 | **零框架依赖、零 mock**（无 IO 可替）；mypy strict | 状态机全迁移路径（08 篇 Task、11 篇审批）、值对象不变式、领域事件载荷 |
| application | 用例测试 | 仓储用 **fake/内存实现**；模型网关 fake（断言 tenant/purpose 记账归因）；事件走内存 Outbox | 用例编排顺序、事务边界（UoW）、事件发布信封、审批状态机流转 |
| gateway | 中间件单测 + 契约测试 | FastAPI TestClient + **OpenAPI→schemathesis** | PDP 五步拒绝路径与 2xxx 错误码（11 篇 §5）；DTO 与领域模型隔离；SSE 编码器 16 事件帧格式 |
| semantic | **属性测试** | rdflib / pySHACL 真实引擎，不 mock | Turtle→模型→Turtle **round-trip 逐 triple 等值**（07 篇 §3 门禁）；SHACL 报告结构 violations[]（focusNode/path/message/severity/sourceShape，07 篇 §7）；推理分级白名单路由（07 篇 §5）；LLM 分支输出未过校验必拒收（宪法第 2/3 条） |
| data | **testcontainers** | PG 16 / Neo4j 5+n10s / Milvus standalone / MinIO / Redis 7 真实镜像（版本对齐 14 篇 compose） | 仓储实现 ↔ 领域接口行为一致；Outbox 同事务提交（01 篇 uow.py）；Alembic 从零 `upgrade head`（§7） |
| foundation | 单测 + 最小集成 | fake 时钟；Redis 用 testcontainers | 配置 fail-fast（12 篇 §6.1）；事件信封 schema 与 event_id 幂等去重（12 篇 §3）；渠道降级/熔断参数（12 篇 §2.3） |

> LLM 真实调用不进 PR/合并流水线：application/semantic 一律 fake 网关；真实模型仅 nightly E2E 冒烟使用（费用归属见 §8）。集成测试环境用 15 篇 §6 dev profile 裁剪编排。

## 3. 架构测试细则

import-linter contracts（`pyproject.toml`，前三条承接 15 篇 §4 原文）：

| contract | 类型 | 断言 | 依据 |
| ---- | ---- | ---- | ---- |
| layers | layers | gateway → application → (domain \| semantic) → data → foundation，只许上层依赖下层 | 00 篇 §2 依赖铁律 |
| domain-pure | forbidden | app.domain 禁 import fastapi / sqlalchemy / redis / pydantic_settings / litellm——**禁止 domain import ORM** 落在此条 | 01 篇 §1.1 |
| module-boundaries | independence | domain 十个子包互不 import（shared 除外）——**模块边界禁跨 import** | 00 篇 §7.1 |
| semantic-no-domain（本篇新增） | forbidden | app.semantic 禁 import app.domain（semantic 只输出候选/报告，由上层落库） | 01 篇 §1.1 |
| foundation 底层位 | （由 layers 覆盖） | foundation 不依赖任何业务层；六件套内部依赖关系（仅 config/logging 可被依赖）由 AST 用例补查 | 12 篇 §1 |

`tests/architecture/` 常驻用例清单（与 import-linter 双保险，15 篇 §4）：

| 用例 | 断言 |
| ---- | ---- |
| test_layers.py | 六层 import 方向（AST 扫描） |
| test_domain_purity.py | domain 包 import 集合 ⊆ {stdlib, app.domain, shared 值对象} |
| test_module_boundaries.py | domain 子包互不 import（shared 除外） |
| test_route_coverage.py | 13 篇端点表 ↔ 路由注册 diff（防契约漂移） |
| test_tool_whitelist.py | MCP 网关白名单 ≡ 05 篇铁律 3 清单（防管理面误挂） |

arch 阶段红 = CI 红 = 不许合并（00 篇 §7.1 交付纪律）。

## 6. 质量门禁与指标

覆盖率门禁（15 篇 §7 DoD 所引"17 篇阈值"即本表）：

| 范围 | 阈值 | 说明 |
| ---- | ---- | ---- |
| domain | ≥90% | 零 mock 纯单测，分支覆盖 |
| backend 整体 | ≥80% | PR 阶段查增量（变更行），nightly 查全量 |
| gateway/schemas（DTO） | 豁免 | 生成物与协议胶水；错误码映射由契约测试覆盖 |
| 投毒检测召回率 | 双轨（规则库 + LLM 审查）在 ≥20 例样例库上回归；目标值待标定（§8） | 10 篇 §12 验收项 |

性能预算基线表（数值全部引用各篇既定值，不新造）：

| 指标 | 预算 | 来源 |
| ---- | ---- | ---- |
| SHACL 校验 P95 | < 50ms（1 万 triple 图） | 07 篇 §11 |
| HermiT 一致性 | 1 千类 TBox < 60s；单次推理超时 30s 中止并告警 | 07 篇 §5/§11 |
| REST P95 | 采集口径已定（RED 三项），预算值待压测标定 | 12 篇 §5.3 |
| SSE 断连率 | 告警线 >30% 持续 10 分钟；预算值待标定 | 14 篇 §5 |
| LLM 首 token 延迟 | 可测（llm_calls.latency_ms）；预算值未定 | 12 篇 §2.5 |
| CLI-harness 单命令 | 超时 120s / 并发 4 / 输出 >64KB 截断 | 05 篇 §6.3、10 篇 §10 |
| 模型渠道熔断 | 连续失败 ≥5 次冷却 60s（初值） | 12 篇 §2.3 |

里程碑评审按 00 篇 §7 验收标准 + 本篇 §4 场景全绿 + §6 门禁达标三件套裁决；DoD 单见 15 篇 §7。

| 注入与投毒 | prompt injection / 工具描述投毒 / 记忆投毒三类用例执行（消费 §5 投毒样例库） | 11 篇 §8、06 篇 §6 |

混沌演练表：

| 演练 | 注入方式 | 断言 | 依据 |
| ---- | ---- | ---- | ---- |
| MCP 熔断 | kill 外部 MCP server | 工具自动不可见（检索不到而非调用报错）→ 半开探测恢复回切 | 09 篇 §5/§9 |

| 向量索引损坏 | 清空 Milvus 集合 | Derived 层重灌，Raw/Compiled 零损失 | 04 篇 §10 场景 8 |
| 沙箱逃逸 | 白名单外出网 / 文件越界 / 资源超限 | 全拒；超限被杀且不影响邻插件 | 10 篇 §12 |
| 备份恢复 | 季度一次，旁路实例不停系统 | RPO/RTO 实测达标并回写 14 篇 §4 目标值 | 14 篇 §4 |

迁移测试（Alembic）：

- 每次 PR：testcontainers PG 从零 `upgrade head` + 种子数据（15 篇 §5），迁移与代码同镜像验证；
- 里程碑末：回滚迁移文件逐级 downgrade **演练**（文件必须写但不自动执行，14 篇 §6 演练用）；
- 破坏性变更：expand → migrate → contract 跨两个版本验证，N-1 镜像兼容 N 数据库（14 篇 §6）。
