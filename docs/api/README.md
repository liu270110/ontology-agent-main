## 2. 权威关系

- 本目录是**汇编与对外发布层**，不是决策层：REST / SSE 的细节权威 = [architecture/02-网关层设计](../architecture/02-网关层设计.md)；MCP 工具与回写权威 = [docs/MCP/MCP网关设计](../MCP/MCP网关设计.md)、[docs/MCP/业务回写设计](../MCP/业务回写设计.md)；JWT / scope 权威 = [architecture/08-横切关注点 §2](../architecture/08-横切关注点与工程规范.md)；
- 与上游冲突时以 02 篇 / MCP 篇为准，并在各篇「待办与开放问题」登记；
- 各篇标注「本篇补充，待回填上游」的端点 / 事件 / 工具，定稿前须回填上游文档消除双源；
- OpenAPI schema（FastAPI 自动生成，`/docs`）是机器事实，本目录是人读评审契约，二者不一致走各篇「变更管理」流程。

## 3. 变更管理规则

1. 契约变更**先改本目录对应文档**并评审，再同步 FastAPI / FastMCP 实现；
2. OpenAPI schema 快照变更必须在 PR 中显式确认（08 篇 §8.2 契约测试纪律）；
3. 语义化演进：向后兼容新增在当前版本内迭代（状态号 +0.1）；破坏性变更升版本（如 `/api/v2`）并公告弃用周期。
