# 02 - 数据与存储设计

> 状态：v1.0 待评审 | 日期：2026-09-26
>
> 定稿五套存储的分工矩阵、数据模型与一致性策略。原则：**每种存储只干它最擅长的事**，跨存储一致性靠 Outbox + 版本化，不追求分布式事务。

---

## 1. 存储分工矩阵

| 存储 | 承载数据 | 禁止放 |
| ---- | ---- | ---- |
| **PostgreSQL** | 一切"业务事实"：租户/用户/权限、会话与消息日志、文档元数据与审核工单、本体项目/版本注册、插件/工具/技能注册、审批流、审计日志、L2 记忆记录、Outbox | 大文本切片向量、图关系、文件本体 |
| **Neo4j** | ABox 实例图谱、GraphRAG 图结构（实体/关系/社区/Chunk 节点）、L3 组织时序记忆（episodic/semantic/community 三层子图 + invalidation 边） | TBox 公理（属性图表达力不足，ADR-5） |
| **Milvus** | 向量：文档切片、实体/关系描述、社区报告、L2 记忆、术语/技能描述的语义索引（dense + BM25 混合） | 元数据主数据（向量库只存 id + 最小标量） |
| **MinIO** | 原始文档、抽取中间产物、**本体版本 Turtle 快照**、插件包、导出文件、附件 | 需要事务/查询的元数据 |
| **Redis** | L1 会话工作记忆、热缓存、限流计数、ARQ 队列、事件总线（Streams）、SSE 在线状态 | 任何需要持久审计的数据（L1 归档进 PG） |

## 2. PostgreSQL 模型（核心表清单）

命名：蛇形复数；所有业务表带 `id (uuid) / tenant_id / created_at / updated_at`。

| 域 | 表 | 关键列与说明 |
| ---- | ---- | ---- |
| IAM | `tenants` | name, plan, status |
| | `users` | tenant_id, email, password_hash, display_name, status |
| | `roles` / `user_roles` | roles.permission_set (jsonb)；绑定表多对多 |
| | `api_keys` | tenant_id, key_hash, scopes (jsonb), expires_at——MCP 出口鉴权 |
| Agent | `sessions` | user_id, agent_slot, title, context_ref（L1 Redis 键）, status |
| | `messages` | session_id, role, content, tool_calls (jsonb), evidence_refs (jsonb), token_usage |
| | `tasks` | session_id, type, state, error, trace_id |
| 知识库 | `documents` | kb_id, name, mime, minio_key, status, meta |
| | `doc_chunks` | document_id, seq, content, span, hash |
| | `extraction_jobs` | document_id, pipeline_stage（七步）, state, stats |
| | `candidates` | job_id, type（实体/关系/属性/公理）, payload (jsonb), source_ref（doc+chunk+span 出处指针）, review_state |
| 本体 | `ontology_projects` | name, namespace（IRI 前缀）, tier（词汇表/轻量图谱/重型本体三档） |
| | `ontology_versions` | project_id, version, minio_key（Turtle 快照）, diff_summary, state（draft/published/rolled_back） |
| | `ontology_change_requests` | project_id, base_version, payload, approval_id |
| 记忆 | `memory_records` | layer(1-4), subject_type/subject_id, content, confidence, decay_at, source_ref, state（active/invalidated） |
| | `memory_promotions` | from_layer, to_layer, payload, approval_id |
| 插件/工具/技能 | `plugins` / `plugin_versions` | slug, server_json (jsonb), signature, state |
| | `tools` | kind（mcp/local/biz_api）, provider_id, name, input_schema (jsonb), semantic_ref（本体行动类 IRI）, scopes |
| | `skills` / `skill_versions` | slug, frontmatter (jsonb), body_md, minio_key |
| MCP | `mcp_servers` | direction（outbound/inbound）, transport, endpoint, credentials_ref, state（默认 untrusted） |
| | `mcp_tool_cache` | server_id, tools (jsonb), fetched_at |
| 治理 | `approvals` | target_type/target_id, submitter, state, decision, decided_by——四类审批统一 |
| | `audit_logs` | actor, action, resource, before/after (jsonb), trace_id |
| | `notifications` | user_id, type, payload, read_at |
| | `outbox_events` | event_type, payload, state（pending/sent）——与业务同事务写入 |
| 模型网关 | `model_providers` / `model_channels` | provider, base_url, credential_ref, budget, priority, enabled |

索引要点：`candidates(review_state)`（审核队列）、`memory_records(layer, subject_id, decay_at)`、`outbox_events(state)`（轮询）、`tools(kind, provider_id)`；全文检索中文用 `pg_trgm` + jieba 分词外置（v1 Milvus BM25 承担语义侧，PG 全文不做复杂中文分词投入）。

## 3. Neo4j 图模型

```
(:Entity {iri, type, label, source_ref, tenant_id, version})
(:Relation {iri, type, source_ref})       # 关系建模为边，类型来自本体对象属性
(:Community {level, summary, embedding_ref})
(:Chunk {doc_id, chunk_id})-[:MENTIONS]->(:Entity)
(:Episode {content, valid_from, valid_to})-[:ABOUT]->(:Entity)   # L3 组织记忆（Graphiti 式）
失效事实：新增 (:Fact)-[:INVALIDATED_BY]->(:Fact) 边，不物理删除
```

- ABox 实例的类型来自 TBox（n10s 导入本体提供 `__ Entity__` 类型约束提示）；写入门禁：候选终审通过 + SHACL 校验通过才写图。
- GraphRAG 索引管线：实体/关系抽取 → Leiden 社区检测 → 每层社区生成摘要（存 `Community.summary` + 向量进 Milvus）。
- 租户隔离：v1 用 `tenant_id` 属性 + 查询强制过滤；多数据库实例（per-tenant）v2 再启用。

## 4. Milvus 集合

| 集合 | 向量 | 标量字段 | 检索方式 |
| ---- | ---- | ---- | ---- |
| `kb_chunks` | chunk embedding | doc_id, chunk_id, tenant_id, kb_id | 混合（dense + BM25），按租户分区 |
| `kb_communities` | community report embedding | community_id, level, kb_id | global search 用 |
| `kb_entities` | 实体描述 embedding | entity_iri, kb_id | local search 扩展用 |
| `memory_records` | 记忆 embedding | record_id, layer, subject_id, tenant_id | L2/L3 召回 |
| `skill_catalog` | 技能描述 embedding | skill_id, version | 技能推荐/检索 |

统一 embedding 模型经模型网关配置（默认 bge-m3 类中文友好模型，dense+sparse 双输出）；集合创建脚本随迁移管理。

## 5. MinIO 桶规划

| 桶 | 内容 | 生命周期 |
| ---- | ---- | ---- |
| `raw-documents` | 上传原始文件 | 永久（审计需要） |
| `extract-artifacts` | 预处理产物、抽取中间 JSON | 90 天滚动 |
| `ontology-versions` | `{project}/{version}.ttl` Turtle 快照 | 永久（版本/回滚基线） |
| `plugin-artifacts` | 插件包、签名 | 永久 |
| `exports` | 导出文件（Turtle/JSON-LD/报告） | 7 天 |

## 6. Redis 键空间

| 模式 | 用途 |
| ---- | ---- |
| `l1:session:{id}` (hash) | 工作记忆块（Letta 式自编辑记忆块），TTL = 会话活跃期 |
| `rl:{tenant}:{route}` | 限流计数（滑动窗口） |
| `stream:events` (Redis Streams) | 领域事件总线；消费组按模块划分 |
| `arq:queue` | ARQ 任务队列 |
| `cache:tool_schema:{tool_id}` | 工具 schema 缓存 |

## 7. 一致性、容量与演进

- **跨存储一致性**：主事实在 PG；Neo4j/Milvus/MinIO 为投影。写路径 = PG 事务内写业务表 + outbox_events 同事务提交 → 中继进程消费 Outbox 投影到图/向量库（幂等，按 event_id 去重）。投影滞后是可接受的最终一致（检索端按租户+时间过滤）。
- **失败补偿**：投影失败进重试队列，超限进死信 + 通知；绝不因投影失败回滚主事实。
- **容量基线（v1）**：PG 50GB / Neo4j 5000 万节点 / Milvus 1000 万向量 / MinIO 500GB——单机 Compose 完全覆盖。
- **扩容触发条件（写明即拆）**：PG 写入 QPS 持续 > 500 或表 > 500GB → 读写分离；Neo4j > 5 亿关系 → 评估 NebulaGraph/TuGraph（03 篇选型预留）；Milvus 多租户隔离要求变高 → 独立集群；模块 CPU 密集（推理/OCR）互相拖累 → 该模块拆独立服务（事件总线已就绪，拆分成本低）。
- **备份**：PG 每日全量 + WAL 归档；MinIO 版本化桶 + 异地同步；Neo4j 每日 dump；Milvus 可重建（源数据在 PG/MinIO，向量重建成本低）。
