## 2. P14 Agent Bot 群聊 `/chat/group/:sessionId`

**目的**：一个会话内用户与多个 Agent 插槽实例协作（如"停电分析群"：调度 Agent + 设备 Agent + 报告 Agent）。角色：全部（建群需所选 Agent 均已授权，受 25 篇 F-10 资源 ACL 约束）。

```text
┌──────────┬────────────────────────────────────────────────────┐
│ 群会话列表 │ ⚡停电分析群 [5人] [_routing:协调者▾] [＋成员] [分享]  │
│ (260px)  ├───────────────────────────────────────────────────┤
│ 🔍 过滤   │  ┌ ChatStream 消息流（归属着色）────────────────┐   │
│          │  │ 🧑 用户：梳理 110kV 变站故障风险               │   │
│          │  │ 🟣调度Agent：从电网侧看…  [⚙kb.search 1.2s]    │   │
│          │  │ 🟢设备Agent：@调度Agent 补充台账缺陷记录…        │   │
│          │  │ 🟠报告Agent：汇总如上，生成报告草稿 [Artifact]   │   │
│          │  │ ⚠ [ActionConfirmCard 高风险动作确认]           │   │
│          │  └─────────────────────────────────────────────┘   │
│          │ [＋附件][🌐][🧠档位][输入框… / @ #][模型▾][发送][⏹]  │
│          ├───────────────────────────────────────────────────┤
│          │ 成员面板(右栏240px)：🟣调度Agent[运行中][暂停]        │
│          │ 🟢设备Agent[空闲] 🟠报告Agent[空闲] [routing说明]     │
└──────────┴────────────────────────────────────────────────────┘
```

- **组件**：复用 ★ChatStream/输入栏五件套/MessageActions/AttachmentChip/EvidenceCard/ActionConfirmCard；新增 AgentAvatar（图谱五分类色板着色）、MemberPanel、MemberPickerDialog、RoutingModePicker、ResponseGroup（见 [24 篇 §3.10](./24-前端组件库扩充与外部样式借鉴.md)）；MentionMenu 扩展 `@` 提及对象=群内成员 Agent。
- **发言编排四模式**（RoutingModePicker，随会话记忆；**宪法 2 的直接落法**）：
  1. `@点名`（mention）：确定性——@谁谁答，可多个，未点名不消耗预算；
  2. `轮询`（round_robin）：确定性——按成员序依次应答；
  3. `多答对比`（all）：并行全答，ResponseGroup 并列渲染 + 用户选优/评分；答案差异进入证据对照；
  4. `协调者`（orchestrator）：**唯一 LLM 路由模式**——协调者成员做低频语义判断决定应答者，路由决定写审计（who/why），UI 在消息流中以系统行显示"协调者 → 设备Agent（原因摘要）"。
- **消息归属**：每条 Agent 消息带头像+名称+模型徽标+分类色左缘；ToolCallCard/EvidenceCard 归属到具体成员；SSE MESSAGE_* 事件补 `agent_id`（挂账 api/02，X15）。
- **上下文与预算**：群聊共享会话 ContextMeter；`@点名`模式下未点名成员不注入该轮上下文（裁剪由后端执行，UI 提示"本轮 1/3 成员参与"）；多答对比模式预算消耗提示（发送前二次确认，>3 成员时）。
- **权限与治理**：建群/拉人需对目标 Agent 有 `use` 级 ACL；成员角色=协调者/发言者/观察者；群会话资源级 ACL 复用 F-10；enterprise 档跨租户 Agent 入群走审批。
- **记忆与审计**：群聊 L2 候选沉淀标注参与者（`participants[]`）；个性化 L1 不从群聊写入（防串味）；每条消息带 `agent_id` + `trace_id` 全程可追溯（宪法 5）。

## 3. P15 Agent 工作流编排 `/workflows`、`/workflows/:id`

**目的**：把 Agent 插槽、工具、知识检索、审批编排为可版本化、可试运行的有向图。角色：admin、ontologist（运行：全部，受工作流 ACL 约束）。

```text
┌─ /workflows 列表：WorkflowCard 网格（名称/版本状态/最近运行成功率/ACL 徽标）+ [＋新建/从模板] ─┐
├─ /workflows/:id 编辑器 ────────────────────────────────────────────────────────────┤
│ [版本操作栏: 草稿v3 ▾ | 保存 | 试运行 | 提交发布 | 对比 v2]（复用版本操作栏模式）          │
├──────────┬──────────────────────────────────────────┬───────────────┤
│ 节点库    │  React Flow 画布（24 篇 §4.11 规范）        │ 检查器         │
│ (240px)  │  [开始]→[Agent:调度]→◇条件?─是→[并行]       │ JsonSchemaForm │
│ 开始/结束 │      ↓否        [Agent:设备][Agent:报告]   │ 节点参数/输入   │
│ Agent    │  [汇聚]→[人工审批]→[结束]                   │ 输出映射/重试   │
│ 工具      │  minimap / controls / 断点chip             │ 确定性表达式编辑│
│ 知识检索  │  ── 底部抽屉：试运行面板 ──                 │ （禁裸 LLM 分支）│
│ 条件/并行 │  节点状态时间线 | 断点 | 查看轨迹(→画框21)    │               │
│ 审批/模板 │                                            │               │
└──────────┴──────────────────────────────────────────┴───────────────┘
```

- **节点类型 v1（八类，最小够用）**：开始/结束、Agent（绑插槽实例，继承群聊成员参数）、工具（注册表选取，scope 徽标）、知识检索（GraphRAG 三模式）、条件路由（**确定性表达式编辑器**，对齐宪法 2——LLM 语义分支不设节点，需要语义路由时用 Agent 节点输出+表达式判断）、并行汇聚、人工审批（生成审批中心工单，等待回执）、模板转换（变量映射）。循环子图 v2 另议（循环上限沿用既有 5 轮裁决）。
- **版本与发布（候选非成品宪法落法）**：草稿可随意改 → 试运行 → 提交发布生成**不可变版本**；solo 档直接发布，team/enterprise 档发布走审批（审批对象类型 `workflow_publish`，**第七类对象候选，挂账 11 篇裁决**，X16）；版本历史+回滚=以旧版本新建草稿（复用画框 25 交互模式）。
- **试运行与断点**：试运行产生真实 Run（走任务中心，type=`workflow_test`）；底部抽屉显示节点状态时间线；节点可设断点，命中即暂停——从断点查看/修参/继续（LangGraph Studio 式 time travel，复用画框 21 TrajectoryView 分叉恢复机制）；每次节点执行展开即轨迹事件流。
- **运行历史**：`/workflows/:id` 运行 Tab → 任务中心过滤 type=`workflow_run`；成功率/耗时进卡片统计。
- **权限**：工作流级 ACL（读/运行/编辑/发布四档，AclEditorDialog 复用）；运行时每个 Agent 节点仍受原 Agent ACL 约束（编排不提权）。

## 7. 宪法对齐自检

1. **推理分级**：群聊四模式中三种确定性路由；协调者是唯一 LLM 判定且写审计；工作流条件节点限定确定性表达式——LLM 不做隐藏分支判断；
2. **候选非成品**：工作流发布=版本+审批（治理三档调节）；群聊不产生入库产物（Artifact 走既有产物流）；
3. **可追溯**：消息/节点执行均带 agent_id+trace_id；路由决定与断点恢复写审计；
4. **最小够用**：节点 v1 收缩八类、群聊不做 bot 商店、不做通用自动化集成；
5. **OB2**：群=对象，发言/编排=行为，路由规则与循环上限=规则，会话/运行事件=事件闭环。

## 8. 范围收窄（对 25 篇 §9 的修订，用户裁决）

原"不做 n8n 式全画布工作流编排"条目**解除并改写**为：**不做通用自动化集成**——编排对象限本平台 Agent 插槽/工具/知识检索/审批四类；不做第三方 SaaS 触发器（邮件/网盘/定时爬取）、不做循环子图（v2 另议，上限沿用 5 轮裁决）、不做前端托管图运行时。25 篇 §9 已同步。
