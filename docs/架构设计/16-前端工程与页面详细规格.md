## 2. 数据层规范（TanStack Query + Zustand + 类型化 client）

### 2.1 query key 与失效策略

规范：三元组 `[模块, 资源, 参数?]`；模块/资源取 `lib/qk.ts` 导出的字符串常量（禁止散写），参数对象键序稳定，cursor 分页参数并入参数。示例：`['auth','me']`、`['ontology','list',{q,cursor}]`、`['session','messages',sessionId]`。

| mutation（13 篇端点） | 成功后失效 |
| ---- | ---- |
| POST /auth/login、/auth/refresh | 置灰并重取 `['auth','me']` |
| POST /ontologies | `['ontology','list']` |
| POST /ontologies/{id}/versions、/publish、/rollback | `['ontology','detail',id]`、`['ontology','versions',id]` |
| POST /kb/{id}/documents、/documents/{id}/extract | `['kb','documents',kbId]`、`['kb','job',jobId]` |
| POST /candidates/{id}/review | `['kb','candidates',kbId]` |
| POST /sessions/{id}/messages | 不失效消息列表（SSE 增量负责），仅乐观插入本地占位 |
| DELETE /sessions/{id} | `['session','list']` |
| POST /approvals/{id}/approve・reject・rollback | `['approval','list']`、`['approval','detail',id]` |
| POST /plugins/{id}/install・enable・disable、PATCH /plugins/{id}/config | `['plugin','list']`、`['plugin','detail',id]` |
| PUT /users/{id}/roles | `['iam','users',id]`；若为本人再失效 `['auth','me']` |

### 2.2 Zustand store 划分（全局仅三个）

| store | 字段 | 说明 |
| ---- | ---- | ---- |
| auth-store | `status('anonymous'\|'authenticated')`、`accessToken`（仅内存）、`user{id,username,tenantId}`、`roles[]`、`permissions:Set<string>`；动作 `applyMe / login / logout / can(p)` | access token 15 min 只驻内存不持久化；会话恢复靠 httpOnly refresh cookie 静默刷新（11 篇 §4）；`can()` 供守卫与按钮级 `<Guard>` |
| session-store | `activeSessionId`、`messages[]`、`thinking{[messageId]}`、`toolCalls{[callId]}`、`runs{[taskId]:{status,usage,error}}`、`contextState`、`approvalPends[]`、`lastSeq`、`sessionMeta{title,pinned,tags[],ephemeral,effort,mountedKbIds[]}`（2026-09-26 对标补齐，[25 篇](./25-前端页面功能缺口对标与任务清单.md) F-01~F-08）、`connection('connecting'\|'open'\|'reconnecting'\|'offline')` | SSE 归约唯一目标（§3.3）；敏感且体积大，不持久化 |
| ui-store | `theme('light'\|'dark'\|'system')`、`sidebarCollapsed`、`commandOpen`、`globalBanner` | theme 走 class 策略并持久化（03 篇 §2.5）；编辑器草稿等域内态放 `features/<域>/stores/`（03 篇 §6） |

### 2.3 openapi-typescript 类型化 client

| 环节 | 定稿 |
| ---- | ---- |
| 生成 | `make api-types`（15 篇 §6，内部即 `npm run gen:api`）：从 `GET /api/v1/meta/openapi`（13 篇）拉 OpenAPI 3.1 → `openapi-typescript` 输出 `src/api/generated/schema.d.ts`，禁止手改 |
| 封装 | `api/client.ts`：注入 `Authorization: Bearer`；统一解 `{code,message,data}` 信封；非 0 抛 `ApiError(code, detail)`；429 读 `Retry-After`（05 篇 §2） |
| 再生成 | 后端契约变更必须同 PR 内再生成并提交；前端禁止手写请求/响应类型（03 篇 §1） |
| CI 漂移校验 | CI 起后端 → 重新生成 → `git diff --exit-code src/api/generated`，有 diff 即红（对齐 00 篇 §7.1 CI 纪律） |

## 3. SSE 客户端（src/sse/）

### 3.1 连接与重连

| 项 | 定稿 |
| ---- | ---- |
| 传输实现 | EventSource 语义封装，以 fetch + ReadableStream 手工解析 `event:`/`data:`/`id:` 帧——原生 EventSource 无法携带 `Authorization` 头，而 13 篇要求订阅已认证；端点 `GET /api/v1/sessions/{id}/events` |
| 帧约定 | `id:` 取信封 `seq` 并记为 lastEventId；`data:` 为 `{taskId, seq, ts, payload}`（08 篇 §5） |
| 过期处理 | 收 401/2002 → 静默 `POST /api/v1/auth/refresh` 后重连一次；再失败 → `connection='offline'`，转登录 |
| 重连退避 | 指数退避 500ms×2、上限 30s、±20% 抖动；每次重连同请求带 `Last-Event-ID: <lastEventId>`（08 篇：网关从 Redis 会话事件流补发） |
| 生命周期 | 仅会话页挂载时订阅，卸载即断开不重连；同一会话同一时刻仅一条连接 |

### 3.2 seq 对账与 MESSAGES_SNAPSHOT 补齐

| 场景 | 处理 |
| ---- | ---- |
| 订阅建立 | 先 `GET /api/v1/sessions/{id}/messages` 拉历史作渲染基线，再开 SSE（13 篇） |
| `seq === lastSeq + 1` | 正常归约，推进 lastSeq |
| `seq ≤ lastSeq` | 重复帧，丢弃 |
| `seq > lastSeq + 1` | 判定跳号：挂起增量 → 立即按退避重连（Last-Event-ID = lastSeq）请求网关补发 |
| 重连后仍跳号 | 以 `MESSAGES_SNAPSHOT`（事件 16）全量覆盖 `messages` 重建，对齐 seq 后恢复增量 |
| 不可续传兜底 | 无快照且历史接口与本地仍对不齐 → 整页刷新兜底并上报 |

### 3.3 16 事件 → store 归约器

| 事件（08 篇 §5 编号） | 归约动作（store.字段） |
| ---- | ---- |
| 1 RUN_STARTED | `session.runs[taskId] = {status:'running', agent摘要}` |
| 2 RUN_FINISHED | `runs[taskId].status='succeeded'`，用量入 `.usage` |
| 3 RUN_ERROR | `runs[taskId].status='failed'`，`.error={code,retryable}`（3xxx，13 篇） |
| 4–6 TEXT_MESSAGE_START/_CONTENT/_END | `messages[]` 追加骨架 → 流式拼接 `delta` → 封口 |
| 7 THINKING_START/_CONTENT/_END | `thinking[messageId]` 流式摘要（默认折叠，租户可关） |
| 8–10 TOOL_CALL_START/_ARGS/_END | `toolCalls[callId]`：开卡（toolName/ActionRef）→ 参数增量 → 收尾 |
| 11 TOOL_CALL_RESULT | `toolCalls[callId].result` + 挂起审批状态 |
| 12 STATE_SNAPSHOT | `session.contextState` 全量覆盖 |
| 13 STATE_DELTA | `contextState` 应用 JSON Patch |
| 14 APPROVAL_REQUIRED | `session.approvalPends[]` 入队，AppShell 待办角标 +1（联动 11 篇） |
| 15 CUSTOM | 按 `payload.type` 分发：证据路径 → `contextState.evidence`；未知类型丢弃并上报 |
| 16 MESSAGES_SNAPSHOT | `session.messages` 全量覆盖（§3.2 对账兜底） |

### 4.2 守卫流程与权限驱动可见性

1. 路由匹配读取 `meta.permission`；`auth-store.status === 'anonymous'` → 先静默 refresh 尝试恢复，仍匿名 → 重定向 `/login?redirect=<原路径>`；
2. 已认证但 `permissions` 为空 → `GET /api/v1/auth/me` 补拉（当前用户 + 角色 + 权限集，13 篇）；
3. 判定 `meta.permission ⊆ permissions`（词汇 = 11 篇 `资源:动作`，字典 `GET /api/v1/permissions`）→ 不足渲染 403 页，不重定向（防循环）；
4. 可见性：侧边栏菜单按 permissions 过滤渲染；按钮级 `<Guard permission="ontology:publish">` 缺失即隐藏/禁用；
5. 铁律：前端隐藏≠授权，服务端 PDP 五步判定（11 篇 §5）仍兜底；权限集以重新拉取 me 为准，前端不做本地推导。

## 7. 错误与加载态统一

| 码段（13 篇 §3） | 示例码 → 提示/前端行为 |
| ---- | ---- |
| 1xxx 网关 | 1002 → 字段级错误回填表单；1005 → Toast「操作过于频繁」+ 按 Retry-After 倒计时禁用；1008 → Toast「请求超时，请重试」 |
| 2xxx 认证 | 2001/2004 → 清会话态跳登录（带 redirect）；2002 → 静默刷新后重放原请求，失败按 2001 处理；2008 → 403 页「没有执行此操作的权限」；2011 → 全站横幅「租户已停用，请联系平台方」 |
| 3xxx 业务 | 3001 → 404 空态页；3005 → 「配额已用尽，请联系管理员调整」；3008 → 操作禁用 +「对象审批中，暂不可修改」；3011 → 会话只读横幅「会话已归档」 |
| 4xxx 语义 | 4001 → 渲染结构化 SHACL 报告列表（定位到节点/属性，非一坨红字，03 篇 §7）；4003 → IRI 字段错误提示；4007 → 冲突待裁决卡，跳审核台 |
| 5xxx 存储 | 5001–5005 → Toast「服务内部错误，请稍后重试」+ 折叠 trace_id；5007 → 「任务排队中」转轮询；5009 → 「模型服务暂不可用，请稍后重试」 |

统一组件：加载 = Skeleton / 表格骨架 / 按钮 spinner（03 篇 §3.1 基元清单）；空态 = EmptyState（图标 + 文案 + 主行动）；路由级 ErrorBoundary 兜底。一切 API 错误经 `lib/errors.ts` 单点映射为中文文案，组件不得自行拼错误字符串。

SSE 断连提示：`connection !== 'open'` 时消息流顶部窄横幅「连接已断开，正在重连（第 n 次）」；退避达上限 → 「实时流不可用」+ 手动重连按钮；恢复并完成对账（§3.2）后 Toast「已恢复同步」。

## 8. 测试（Vitest + React Testing Library + MSW）

| 范围 | 必测用例 |
| ---- | ---- |
| SSE 归约器（src/sse） | 16 事件逐一归约断言；seq 正常/重复/跳号；MESSAGES_SNAPSHOT 覆盖重建；Last-Event-ID 重连参数与退避序列 |

MSW 约定：handlers 按 13 篇模块分文件（`tests/msw/handlers/<模块>.ts`），路径与端点一一对应；响应一律 `{code:0, message:'ok', data}` 信封，错误用例显式使用 13 篇错误码；分页返回 `items + next_cursor`。SSE 不经 MSW：用可编程 fake（注入事件序列、可控断线/跳号）驱动归约器测试。
