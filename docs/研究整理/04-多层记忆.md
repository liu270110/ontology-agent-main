# 04 - 多层记忆系统

> 状态：v0.1 | 调研时间：2026-09 | 依据：CoALA 论文、Letta/mem0/Graphiti/LangMem 官方仓库与文档
>
> 记忆服务是平台的横切能力：Agent 服务读写，知识级与本体核心打通。

---

## 1. 理论基座：CoALA 记忆分类

《Cognitive Architectures for Language Agents》（Sumers et al., 2023, [arXiv:2309.02427](https://arxiv.org/html/2309.02427v3)，TMLR）：agent = 记忆 + 决策循环（检索→推理/规划→学习→行动）。记忆四分：

| 类型 | 内容 |
|---|---|
| **工作记忆** | 当前决策所用、在上下文中的信息 |
| **情景记忆**（episodic） | 过往经历/轨迹 |
| **语义记忆**（semantic） | 世界知识与事实 |
| **程序记忆**（procedural） | 技能/代码（含 LLM 权重本身） |

## 2. 代表项目对比

| 项目 | 仓库 | 记忆分层与检索机制 |
|---|---|---|
| **Letta**（原 MemGPT） | letta-ai/letta | OS 虚拟内存隐喻，上下文窗=RAM。三层：**Core Memory**（常驻上下文、可自编辑记忆块，存 persona/关键用户事实）、**Recall Memory**（可检索会话历史，SQLite/Postgres）、**Archival Memory**（外部长期存储，工具调用读写） |
| **mem0** | mem0ai/mem0 | 两阶段流水线（[arXiv 2504.19413](https://arxiv.org)）：**抽取**（LLM 从新交互+近期上下文抽候选记忆）→ **更新**（相似检索后判定 ADD/UPDATE/DELETE）；向量库为主，可选图存储；v3 趋向 append-only 图记忆（社区讨论，未确认） |
| **Zep / Graphiti** | getzep/graphiti | **时序知识图谱（bi-temporal）**：对话/业务记录持续摄入时间感知图，分 **episodic（事件）/ semantic entity（实体语义）/ community（社区）** 三层子图；用 **invalidation 边表达事实失效**而非物理删除，保留完整时间线；后端 Neo4j/FalkorDB/Memgraph。注意：Zep Community Edition 已于 2025 弃用，开源路线直接用 **Graphiti** |
| **LangMem** | langchain-ai/langmem | LangChain 官方记忆 SDK：**热路径**（对话中即时写）+ **后台**（异步反思沉淀）两条写入路径；语义记忆抽取 + 可执行"记忆更新规则"（偏程序记忆） |

**横向结论**：Letta 强在"上下文内自编辑记忆块"（工作记忆工程化）；mem0 强在轻量抽取/更新管线与多后端；Graphiti 强在**时间维与图结构**（适合组织级/知识级沉淀）；LangMem 强在 LangChain 生态内嵌。

## 3. 平台四层记忆设计

按 CoALA 四类映射到四层（层次递升、逐层沉淀）：

| 层 | 内容（CoALA 对应） | 建议存储 | 写入/沉淀 | 遗忘策略 |
|---|---|---|---|---|
| **L1 会话级**（工作记忆） | 当前任务上下文、滑动窗口、任务草稿 | Redis（热）+ Postgres（会话日志，参考 Letta recall） | 实时写入；会话内自编辑记忆块（Letta 式） | 会话结束即归档，活跃 TTL |
| **L2 用户级**（情景+个人语义） | 用户画像、偏好、历史事实 | **mem0**（向量+ADD/UPDATE/DELETE）或 Graphiti 单用户图；pgvector 落底 | 会话结束后台抽取沉淀（LangMem 后台路径式） | 置信度/时间衰减 + 矛盾更新 |
| **L3 组织级**（共享情景） | 团队/项目共同事件、决策、社区结构 | **Graphiti**（时序图三层子图） | 审核后的用户级记忆升级合并；invalidation 边软删保留时间线 | invalidation 边 + 归档，不物理删除 |
| **L4 本体/知识级**（共享语义） | 领域本体、GraphRAG 知识库（即 [03 篇](./03-知识库与本体核心.md)） | Neo4j 属性图 + 向量层（OWL 本体管控） | 知识工程流程 + GraphRAG 索引管线 | 版本化发布，本体走变更评审 |

### 3.1 沉淀管线（写入侧）

统一为三步（mem0 两阶段 + LangMem 后台反思的结合）：

```
抽取（LLM 从新交互抽候选记忆）→ 冲突判定（相似检索 + ADD/UPDATE/DELETE/升级决策）→ 分级写入（L1~L4 各走各的门禁）
```

- L1→L2：会话结束后台自动抽取，静默写入；
- L2→L3：需审核（共享记忆涉及他人，默认不自动升级）；
- L3→L4：走本体知识工程的"机器粗加工+人工终审"门禁（见 03 篇）。

### 3.2 检索管线（读取侧）

各层**并行召回** → 按层级加权合并注入 prompt：

- L1 常驻（工作记忆必须全量在上下文）；
- L2/L3 按相关性 + 时效性加权（Graphiti 的时间感知检索在此发挥作用）；
- L4 走 GraphRAG 检索（local/global 按问题类型路由，见 03 篇）；
- 程序记忆（技能/提示词模板/工具配方）单独建版本库，**与插件市场打通**（见 06 篇）。

### 3.3 遗忘与审计

遗忘 = **TTL（会话级）+ 时间衰减（用户级）+ 时序失效边（组织级）+ 版本化（知识级）**——全程不物理删除，保证可审计。这与本体的"知识漂移"治理（03 篇）共享同一套变更管控思想。

## 4. 与平台其他服务的关系

- **Agent 服务**：agent 工具经平台统一的 memory API（或 MCP tool `memory.read/write`，见 05 篇）读写，按层授权；
- **本体核心**：L4 与本体重合——本体是"经过治理的知识级记忆"；记忆服务沉淀的高频事实可发起"候选本体条目"流程进入人工审核；
- **agent 工具**：各自的本地记忆（nanobot Dream、hermes 画像、pi JSONL 会话）保留为**会话私有缓存**，跨会话/跨工具的长期记忆统一收口到平台记忆服务——避免记忆孤岛。
