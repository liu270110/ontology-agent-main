# 05 - 前端 VibeCoding 规范（AI 代理执行版）

> 状态：v1.0 待评审 | 日期：2026-09-26 | 上游：[03-UI设计规范](./03-前端架构与UI设计规范.md)、[22-工程规范与研发流程](./22-前端工程规范与研发流程.md)
>
> **本文把 03/22 篇的"人用流程"改写成"AI 代理可直接执行的规则"**：传统方式是"设计师出稿 → 人按主题找组件 → 人工适配"，VibeCoding 方式是把每一步变成 *规则 + 机器可校验的验收标准*，让任何 agent（Claude Code / pi / openclaw / 未来平台自托管的 agent 工具）读完即可产出风格一致、质量达标的前端代码。
>
> 行业共识（2026）：探索性工作用 vibe coding 快速出稿，**生产系统必须走规范驱动（SPEC 模式）**——本规范即本仓库前端的 SPEC 模式。

---

## 1. 范式转变对照

| 传统流程（人执行） | VibeCoding 规范（agent 执行） | 机器可校验方式 |
| ---- | ---- | ---- |
| 设计师定主题，出设计稿 | 读 `theme/tokens.css` + 03 篇设计系统章节 | 组件内不允许出现令牌外的颜色/字号/圆角值（ESLint tailwind 插件 + Stylelint 拦截） |
| 人从脚手架/组件库挑组件 | 强制先查组件清单（03 篇 §3 + `components/` 目录），复用优先 | PR 中新增组件必须附"清单检索记录"：已有哪些、为何不够 |
| 人做主题适配 UI 设计稿 | 组件只消费令牌；适配=组合基元+令牌参数，不是改基元内部 | shadcn 基元文件原则上只读（改动须单独 PR 且说明影响面） |
| 设计师走查 | agent 截图自检 + DoD 清单（§5） | Playwright 截图（亮/暗 × 关键状态）附 PR |
| 测试工程师回归 | 视觉基线比对 + e2e 关键路径 | CI 门禁（22 篇 §4.3） |
| 口头/文档交接上下文 | AGENTS.md + skills 自动加载（§2） | 文件存在且被工具加载，无需人转述 |

## 2. 规则文件体系（上下文如何进入 agent）

```
AGENTS.md                        # 【入口】仓库根：项目是什么、铁律、文档地图（任何 agent 会话自动获得）
└── frontend/AGENTS.md           # 【前端工程细则】M1 脚手架落地时创建：命令、目录、约定速查
docs/架构设计/03、22~23               # 【知识库】设计系统全量定义（按需 Read，不整篇塞上下文）
skills/                          # 【技能】按任务类型加载的操作手册（SKILL.md，agentskills.io 格式）
├── frontend-ui-apple/           #   做界面/组件时加载
├── frontend-dev-standards/      #   写任何前端代码前加载
└── frontend-testing/            #   自检/修样式/写测试时加载
```

加载约定：会话开始读根 AGENTS.md（短，索引性质）；动手前按任务加载对应 skill；需要设计细节时**只读 03 篇相关章节**，禁止整篇粘贴。平台自身的 Skills 服务（研究 06 篇）上线后，`skills/` 目录即第一批技能资产——开发平台的 agent 工具时吃自己的狗粮。

## 3. 六条铁律（每条 = 规则 + 校验 + 违规示例）

1. **令牌是唯一事实源**：颜色/字号/间距/圆角/阴影/动效曲线只允许引用 `theme/` 令牌；新增令牌必须先改 `tokens.css` 并单独说明。
   校验：ESLint `tailwindcss` 插件 + Stylelint。违规：`style={{ color: '#0071e3' }}`、Tailwind 任意值 `bg-[#f5f5f7]`。
2. **组件清单优先**：动手前先盘点已有组件；新增组件须声明清单检索结论。校验：PR 模板字段必填。违规：重写一个已有 `ApprovalCard` 变体。
3. **基元只读**：shadcn 定制基元（`components/ui/`）禁止在业务代码内修改；要改走独立 PR（影响全站）。校验：CODEOWNERS + review。违规：为某个页面顺手改 Button 内边距。
4. **契约先行**：接口类型只允许 `openapi-typescript` 生成；后端未定义的接口先补后端 schema。校验：CI 比对生成物与手写类型。违规：手写 `interface ChatResponse {...}`。
5. **小步可验证**：单次交付 ≤ 一个页面或 ≤ 3 个组件，每次交付必须跑通自检闭环（§5），禁止"写完一起验"。校验：PR diff 规模 + 自检记录。违规：一次 PR 提交五个页面。
6. **截图验收闭环**：任何视觉改动必须以截图证明（亮/暗 × 空态/加载态/错误态按适用），截图由 Playwright 脚本产出、存 `e2e/__screenshots__/` 并贴 PR。校验：CI 视觉回归。违规："应该没问题，没截图"。

## 4. 标准任务流（SOP，agent 每次前端任务按此走）

```
①对齐 spec → ②组件盘点 → ③契约检查 → ④实现 → ⑤静态自检 → ⑥截图验收 → ⑦交付报告
```

| 步 | 动作 | 产出 |
| ---- | ---- | ---- |
| ①对齐 spec | 找到该页面/组件在 03 篇（或 feature spec）的定义：结构、状态、跳转、组件关联；缺失则**先补 spec 请用户确认，不许直接编码** | spec 引用或新增 spec |
| ②组件盘点 | 列出 spec 需要的组件 → 对照 `components/ui|business/` 清单，标注复用/新增；新增组件先写 story | 盘点表（进交付报告） |
| ③契约检查 | 该页面用到的 API 是否已在 OpenAPI；无则先与后端对齐 schema，生成类型 | 类型化 client 可用 |
| ④实现 | 按 03 篇组件关联逻辑组装；TanStack Query 管数据、Zustand 管本地态；路由与跳转按 §4.1 路由表 | 可运行代码 |
| ⑤静态自检 | `pnpm typecheck && pnpm lint && pnpm test`；逐条过 DoD 清单（§5） | 自检记录 |
| ⑥截图验收 | 起 dev server，按 frontend-testing 技能跑截图脚本：目标页面 ×（亮/暗）×（空/加载/错误态） | 截图 + 差异结论 |
| ⑦交付报告 | 固定格式（§4.1）汇报给用户，等确认后提交 | 报告 + commit |

### 4.1 交付报告模板

```
## 本次交付
- 范围：<页面/组件，对应 spec 章节>
- 组件盘点：复用 x 个（列出）；新增 y 个（理由）
- 自检：typecheck/lint/test 结果；DoD 六维各一行结论
- 截图：<路径>（亮/暗 × 状态）
- 已知问题与建议：<如有>
```

## 5. DoD 清单（Definition of Done，六维）

| 维度 | 自检项 |
| ---- | ---- |
| 功能 | spec 全部状态实现（加载/空/错误/成功）；跳转与 03 篇路由表一致；mutation 有 pending 反馈 |
| 视觉 | 只用令牌；亮暗模式都过；发丝线/圆角/阴影与 03 篇 §2 一致；动效用 `ease-apple`/spring |
| 类型 | 无 `any`；API 类型来自生成物；query key 三段式且已登记 |
| 测试 | 新增逻辑有单测；业务组件有交互测试；视觉基线已更新（附理由） |
| 性能 | 无超预算依赖；重组件（React Flow/ECharts）懒加载；列表虚拟化（>200 行） |
| a11y | 键盘可达；aria 齐全；对比度达标；`prefers-reduced-motion` 生效 |

## 6. 反模式清单（AI 审美与工程双重防治）

**绝对禁止**（AI slop 防治，源自 frontend-design 技能原则 + 本项目约定）：
- 紫色渐变、白底紫按钮、居中堆砌布局、emoji 当图标；
- 硬编码色值/字号/圆角（铁律 1）；
- 组件内裸写中文长文案、裸写接口类型（铁律 4）；
- 为"看起来完整"加无用功能（YAGNI，设计宪法第 4 条同样适用于 UI）。

**本项目豁免**：`frontend-design` 技能默认"禁用系统字体"，本平台**反其道而行**——Apple 系统字体栈（SF Pro/苹方/雅黑降级链）就是品牌本身，属于刻意决策，不是偷懒；同理禁用的还有"自创字体""撞色撞渐变"等偏离 Apple 语言的做法。风格问题的最终解释权在 03 篇设计系统章节。

**修复循环规则**：截图验收不过 → 修复 → 重截，最多 3 轮；3 轮仍不过，停止并向用户报告卡点（附三组截图对比），不许继续盲改。

## 7. 与平台 Skills 服务的关系

`skills/` 下三个 SKILL.md 按 agentskills.io 格式编写（name + description frontmatter），既是开发本仓库的 agent 技能，也是平台技能（Skills）服务的**第一批真实资产**：格式、审核、分发流程先在自己的开发流程中验证，再供平台用户使用。
