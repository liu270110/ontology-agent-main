## 1. 对标基准与选取理由

| 对标项目 | 定位 | 借鉴面 | 代表性参考功能 |
| ---- | ---- | ---- | ---- |
| **ChatGPT / Claude / Gemini**（官方消费级） | 对话体验天花板 | 对话页交互与会话组织 | Projects（会话文件夹+项目文件+项目指令）、临时会话（无痕）、推理力度档位（GPT-5 light/standard/heavy）、Artifacts 画布、消息编辑/重生成、语音、分享快照链接 |
| **Open WebUI**（自托管，GitHub 90k+ star） | 管理端与权限模型标杆 | RBAC 之上的 Groups+ACL、管理端 | 用户组 Groups、资源 ACL（模型/知识库按组可见）、默认权限模板、聊天文件夹/置顶/标签、@提及知识库、会话分享、管理员模型管理 |
| **LobeChat / Cherry Studio**（开源全功能对话） | 对话周边能力全集 | 文件与提示词资产 | 对话中直接上传文件并挂知识库、文件管理页、提示词库/助手市场、TTS/STT、话题分组 |
| **Dify / FastGPT / RAGFlow**（RAG 平台） | 知识库工程化 | 知识库页深度 | 文档管道（解析/分块/嵌入可配置）、检索测试、文档在线预览、团队空间与库级权限、标注回复 |

选取逻辑：本项目 = 对话 + 知识库 + 管理三位一体的自托管平台，**消费级对话体验**看 ChatGPT/Claude，**自托管管理与权限**看 Open WebUI，**对话周边资产**看 LobeChat/Cherry Studio，**知识库工程面**看 Dify/RAGFlow。

## 2. 结论速览

当前设计在**引用渲染、证据链、审批流、治理档位**上领先对标项（这是本平台差异化）；缺口集中在四带：

1. **对话页文件能力带（P0，用户点名）**：输入栏无附件上传、无会话级知识库挂载、无 @提及、无文件库 —— 全线缺失；
2. **对话控制带（P0）**：无思考等级档位、无消息编辑/重生成操作组、无联网搜索等工具开关、无临时会话；
3. **会话资产带（P1）**：无置顶/文件夹/Projects、无分享链接、无提示词库管理；
4. **权限纵深带（P1）**：只有角色级 RBAC，无用户组 Groups、无资源级 ACL（知识库/会话/Agent 协作者共享）、无"权限申请"审批对象（403 页申请入口无落点）。

## 4. 对话页专项设计要点（P0 落地口径）

1. **输入栏五件套**（对标 ChatGPT 输入栏，从左至右）：`+ 附件` → 工具开关组（联网搜索/图片生成）→ 思考档位 → 文本框（`/` 斜杠命令、`@` 提及、`#` 引用知识库三触发符）→ 模型/Agent 选择器（已有）。玻璃材质遵循 03 篇（输入栏=Clear 档悬浮层）。
2. **附件生命周期（候选非成品宪法的落法）**：附件分两路——**临时附件**（随消息存 MinIO，仅本会话引用，不进抽取流水线）与**转存知识库**（显式动作，走既有 UploadZone 七步流水线+审核队列，绝不绕过审核直入库）。默认临时，转存需确认。
3. **思考档位与推理分级的关系**：档位只调 LLM 推理预算（低频语义判断路径），规则引擎/SHACL 确定性路径不受影响——与宪法 2 完全同构；solo 档默认"标准"，enterprise 档可由管理员限制可选范围。
4. **消息编辑语义**：编辑用户消息 = 从该点分叉（复用 BranchSwitcher 与轨迹页"从此分叉"既有机制，非原地改写，保全程可追溯宪法）。
5. **临时会话与记忆**：临时会话不产生 L2 候选沉淀、不写 L1 个性化——记忆系统既有"候选→审批"链路天然兼容，只需会话标记位。**临时会话仍全量写审计与 trace_id（宪法 5）**，仅不进用户历史检索与记忆沉淀。
6. **上下文用量条**：后端 Run 已有绝对预算，前端以 SSE 周期事件暴露用量水位即可（需在 08 篇事件契约中补一个用量事件，见 §7）。

## 5. 权限专项：三层模型（补齐纵深）

```
第1层 角色 RBAC（已有：RbacMatrix，画框23）
第2层 用户组 Groups（本批新增：组=授权单元+资源 ACL 的授权对象）
第3层 资源级 ACL（本批新增：知识库/Agent/模型渠道/会话分享 的 per-组/per-人 可见可用授权）
```

- 治理三档映射：solo 档可不暴露第 2/3 层 UI；team 档启用组+库级 ACL；enterprise 档全量+SSO。
- **权限申请闭环**：403 页"申请入口"→ 生成权限申请 → 审批中心第六类对象（新审批类型，带申请理由+目标资源+申请权限）→ 通过后自动授权并审计。这是把既有审批流变成权限治理载体的最小改动。
- 模型渠道"可用人选"：管理员限定哪些组可用哪个渠道（对标 Open WebUI 模型 ACL），与数据分析页预算降级策略联动（触顶切本地档时同样按组判断）。
