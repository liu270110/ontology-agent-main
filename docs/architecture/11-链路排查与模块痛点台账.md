### 压缩（compaction）设计（2026-09-26 新增）

**核心洞察：压缩即再生成，是隐蔽的幻觉入口**——摘要丢掉的关键数字/ID/约束会在后续步骤被模型"脑补"回来。四条规则：

1. **触发**：工作集超预算 80% 时触发（不等爆窗）；由组装器而非模型决定；
2. **压什么不压什么**：结构化状态（计划/StepState/事实槽位/未决审批）**永不压缩**——它们本来就在 ABox/账本外置，重读即可；只压对话叙述与已消费证据的引文（保留指针丢正文）；
3. **压缩产物过裁判**：摘要必须过 SHACL/事实槽位比对（摘要里出现的数字/ID/枚举必须能在原始段或外置状态找到出处），不过则降级为"截断+指针"（宁丢勿编）；
4. **可回溯**：原始上下文不删（归 PG 账本），压缩点标记 `compacted_at`，用户/调试可展开原文；压缩动作留 trace。
落点：Agent §4.1 组装器增补；验收=压缩后关键事实槽位零丢失用例 + 摘要编造数字被拦截用例。

| ---- | ---- | ---- | ---- |
| 网关×SSE | **慢消费者背压**：客户端读得慢，写缓冲堆积拖死 worker（长连接系统头号事故） | 写缓冲上限+超限断开（客户端重连走回放窗口）；指标 `sse_write_buffer_bytes` | P1 |
