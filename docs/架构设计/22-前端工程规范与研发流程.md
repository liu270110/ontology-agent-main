## 1. 大厂流程参照（定了什么、为什么）

Ant Design（蚂蚁）、Semi Design / Arco（字节）、TDesign（腾讯）三条国内主流设计体系工程路线的共性，抽象成五段管道：

| 阶段 | 大厂做法 | 本项目落点 |
| ---- | ---- | ---- |
| **设计令牌管道** | Figma Tokens/Style Dictionary：设计值（颜色/字号/圆角）以 JSON 为源，流水线产出多端 CSS 变量；设计与代码共享同一份令牌，禁止手工抄色值 | 03 篇 `theme/tokens.css` 为唯一事实源；未来引入 Figma 时令牌 JSON ↔ tokens.css 双向对齐 |
| **组件驱动开发（CDD）** | 基元组件先于页面，每个组件配 Storybook story（状态矩阵：默认/hover/禁用/加载/空态/异常），组件验收先于页面验收 | 基元组件（shadcn 定制）逐个 story 化后才允许页面引用；业务组件同样 |
| **设计走查（UI Review）** | 设计师按走查单逐项核对实现稿（间距/字重/圆角/动效曲线/暗色模式/空态），走查单是硬门禁不是建议 | 走查单内化为 23 篇 DoD 清单的"视觉"维度，由 agent 截图自检 + 用户抽查 |
| **视觉回归** | Chromatic/Playwright 截图基线比对，防止样式回归悄悄合入 | Playwright 截图基线（`e2e/__screenshots__`），CI 比对，重大改版显式重建基线 |
| **契约先行** | OpenAPI/GraphQL schema 先于前端编码生成类型，前端不手写接口类型 | openapi-typescript 从 FastAPI 生成，PR 中禁止手写 API 响应类型 |

## 2. 本项目研发流程（阶段门禁）

```
需求 → UI 设计 → 设计评审 → 组件实现 → 页面组装 → 走查 → 测试 → 合并
       ①产出页面稿与组件清单  ②评审通过才编码  ③story 先行  ④对照 03 篇关联逻辑  ⑤走查单  ⑥四层测试  ⑦PR 门禁
```

| 阶段 | 产出物 | 通过标准（门禁） |
| ---- | ---- | ---- |
| UI 设计 | 页面结构说明 + 组件清单 + 跳转关系（写入 `docs/架构设计/03` 或 feature spec） | 清单里每个组件标注"复用已有"或"新增"，新增须说明理由 |
| 设计评审 | 评审结论追加在 spec 上 | 用户或设计负责人确认；改动涉及主题令牌必须先改 tokens.css |
| 组件实现 | 组件 + story + 单测 | story 覆盖六态（默认/hover/禁用/加载/空态/异常）；a11y 无违规 |
| 页面组装 | 页面 + 路由 + query hooks | 数据全部走 TanStack Query；无本地 mock 残留 |
| 走查 | 截图（亮/暗 × 关键状态） | 23 篇 DoD 视觉维度全过 |
| 测试 | 测试报告 | CI 门禁全绿（见 §4.4） |
| 合并 | PR | ≥1 approve；commit 符合仓库中文提交惯例 |

## 3. 工程规范

### 3.1 工具链（脚手架内定死）

| 工具 | 配置要点 |
| ---- | ---- |
| TypeScript | `strict: true`，禁 `any`（`unknown` + 收窄），禁 `!` 非空断言（domain 数据除外，须注释） |
| ESLint | flat config；`typescript-eslint` + `react-hooks` + `jsx-a11y` + `tailwindcss`（class 顺序与非法值检查） |
| Prettier | 默认配置 + `printWidth: 100`；与 ESLint 冲突项以 Prettier 为准 |
| Stylelint | 仅管 `*.css`（令牌文件），校验 CSS 变量命名 `--{category}-{name}` |
| husky + lint-staged | pre-commit：staged 文件 lint + format；commit-msg：commitlint |
| commitlint | 中文 conventional：`feat/fix/docs/refactor/test/chore: 描述`（沿用仓库现行中文提交惯例） |

### 3.2 命名与文件组织

- 组件文件与目录 PascalCase（`MemoryLayerTabs/`，入口 `index.tsx`）；hooks `useXxx.ts`；工具 `lib/` 内 camelCase；常量 UPPER_SNAKE。
- 路由 path 小写中划线；query key 按 `[域, 资源, 参数]` 三段式，集中在 `api/queries.ts` 管理，禁止组件内裸写 key。
- 一处一义：每个业务组件只属于一个 feature 目录，跨 feature 复用必须提升到 `components/business/`，禁止相对路径跨 feature import（ESLint `no-restricted-imports` 强制）。

### 3.3 Git 流程

- 分支：`develop` 拉 `feature/frontend-{域}-{简述}`，合回 `develop`；主题令牌变更单独 PR（影响全局，需用户确认）。
- PR 模板四张自检清单：视觉（令牌/亮暗/空态）、逻辑（错误处理/加载态/取消竞态）、性能（code splitting/依赖体积）、a11y（键盘/对比度/aria）。

### 3.4 性能与体验预算（超预算 = 不合格）

| 项 | 预算 |
| ---- | ---- |
| 首包 JS（gzip） | ≤ 200KB（路由级 code splitting，React Flow/ECharts 只在对应页面懒加载） |
| LCP（工作台） | ≤ 2.5s（本地/内网部署） |
| 交互延迟 | 列表操作 < 100ms 出现 loading 反馈；所有 mutation 有 pending 态 |
| 图包 | 新增 dependency 需在 PR 说明体积与替代方案；禁止引入 moment/ lodash 全量 |

### 3.5 无障碍与文案

- 全键盘可达（对话框聚焦陷阱、Esc 关闭）；交互元素对比度 ≥ 4.5:1；图标按钮必须 `aria-label`；动效尊重 `prefers-reduced-motion`。
- 中文文案：按钮用动词短语（"新建本体"不写"确定"）；错误文案 = 原因 + 建议；空态必须给下一步动作入口。文案集中在 `locales/zh-CN.ts`，组件内禁止裸写中文长文案。

## 4. 测试策略

### 4.1 分层

| 层 | 工具 | 范围 | 比例预期 |
| ---- | ---- | ---- | ---- |
| 单元 | Vitest | 纯函数、hooks、zod schema、状态机 | 覆盖 `lib/` 与 hooks 的关键分支 |
| 组件 | Vitest + Testing Library + Storybook 交互测试 | 基元组件行为、业务组件状态矩阵 | 业务组件必测核心交互 |
| E2E | Playwright | 关键路径：登录→工作台→对话→本体建模保存→审核通过 | 每条关键路径一条脚本 |
| 视觉回归 | Playwright 截图 | 基元组件六态 + 四个核心页面（亮/暗）× **视口矩阵 1440/1280/1024/768/375**（03 篇 §2.6） | 基线入库 `e2e/__screenshots__/` |
| a11y | axe-core（挂 Playwright） | 同四页面 | 零 critical 违规 |

### 4.2 关键约定

- 测试不测样式细节（那是视觉回归的事），测行为与状态；mock 网络一律走 MSW，禁止各测试自造 fetch mock。
- 截图基线更新必须在 PR 中说明原因；连续两次"无关差异"说明基线策略要修，不允许反复 `--update-snapshots` 掩盖。

### 4.3 CI 门禁（Gitee Go，`develop` 与 `master`）

```
install → typecheck → lint → unit+component → build → e2e(关键路径) → visual(截图比对) → 汇总报告
```

任一环节红即阻断合并；e2e 失败自动附 Playwright trace 与截图到制品。

### 4.4 手工测试兜底

自动化覆盖不了的（动效质感、毛玻璃渲染、长文本溢出），用 [webapp-testing 技能（本机绝对路径引用已失效，技能见 skills/frontend-testing/） 的 Playwright 交互脚本半自动走查，走查记录贴 PR。
