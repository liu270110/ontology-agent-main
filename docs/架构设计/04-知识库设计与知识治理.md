### 1.2 从 llmwiki 借鉴什么

| llmwiki 机制 | 本平台对应物 | 差异说明 |
| ---- | ---- | ---- |
| 原始文件只读，wiki/ 是编译产物，`.llmwiki/` 索引可删可重建 | **三层资产模型**（§2）：Raw 不可变 / Compiled 可再编译 / Derived 可丢弃 | 平台的编译产物不止 Markdown 页，而是候选实例 → 终审事实 → 图谱/向量索引 |
| 增量编译：routine 只处理上次运行以来的新增，把新材料"折入"既有页面 | **nightly 维护例程**（§5.2）：只重编译受影响事实的社区摘要，不全量重建 | 平台有 ARQ 任务队列与 Outbox 事件，例程由事件驱动 + 定时兜底 |
| **Supersession callout：变更要显式声明取代，不许静默覆盖** | **supersedes 链**：文档级与事实级都显式记录取代关系，检索结果默认携带"已被 X 取代"提示（§4、§6） | 平台用图边（`INVALIDATED_BY`/`SUPERSEDES`）+ 双时间戳承载，比 Markdown 标注更结构化 |
| 外部系统声明必须带指针 + 核对日期，lint 按最老优先重验 | **易变知识不入库，只存指针**（§5.4）；知识条目带 `checked_at`，lint 陈旧重验 | 直接采纳，这是社区 1000+ 评论里最痛的教训 |
| lint 巡检：悬挂链接、孤儿页、陈旧页 | **知识 lint**（§5.2）：悬空出处、孤儿实体、陈旧声明、失效未封口 | 检查对象从 Markdown 换成图谱与索引 |
| Promotion gate：agent 起草、人工晋升，未晋升草稿不得作为证据被引用 | **候选非成品**（设计宪法第 3 条，已有）：候选实例未经终审不得写图，更不得被其他抽取引用 | 已有，本文补"候选不得互为证据"细则 |
| "Scope, don't filter"：按领域切分语料，不把一切塞进上下文 | 知识库按 kb_id（业务域）划分集合/分区，检索路由先定域再查 | 已有 kb_id 设计，重申为检索前置步骤 |

### 1.3 六条设计公理（本文档范围内强制）

1. **原始层不可变**：原始文档与切片永不修改、永不物理删除；一切下游资产都是它的投影。
2. **事实带时间线**：每条断言有双时间（业务有效时间 t_valid / 入库事务时间 t_txn）；失效用边和封口表达，不删除。
3. **取代必须显式**：新旧更替走 supersedes 关系并留痕，禁止静默覆盖。
4. **默认最新，旧知可寻**：检索默认只返回当前有效知识；时间点查询（as-of）与显式包含被取代知识是一等公民参数。
5. **消歧在入库时完成大半**：术语对齐是入库门禁，不留到检索时猜。
6. **冲突是治理信号，不是错误**：冲突自动分诊，裁决不了的进人工工单，绝不两边都默默保留或默默丢弃。

## 2. 三层资产模型（知识库的地基）

```
┌────────────────────────────────────────────────────────────────┐
│ Raw 原始层（不可变）                                              │
│   原始文档（MinIO raw-documents，永久）                            │
│   切片 doc_chunks（PG，带 hash 与 span，版本戳）                    │
└──────────────┬─────────────────────────────────────────────────┘
               │ 七步流水线（抽取/对齐/校验/终审）
┌──────────────▼─────────────────────────────────────────────────┐
│ Compiled 编译层（可再编译，有门禁）                                 │
│   候选实例 candidates（PG，审核队列）                               │
│   终审事实/断言（Neo4j ABox + Fact 时间线）                        │
│   社区摘要（GraphRAG compilation，Neo4j + Milvus）                │
│   术语表 terms / 别名表（PG）                                      │
└──────────────┬─────────────────────────────────────────────────┘
               │ 投影（Outbox 中继，幂等）
┌──────────────▼─────────────────────────────────────────────────┐
│ Derived 派生层（可丢弃、可重建）                                    │
│   Milvus 向量索引、PG 全文索引、Redis 缓存、图谱统计物化              │
└────────────────────────────────────────────────────────────────┘
```

| 层 | 变更策略 | 回答什么问题 |
| ---- | ---- | ---- |
| Raw | **append-only**：只增不改不删（同源更新 = 新版本文档追加，旧版本转 superseded 状态而非删除） | "旧知识也需要在"的第一保证——任何历史内容永远取得到 |
| Compiled | 门禁内变更：终审事实被取代时封口 + 连边，不删；社区摘要可随时由 Raw + 事实重算 | 知识的当前语义与历史演变 |
| Derived | 任意重建：Milvus 可全量重灌（源在 PG/Neo4j），索引损坏零风险 | 检索速度 |

这一分层是 llmwiki "filesystem is the source of truth; the index just makes it fast to search" 的结构化落地：**只要 Raw 在，任何知识在任何时刻的状态都可重放重建**。02 篇的容量与备份策略（Milvus 可重建、MinIO 永久）与本模型一致。

## 3. 文档解析入库（七步流水线的落地细化）

既有七步框架不变：`文档预处理 → 环境配置 → 批量抽取 → 术语对齐 → 一致性校验 → 约束校验 → 人工归档`。本节给每一步补上本文关心的强化点。

### 3.1 文档预处理：准入 + 同源检测（新增子步骤，最先执行）

上传后先做三级同源检测，再进常规预处理（格式转换/OCR/表格标准化，矩阵见研究 03 篇）：

| 级别 | 手段 | 命中含义 | 路由 |
| ---- | ---- | ---- | ---- |
| ① 精确重复 | 内容 SHA-256 | 完全相同的文件 | 拒收（幂等返回既有文档） |
| ② 身份命中 | **文档身份键**：规范化编号/标题（如 `GB/T 31486`），解析出 `identity_key + doc_version` | 同一文档的新版本（如 2015 版 vs 2024 版） | 走**版本更新路径**（§3.4） |
| ③ 近似同源 | n-gram SimHash（阈值 ~0.9，初值待校准） | 大面积改写/拆分合并的疑似同源 | 人工确认：新文档 or 新版本 or 独立文档 |

- 身份键解析：标准/法规类文档优先解析编号（`GB/T xxx`、`ISO xxx`）+ 年号版本；无编号文档用规范化标题 + 发布日期。
- **命中身份即建链**：新版本文档的 `supersedes_id` 指向旧版本，形成文档版本链（`v2015 → v2024`），链上每个版本都是独立的 Raw 资产，永不删除。

### 3.2 环境配置 / 批量抽取：出处指针加密

- 抽取提示词模板（研究 03 篇四类）不变；本节新增硬要求：**每个候选事实必须带 `source_ref = (document_id, doc_version, chunk_id, span)`**，且 `doc_version` 参与哈希——引用出处时永远能定位到"哪个版本的哪一段原文"。
- 候选之间**不得互为证据**（promotion gate 细则）：候选 A 的置信度不能因为引用了候选 B 而提升，防止"页面互相引用成环、坏知识变先验"的 llmwiki 社区教训；佐证计数只统计经终审的事实。

### 3.3 术语对齐：消歧的入库时刻（详见 §8）

候选实体/概念在此与术语表对齐（绑定既有 IRI / 新建候选 / 歧义工单三态）。术语唯一性国标底线在此门禁。

### 3.4 一致性校验：冲突分诊 + 事实级承接判定（详见 §4）

新增冲突检测器。**核心原则：文档被替代 ≠ 其派生事实全部作废**——新版文档通常只改写部分内容，必须逐条判定，不能整链推翻：

```
新版文档 v2024 终审通过
  → 取旧版本 v2015 派生的全部当前有效事实（按 subject 分组）
  → 与 v2024 的新事实逐条比对（subject + predicate 对齐）：
      a) 新版有同主谓新事实        → 旧事实标记 superseded，连 SUPERSEDES 边（时间戳、出处齐全）
      b) 新版未重现的旧事实        → 标记 needs_review（"源已更新，本条未在新版重现"）
                                    默认降权但可见，进批量人工复核，不是直接删除
      c) 新版明确否定（矛盾）       → 走冲突分诊（§4）
```

### 3.5 约束校验 / 人工归档：版本切换执行

终审通过后执行**原子切换**，全程检索不中断：

1. 新版事实写入图与向量索引（`is_current = true`）；
2. 旧版受影响事实封口（`valid_to = now`、连取代边），**不删除**；
3. 受影响实体与社区摘要标脏，投递 `kb.community.dirty` 事件；
4. 旧文档 lifecycle 置 `superseded`（Raw 层文件原封不动）。

切换用状态字段翻转实现（无双写窗口），投影经 Outbox 异步追赶，符合 02 篇最终一致约定。失败处理沿用 extraction_jobs 的 stage 级重试；已产出的候选作废，不污染主库。

## 4. 新旧知识冲突治理

### 4.1 冲突分诊：四型四处置

冲突检测器触发时机：新事实终审前（与既有当前有效事实比对）+ nightly 例程补扫。比对键 = `subject IRI + predicate IRI`（对象属性类冲突再比 object）。

| 类型 | 特征 | 处置 | 例子 |
| ---- | ---- | ---- | ---- |
| **T1 版本演进** | 两事实的 source_ref 在同一文档版本链上（或源文档间有 replaces 关系） | 不是冲突：自动建立事实级 SUPERSEDES 边，新版遮蔽旧版（§6.2），无需人工 | GB/T 31486-2024 修改了 2015 版的容量限值 |
| **T2 真矛盾** | 无版本关系，语义互斥 | 置信度评分自动裁决（§4.2）；分不出高下 → 冲突工单 | 文档 A 说审批上限 50 万，文档 B 说 100 万 |
| **T3 限定差异** | 表面矛盾，适用 scope（时间/地域/产品线/法规域）不同 | 两事实都保留为有效，各自标 scope；检索按查询上下文匹配 | 京沪海规 vs 国标对同一指标的不同要求 |
| **T4 多源重复** | 主谓宾全同，来源不同 | 合并佐证：一条事实挂多 source_ref，置信度上调，来源列表保留 | 三个文档都确认同一参数 |

T3 依赖本体支持"限定上下文"：实体与事实带 `scope` 属性（结构化键值，术语对齐阶段与抽取阶段产出），这是本体区别于普通图谱的又一收益。

### 4.2 自动裁决规则（T2）

新事实 candidate 与既有事实各算一个置信分，**分差够大才自动裁决，否则必须人工**：

```
score = 0.35·来源权威(文档类型/机构分级) + 0.25·时效(新近者得分)
      + 0.20·佐证数(独立 source_ref 数) + 0.20·出处质量(span 指向条款原文 > 转述)
```

- `|Δscore| ≥ 0.25`（初值，上线前用标注集校准）：高分者胜，败者自动封口并连 SUPERSEDES 边 + 生成裁决说明（写入冲突记录，可审计）；
- `|Δscore| < 0.25`：生成冲突工单。**冲突工单复用审批中心状态机**（第五类审批对象：`submitted → reviewing → approved/rejected → applied`），候选的 review_state 扩展 `conflict_pending`；工单 UI 并排展示两条事实 + 各自原文出处 + 评分明细，人工点选胜者/判定 T3 限定共存/判定待定。

### 4.3 与记忆系统的边界

本节治理的是**知识库 ABox（L4 共享语义）**。会话/用户/组织层记忆的新旧冲突（L1~L3）走记忆沉淀管线的 ADD/UPDATE/DELETE 判定（04 篇 §3.1），不复用知识库冲突工单；但 L2/L3 记忆沉淀中发现的**领域事实级**矛盾，可发起候选本体条目/候选知识条目流程进入本节管线（04 篇已定的 L3→L4 通道）。

## 5. 知识保鲜：三条保鲜线 + 维护例程

### 5.1 文档级：生命周期状态机

```
draft → current → superseded ──┐
   ↑               │           ├──→ archived（仅检索默认视图移除，Raw 永在）
   └── (新版本终审) ─┘───────────┘
```

`current` 文档派生的知识默认可见；`superseded` 文档的知识按 §3.4 承接判定处理；`archived` 仅审计/as-of 场景可达。

### 5.2 知识级：nightly 维护例程（llmwiki routine 的对应物）

ARQ 定时任务 `kb_nightly_maintenance`（租户级可配频率），**只处理增量**，不全量重建：

1. **增量重编译**：消费上次运行以来的事件（新终审事实、取代边、标脏社区），只重算受影响的社区摘要与实体描述向量（对应 llmwiki "只更新新来源触及的页面"）；
2. **知识 lint 巡检**：
   - 悬空出处（source_ref 指向不存在的文档/切片）→ 告警；
   - 孤儿实体（无任何关系、无任何事实）→ 候选清理工单（人工确认后转为 archived）；
   - 陈旧声明：`checked_at` 最老的事实优先重验——对照原文重新校验（LLM 抽查 + 结构校验），过期未验者降权并标记 `stale`（对应 llmwiki "lint 按最老优先重验外部声明"）；
   - 失效未封口（标记 needs_review 超时未复核）→ 催办。
3. **冲突补扫**：对 T2 抽样复检（本体/规则更新后，旧裁决可能失效）。

### 5.3 本体级：TBox 版本链与 ABox 共存（"本体最新，旧知识也在"）

本体版本管理已有基线（ADR-5：Turtle 快照 + 版本注册 + 变更评审 + 回滚；`ontology-versions` 桶永久保留）。本节补齐**本体演进时旧知识怎么办**：

1. **语义兼容分级**（发布时自动计算，写入 `ontology_versions.compat_level`）：

| 级别 | 变更内容 | ABox 影响 |
| ---- | ---- | ---- |
| PATCH | 标签、注释、非约束性元数据 | 无需迁移，实例即时"按新版本解读" |
| MINOR | 新增类/属性/公理（向后兼容） | 无需迁移；新增公理带来的可推理新结论由规则物化增量补齐 |
| MAJOR | 删除/收窄类、修改属性定义、公理收紧（破坏性） | 必须走影响面迁移 |

2. **实例版本戳**：Neo4j 实例与事实节点带 `ontology_version` 属性；查询可显式指定"按本体 vX 解读"（RDQL/SPARQL 装载对应版本 TBox 快照执行）——**旧版本本体永远可加载，历史事实永远可按当时的模式还原语义**。
3. **影响面分析器**（MAJOR 发布时）：diff 新旧 TBox 公理 → 计算受影响实例清单（按类/属性闭包）→ 生成迁移任务（带 before/after 快照）→ 审批中心审核 → 批量执行 → 旧事实封口归档而非删除。迁移失败可整批回滚（激活旧 TBox 版本 + 还原事实戳）。
4. **非破坏演进原则**（承接国标第 9 章扩展原则）：优先用新增与收窄代替删除；确需删除的概念先标记 `deprecated`（本体的 supersession），实例迁移完成两个版本周期后才允许在 MAJOR 中移除。

### 5.4 易变知识不入库，只存指针

价格、库存、实时状态、外部系统权限类**易变声明不作为知识入库**——知识库只存"该去哪查"的工具/接口指针（挂到本体行动类，经 MCP 工具实时取数）。这是 llmwiki 社区最痛的教训（"lint 天天验证通过，矛盾却在知识库从不读的代码里"）：**保鲜成本过高的知识，正确的处理是不让它变成知识**。

## 6. 旧知识找回：bi-temporal 时间机器

### 6.1 双时间线模型

| 时间维 | 含义 | 例 |
| ---- | ---- | ---- |
| `t_valid_from / t_valid_to` | 业务有效时间：这条事实描述的世界状态何时成立/失效 | 容量限值 100Ah 在 2024-03-01 被改为 120Ah |
| `t_txn` | 事务时间：我们何时知道并入库 | 2024-05-10 上传 2024 版标准并终审 |

Graphiti 式：失效 = `valid_to` 封口 + `SUPERSEDES`/`INVALIDATED_BY` 边，物理数据永在。文档版本链、事实 supersedes 链、TBox 版本链三链齐备，任意历史时刻的"知识库全貌"可重建（Raw + 版本快照重放）。

### 6.2 检索三态语义（产品级默认值，所有检索接口强制实现）

| 模式 | 参数 | 语义 | 过滤实现 |
| ---- | ---- | ---- | ---- |
| **当前有效**（默认） | 无 | 只返回未被取代的当前事实 | Milvus 标量 `is_current=true`；图查询 `valid_to IS NULL` |
| 时间点 as-of | `as_of=<时刻>` | 返回该时刻有效的知识（审计/合规："当时的规定是什么"） | `t_valid_from ≤ as_of < t_valid_to`（尚未知的事实按 `t_txn > as_of` 排除） |
| 全量含旧 | `include_superseded=true` | 被取代知识一并返回，**必须带显著标注**（"已于 X 时被 Y 取代"+ 取代链入口） | 不过滤，结果分组：current / superseded（附 supersedes 链） |

- **遮蔽而非消失**：superseded 知识从默认视图消失，但在 as-of 模式、supersedes 链遍历（"这条结论的演变史"）、出处反查（从原文切片找它派生过的知识）三条通道中永远可达。
- 前端三处消费：对话答案的"知识时效"徽标、知识详情页的版本时间线、图谱浏览的"显示已失效事实"开关。

## 7. 多路召回与融合

### 7.1 六路并行召回

| # | 通道 | 存储/实现 | 最擅长命中 | 典型失效场景（为何必须有这路） |
| ---- | ---- | ---- | ---- | ---- |
| 1 | 向量语义路 | Milvus kb_chunks（dense+sparse 混合） | 换说法的语义匹配 | 精确编号/术语字面查询（向量会偏） |
| 2 | 词法精确路 | BM25 + PG pg_trgm | 编号、代码、专有名词字面 | 高频词淹没 / 新词无向量 |
| 3 | 图结构路（local search） | Neo4j 实体邻域 + 关系路径 | 关系型问题（"A 和 B 什么关系"）、多跳 | 纯语义相似但图上无关的噪声 |
| 4 | 社区摘要路（global search） | 社区报告 map-reduce | 全局主题/总结类问题 | 细节问题（摘要粒度不够） |
| 5 | 时间线路 | supersedes 链 + bi-temporal 查询 | as-of 查询、演变史、"最新版改了什么" | 其他五路默认过滤掉旧知识，此路专门翻历史 |
| 6 | 出处反查路 | source_ref 反向索引 | 从答案/实体回到原文切片；从文档找它派生的知识 | 供审计溯源与 §3.4 承接判定用 |

路由策略：查询先经术语对齐（§8.3）+ 问题分类（local/global/时间线/精确词，DRIFT 作折中档），**命中多解时多路并行而不是二选一**——多路召回是检索的默认结构，路数取舍在融合层完成，不在入口完成。

### 7.2 融合排序

```
六路候选 → RRF（Reciprocal Rank Fusion）粗排
        → 硬过滤：tenant_id、kb_id、权限（检索前过滤，模型看不见无权数据）
        → 时效语义过滤：默认 is_current（§6.2 三态）
        → 软加权：时效衰减(λ·age) + 置信度(§4.2 score) + 来源权威 + T3 scope 匹配度
        → 去重聚合：同一事实多路命中只留一条，合并命中路数（路数越多越靠前）
```

### 7.3 证据链拼装

最终注入 LLM 上下文的每条知识都携带：`IRI + label + 版本/时效状态 + 置信度 + source_ref`。回答生成时强制引用条目 ID（AG-UI 事件流回传 evidence_refs，已有设计），前端可点开原文定位——**全程可追溯**（设计宪法第 5 条）在检索出口收口。

## 8. 知识消歧

消歧在三个时刻发生，**大头在入库时**（公理 5）。

### 8.1 术语表：消歧的户口本（新增存储，02 篇增量）

PG 新增 `terms` + `term_aliases` 表（详见 §9），由语义层 terminology 模块管理，本体 TBox 的 `skos:prefLabel/altLabel` 同步投影：

```
terms:       id, iri, preferred_label, definition, kb_id, status, scope, ontology_version
term_aliases: term_id, alias, alias_type(缩写/俗称/旧称/译名), source_ref
```

- 一个概念一个 IRI 一个 prefLabel，多个 alias；**旧称也是 alias**（标准换版后旧术语指向新 IRI，检索旧叫法能命中新知识）——这是"知识最新、旧叫法也能找到"的关键。

### 8.2 入库时：术语对齐四步判定（流水线第 4 步细化）

对每个候选实体/概念，依序执行：

1. **精确匹配**：label/alias 完全一致（含规范化：大小写、全半角、空白）→ 绑定既有 IRI；
2. **词典匹配**：别名表 + 领域同义词典命中 → 绑定；
3. **语义判别**：embedding 相似度 ≥ 0.92 → 自动绑定；0.80 ~ 0.92 → LLM 判别（输入：两个定义全文 + 各自出处对比，输出：同义/不同/不确定）；
4. **新建候选**：相似度 < 0.80 → 走新建候选，人工终审时定名（终审界面强制查重提示）。

三态出口：**绑定**（写 alias 若 label 不同）/ **新建**（登记新 term）/ **歧义工单**（判别不确定时，UI 并排两个定义 + 原文，人工裁决"合并/区分/暂缓"）。对齐结果回写候选的 `entity_iri`，抽取后续关系时用对齐后的 IRI——保证图谱里同名实体唯一归位。

### 8.3 检索时：查询消歧

1. 查询词先经术语对齐（复用 §8.2 的 1~3 步，只读）得到 canonical IRI 集合；
2. **单解**：直接按 IRI 检索（图谱路 + 向量路带 IRI 过滤）；
3. **多解**（同形异义，如"苹果"多个 IRI）：
   - 查询上下文与候选实体的 scope/社区/邻域做相似匹配，高置信 → 自动选定并在答案中注明依据；
   - 低置信 → **多路都查，结果按概念分组返回**，每组带"这是《XX》中的定义"标签——宁可多给，不许静默二选一；
4. **零解**：回落纯语义检索 + 提示"未对齐到术语表，可能为新概念"，并可反哺候选术语流程。

### 8.4 输出时：身份三元组引用

LLM 回答中每条知识引用必须携带**身份三元组**：`IRI + prefLabel + 时效状态（current / superseded-by-X / as-of-T 有效）`。新旧并存的场景（`include_superseded` 查询）答案必须分组表述，禁止新旧混排不分。Schema 约束由输出校验器检查（引用的条目 ID 必须真实存在于本次召回集合，防幻觉引用）。

## 11. 与平台其他服务的关系

- **本体核心**：术语表与 TBox 双向投影；冲突分诊的 T1 依赖本体 replaces/supersedes 关系；TBox 版本链（§5.3）是本体核心版本管理的直接延伸。
- **记忆服务**：边界见 §4.3；L4 与知识库共用保鲜思想（TTL/衰减/失效边/版本化，04 篇 §3.3），机制同构、工单分流。
- **审批中心**：新增第五类审批对象（冲突工单）；本体 MAJOR 迁移任务亦走审批。
- **Agent 服务 / MCP 出口**：`knowledge.search` 工具暴露三态参数（默认 current）；`ontology.query` 支持"按版本解读"；答案证据链格式在 AG-UI evidence_refs 中落地。
- **审计**：一切取代/裁决/迁移动作写 audit_logs（before/after），满足"谁在何时依据什么取代了哪条知识"的追问。
